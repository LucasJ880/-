# 青砚 UI/UX 更新：Phase 4A 客户工作台

日期：2026-08-07
范围：将 Phase 2/3 已验证的统一 Shell 与决策摘要推广到客户详情；保留现有客户、商机、报价、订单、邮件、数字员工、权限与审批流程。

## 本次交付

客户详情新增“客户决策摘要”，统一回答：

- 当前客户处于哪个销售阶段；
- 哪些客户资料或销售动作尚未完成；
- 当前主要风险；
- 最近一次客户互动；
- 数字员工行动队列是否有待处理项；
- 推荐的下一步是什么。

客户页面接入统一 Shell：顶部显示客户名称、当前商机阶段和待处理行动数量；桌面右侧“青砚 · 客户上下文”展示商机、报价、订单、风险、缺失项、最近变化、邮件通道和推荐下一步。平板继续使用 Phase 2 Drawer，手机保留单栏决策摘要，不强制显示桌面右栏。

## 决策优先级

推荐动作按业务阻塞顺序推导：

1. 缺少电话和邮箱 → 完善联系方式；
2. 已签约但未登记定金 → 进入报价记录登记实收；
3. 有待发送报价但销售邮箱未绑定 → 前往邮箱设置；
4. 已有订单但没有活跃商机 → 查看订单进度；
5. 尚未建立商机 → 记录需求并建立机会；
6. 使用既有 CRM 数字员工规则判断资料、逾期跟进、报价窗口与下一步；
7. 无阻塞时按计划继续跟进。

## 数据与安全边界

- 客户、商机、互动、报价和订单继续来自现有客户详情 API。
- 邮件状态复用当前销售账号的 `/api/sales/email-status`，不改变邮箱绑定与发送机制。
- 数字员工行动复用 `/api/sales/actions?status=active&customerId=...`，不新增执行入口。
- 右栏只导航到既有资料、互动、报价、订单和邮箱设置页面；不自动写数据、不自动发送邮件、不绕过审批。
- 未修改 Prisma Schema、migration、API 数据结构、权限逻辑、AI Scope 或 Pending Action。

## 响应式与兼容

- `>=1280px`：客户上下文与主工作区并列。
- `768–1279px`：复用已有 Drawer，不压缩客户工作区。
- `<768px`：保留客户决策摘要和原有可折叠资料区、横向标签与 FAB。
- 原有客户基本信息编辑、电话/邮件/地图快捷入口、数字员工建议、互动、报价、定金、工艺单、可视化方案和建议记录均保留。

## 验收重点

- 缺联系方式时优先引导完善资料。
- 签约报价未登记定金时优先引导报价记录。
- 销售邮箱未绑定时明确提示无法从青砚发送报价。
- 健康客户显示正确商机阶段和下一次跟进节奏。
- 右侧上下文按钮能正确切换互动、报价、订单或邮箱设置。
- 390px 下不出现页面级横向溢出，原有标签和 FAB 可用。
