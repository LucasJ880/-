## 1. 用户现在会怎么看到

- **询盘收件箱的卡片**：买家名字旁的灰色标签由「已回复」变为「买家已来信」；我们回过的卡片，下方绿色文字由「已回复」变为「我方已回复」。一张等我们回复的卡片现在是「买家已来信」+「写回复」，不再有两个意思相反的「已回复」。
- **别的地方同一个阶段**：线索详情、外贸获客首页的线索列表、概览卡、漏斗，活动详情与活动漏斗，驾驶舱漏斗，都改叫「买家已来信」。外贸助手、数字员工读到的阶段文字也是这个名字。
- **阶段本身没有变**：哪些线索在这个阶段、漏斗的数字、筛选，都和以前一样。
- **按钮「已回复，标记」没有改名**，使用说明里引用它的那一行也没有动。
- **只能查看外贸的成员**（今天没有这样的账号，见 §3）：收件箱卡片上没有「写回复」「再写一封」「已回复，标记」；有 AI 草稿的会话仍可点「查看回复草稿」，窗口只读，写着「你的岗位只能查看询盘，不能回复」，只有「复制草稿」；从别处带着买家点进收件箱时不开窗口，只提示这句话。
- **Cathy 与外贸业务员**：除了上面两处文字，没有任何变化。

## 2. 这个阶段名出现的各处

阶段 `replied` 是买家来信时进的（包括第一次主动询盘），我方在收件箱回复之后也不变，所以定名「买家已来信」。

| 位置 | 改动前 | 现在 |
|---|---|---|
| 阶段表 `src/lib/trade/stage.ts` | 「已回复」 | 「买家已来信」（唯一来源） |
| 询盘收件箱卡片、线索详情、外贸获客首页线索列表、活动详情、驾驶舱漏斗、阶段下拉选项 | 读阶段表 | 读阶段表（自动变化，没有改文件） |
| 外贸助手的线索文字、数字员工外贸工具的 `stageLabel`、秘书跟进引擎的「当前阶段」 | 读阶段表 | 读阶段表（自动变化，没有改文件） |
| 外贸获客首页概览卡 `trade/page.tsx` | 写死「已回复」 | 读阶段表 |
| 外贸看板接口的漏斗 `api/trade/dashboard/route.ts` | 写死「已回复」 | 读阶段表 |
| 活动统计接口的漏斗 `api/trade/campaigns/[id]/stats/route.ts` | 写死「已回复」 | 读阶段表 |
| 外贸助手的阶段分布 `chat-assistant.ts` | 写死「已回复」 | 读阶段表 |

## 3. 只读成员这部分：今天没有人会遇到

含 `trade.read` 的岗位模板共三个（系统模板企业负责人、外贸业务员、窗饰老板），每一个都同时含 `trade.manage`；旧模式的兼容回退给的也是外贸业务员；企业不能自建岗位。所以目前没有任何账号是「只能看外贸、不能处理」的。这部分是预防性的：以后加出只读的外贸岗位时，收件箱不会出现点了没用的回复按钮。

测试与截图里的只读成员，是在隔离测试库 / 本机演示库里临时建的一个只含 `trade.read` 的测试岗位，没有进种子，也没有进岗位模板。

## 4. 接口变化

| 接口 | 变化 |
|---|---|
| `GET /api/trade/inbox`、`GET /api/trade/inbox/focus` | `capabilities` 多一个布尔字段 `reply`：当前成员在该企业持 `trade.manage` 或是平台 super_admin 时为真。读权限、其余字段、只读性质不变 |
| `GET /api/trade/dashboard`、`GET /api/trade/campaigns/[id]/stats` | 漏斗里 `replied` 这一档的 `label` 由「已回复」变为「买家已来信」；`stage` / `key`、包含的阶段集合、数字不变 |
| `POST /api/trade/inbox/[prospectId]/reply` | 没有动，仍自己校验 `trade.manage` |

没有新增接口，外贸守卫处理器仍是 111 个。

## 5. 与四件套不一致、或实施中才发现的

1. **深链的做法与 design 初稿不同。** 初稿写的是「不能回复时不请求单会话接口」。实施时页面在深链那一刻还不知道能不能回复（要等接口返回），所以改成照常请求单会话接口（只读，它的响应里同样带 `reply`），为假时不开窗口、只提示。对用户看到的结果没有差别；design D5 已按实际做法改写。
2. **`reply-entry.test.ts` 没有需要调整的断言。** tasks 2.2 预计要改两条；实际上新的出现条件是在原条件前面加了一项，原断言照样成立，通过数仍是 45。
3. **发现、没有做的一处**：有 AI 草稿的卡片上，分析块里还有「重新生成」和「按建议生成报价草稿」两个按钮，它们对只读成员仍然显示，点了会被接口拒绝（截图 `04` 第二张卡片能看到「重新生成」）。四件套只列了三个回复操作，这两个不在其中，所以没有擅自加。今天没有只读账号，不影响任何人；要不要一并收掉，请定。
4. 看板漏斗里只有这一档改读阶段表，旁边仍是写死的「已联系」「成交」（阶段表里是「已触达」「已转化」）。这是既有差异，按 design D2 有意不动。

## 8. 上线注意

- 合并即生效，没有开关，没有数据迁移；回滚 = revert。
- 梦馨的人会看到「已回复」变成「买家已来信」。通知梦馨时可以加一句：卡片上买家名字旁的标签现在写「买家已来信」，我们回过的写「我方已回复」。
- 外贸助手与数字员工读到的阶段名也变了。这只是既有提示里的一个词，不改调用次数与流程；没有在真实模型上对比过改名前后的回答。
- 后续候选（都不在本 change）：§5 第 3 条的两个按钮；看板漏斗其余各档与阶段表的名字统一；询盘收件箱以外的外贸页面对只读成员的按钮显隐。
