## 1. 问题

青砚有一张确定性的「下一步」查表（十条规则），但只接在已冻结的 Muse 通道上，网页用不到。网页上另有两处各说各的「下一步」——工作台的三步卡、项目决策摘要上的按钮——都只看项目的基本信息，看不到询价、报价、审批的实际状态；要求确认之后，三步卡永远停在「准备标书与报价」。人只能自己记着现在该去哪个页签点什么。

## 2. 做了什么

1. **接口** `GET /api/projects/{id}/next-step`：返回一条结论、最多三条原因、一个要去的位置、截标提醒、最多三条顺带要办的事。只读。
2. **判断**：十条共用规则直接调用 Muse 的那张查表（不复制、不改它），在它前后补上网页才需要的状态，并把每个结论换成页面上的一个位置。
3. **卡片**：工作台页签最上面。点按钮只是带人过去——切页签、滚到那个位置、开文件抽屉或进审批中心。
4. **一个声音**：卡片出现时，「项目决策摘要」与右侧的项目上下文显示同一条结论。

## 3. 需要你知道的取舍

### 3.1 卡片只说现状、只指路，不承诺系统会做什么

第一版写过「定时检查会给其中 N 家起草催单」「系统不会再催」。独立审查逐条证明这些话在好几种情况下是错的（发信邮箱没连、催单卡被驳回过、这一轮带着自动跟进的授权……）。现在只说「几家没回、超过几天、去这一轮看」。

### 3.2 截标：按天说，过了整整一天才说「已过」

手工填的截标时间只有日期，系统存成当天中午——钟点是假的。所以卡片不说「约 5 小时后截标」，也不会在中午一过就判「已错过截标」：当天之内只提醒「截标时间到了或刚过」，照常给下一步；过了一天以上才给「截标日期已过」。只认项目的截标时间，不拿内部到期日顶替。

### 3.3 和 Muse 那张表不一样的地方（Muse 没有改）

| 状态 | Muse 的查表 | 网页 |
|---|---|---|
| 分析完、等确认与批准 | 落到「还没问过供应商」 | 「等你确认要求并批准」 |
| 三天内截标 | 排第二，只说截标 | 作为提醒，与下一步并存 |
| 等待天数 | 提问人的设置 | 项目负责人的（或该轮授权里定格的），与定时催单相同 |
| 回复截止已过 | 仍说「该催了」 | 不说 |
| 取哪一轮 | 最新一轮 | 最新一轮**有已发出供应商的** |
| 已选定一家、另一家没回 | 「1 家没回」 | 去定投标价 |

Muse 通道已冻结，这些不一致留着；同一个标在两边问「下一步」可能得到不同的话。

### 3.4 沿用了查表的顺序

「强制要求当前无法满足」「有供应商没回」排在比价与定价之前。这是查表本来的顺序，网页只做了一处调整（已选定之后没回的不挡路）。

### 3.5 页面上本来没有的按钮，卡片也没有加

- **没有「起草催单」的按钮**：催单由定时检查起草，网页只能批。卡片指到那一轮。
- **没有「标记已提交」的按钮**：提交时间只能通过推进项目阶段写入。「截标日期已过、没有提交记录」时卡片指到工作台的关键日期，并照实说明。

这两件事要不要补，是另一个 change 的事（方案里的 H4）。

### 3.6 决策摘要的按钮没了

卡片出现时，决策摘要不再有自己的按钮（按钮在它正上方的卡片上）。右侧的项目上下文保留按钮（它在每个页签都看得到，而卡片只在工作台）。开关关闭时两处与原来相同。

## 5. 独立审查

开 PR 前请了一个不带结论的独立审查（它自己跑代码、自己做变异）。结论：**多租户隔离、只读、硬纪律都成立；但卡片在好几种真实状态下会说错话，默认的那次点击到不了位，19 处新变异里有 15 处测试没发现。** 逐条处理：

| 它实际跑出来的 | 处理 |
|---|---|
| **点「去问供应商要价」滚不到按钮**：位置放在轮次列表上，而还没有轮次时它不存在。我自己的截图上就能看出来 | 位置改到供应商询价整块的根上；测试核对它在根元素上；真实浏览器里核对按钮在视野里 |
| **空的新轮次盖住上一轮的报价**：第 1 轮两家报价，再手工建一个空轮次，卡片就说「还没问过供应商」 | 当前这一轮 = 最新一轮有已发出供应商的 |
| **截标**：手工填的时间是当天中午，一过就判「已错过截标」并盖掉待批；没有截标时间时拿内部到期日顶替 | §3.2 |
| **「批准之后才能询价」是错的**：询价入口看的是已确认的要求，不是批准；反过来，批准了而没有已确认的要求，卡片还让人去点一个用不了的按钮 | 改说法；后一种单列一条规则，给两条出路 |
| 供应商都「已回复」→ 卡片说「没有拿到报价」 | 新增「已回复、报价还没录入」；认不出的状态不猜 |
| 「再问一轮」指向一个灰的按钮（三天内不开新轮、没连邮箱……） | 指向询价入口时读入口自己的状态，把原因写出来 |
| 催单的说法在六种情况下与定时扫描不一致 | §3.1；已结束的轮次、超出 90 天的不再算在等 |
| 催单针对的那家已经报价了，卡片还指到那一轮（那里不会列出这张卡） | 改去审批中心，说明这张催单用不上了 |
| 工作区开了但没用过的组织，永远看到「提交前还有阻断项」 | 只在录了价格表之后才谈阻断项 |
| 审批标题里有金额时原样出现在响应里 | 带金额的自由文字整段不显示 |
| 已取消、已被取代的报价也算「投标价已有」 | 不算 |
| 最近一次重新分析失败，卡片就说「上次分析失败」，而之前那份还能用 | 用之前可用的那份，顺带提示 |
| 没有分析的老项目永远卡在「去分析」，即使报价都回来了 | 跟着实际进度说 |
| 已选定一家，另一家没回 → 「1 家没回」 | 去定投标价 |
| 右侧的项目上下文在每个页签都丢了按钮 | 保留按钮 |
| 在工作台上改了关键日期，卡片不刷新 | 项目数据重新载入时重新取 |
| 滚动只发生一次，上面的区块晚一步撑开就偏了；地址里别的参数被丢掉 | 到位后再核对几次，人一滚动就停；保留其它参数 |
| 已中标显示「已结束」 | 单列「已中标」 |
| **15 处变异没被发现**（取最早的分析 / 最早的轮次、不读授权的天数、不解析催单记录、非强制的不满足也算、项目管理员没有写权限……） | 每一处都补了测试；连同新加的行为共 41 处变异，全部被发现 |

**修审查的过程中我自己又出了一个错**：改页面文件时把它的 `export default` 误删了并且推了上去。类型检查和单元测试都发现不了，是重拍截图时真实浏览器报出来的。已恢复，并加了一条断言。这一提交在开 PR 之前就修掉了。

没有改、写进了已知限制的：审批中心按当前选中的组织列卡；只靠旧字段认作招投标的老项目没有卡片；开关关闭时每次打开多一次 404 的请求。

## 7. 已知限制

- **判断依赖的数据不准，卡片就不准**：比如截标时间没有随补遗更新。卡片在「截标日期已过」时会提示去更新。
- **六段进度条与三步卡没有动**，它们仍然靠手工推进的阶段，可能与卡片说的不一致（截图里能看到：卡片说「报价齐了」，决策摘要的标题仍是「项目分发」阶段）。这是 H1 的后半，另开 change。
- **Muse 与网页在几处不一致**（§3.3）。
- **审批中心按当前选中的组织列卡**：属于多个组织的人，从卡片进审批中心可能要先切组织。
- **只靠旧字段认作招投标的老项目没有卡片**（接口与询价入口都只认 `workDomain = tender`）。
- **开关关闭时，招投标项目的页面每次打开多一次返回 404 的请求**。
- **每次取数十条左右的查询**；要指向询价入口时更多。不轮询。
- **真库测试在 CI 里是跳过的**（CI 没有隔离库），只在本地跑得出来。
- **页面上的行为靠截图、真实浏览器里的一次核对与源码断言**，没有自动的浏览器测试。
