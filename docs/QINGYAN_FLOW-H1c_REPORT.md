## 1. 问题

项目上的阶段记录（几个时间）被项目列表、Muse 的 `status`、主动提醒、放弃项目的接口读取。其中「供应商报价」只能人在对话里点「推进」，常常落后；FLOW-H1b 只让项目页按事实显示，别处仍落后。已有的两处自动写入（分析完成 → 项目解读、询价发出 → 供应商询价）只写时间，不关不建阶段任务——FIX-7 修好任务之后，它们会让上一阶段的任务一直挂着。

## 2. 做了什么

开关打开时，四个事实让阶段记录自动前进：

| 事实 | 到达 | 任务与审计记在谁名下 |
|---|---|---|
| 分析产出可审核的结果 | 项目解读 | 发起分析的人；不知道是谁时项目负责人 |
| 询价执行**这一次真的发出**至少一家（审批通过之后） | 供应商询价 | 批准执行的人 |
| 有人把询价项**标记为已发送**（电话、微信询价） | 供应商询价 | 标记的人 |
| 没取消的轮次里某个询价项**第一次录入报价**（人工录入或回信自动解析） | 供应商报价 | 录入的人；回信解析时项目负责人 |

「前进」= 这一段的时间还空着、**而且写上之后阶段记录会变靠后**，才写当时的时间；写了就关掉之前各阶段还没完成的自动任务、为新阶段建任务（FIX-7 的规则），再写一条审计 `tender.stage.auto_advance`（触发、写的哪一段、前后阶段、触发的人、是否知道是谁；不含金额）。

不前进：不是招投标项目；已放弃 / 已归档；招投标状态已是结果或已记了授标日期；写了也不会变靠后；读之后项目被放弃、记了结果或被推进到更靠后。第二家报价、第二轮询价不再前进；同时触发两次只写一次。

不做：不改招投标状态，不给 BidToGo 发状态回调，不发讨论区消息与成员通知，不调模型。写时间、建任务、写审计任何一步失败，录入报价 / 标记已发送 / 询价执行 / 分析收尾照样成功，留下错误日志。

已有两处原来的写入原样保留（分析收尾「为空就写」、询价发出「每轮覆盖」），开关关闭时一行都不多走。

改动的既有文件：`src/lib/inquiry/service.ts`（`recordQuote`、`markItemSent`）、录入报价与标记已发送两个接口、`src/lib/tender-rfq/execute.ts`、`src/lib/tender-auto-analysis/worker.ts`、审计标签两张表（`src/lib/cockpit/audit-labels.ts`、`src/lib/activity/formatter.ts`）。新文件：`src/lib/tender/stage-auto.ts`、`src/lib/tender/stage-auto-flags.ts`。

## 3. 需要你知道的取舍

### 3.1 不走人确认的阶段推进，所以招投标状态会落后——「供应商报价」这个状态以后到不了

我没让自动前进调用对话里那套阶段推进：它会改招投标状态，并在项目有来源系统时给 BidToGo 发状态回调——那是对外发送，原来要人确认后才发；它还会给全体成员发「项目已推进」。

代价（独立审查指出，我核过）：阶段推进在目标阶段已到时什么也不做。自动写了「供应商报价」的时间之后，人再在对话里推进到「供应商报价」只会得到「无需重复推进」，招投标状态不会变成「供应商报价」，BidToGo 也收不到这一次回调；状态会从「供应商询价」直接跳到推进到「项目提交」时的「已提交」。已有两处自动写入对「项目解读」「供应商询价」两个状态本来就是这样。

**要不要补，需要你定**：如果 BidToGo 那边要看到中间状态，可以另开一个小 change，让人确认的推进在「阶段已到、状态落后」时仍补状态与回调。那要改 `stage-transition.ts`，#446 也在改它，所以这次没做。

### 3.2 依赖 #447，合并顺序 #447 在前

建任务在 main 上仍是坏的（FIX-7 修的那个 `sortOrder`）。本分支单独跑隔离库测试：40 项通过，8 项失败——全是在数任务条数；合并了 #447 之后 48 项全部通过。CI 不跑隔离库测试，所以 CI 是绿的。两个分支合并没有冲突。

### 3.3 成员会看到更多任务提醒

自动前进也会建任务，FIX-7 报告 §3.1 说的到期提醒（项目里所有成员都会收到）同样适用。

### 3.4 其它

- **回信解析可能解析错**：把一封不是报价的回信当成报价，会让阶段记录提前到「供应商报价」；阶段不能回退（既有规则）。
- **FLOW-H1b 那行「阶段记录没有自动推进」的说明**：开关打开后它只在三种情形下出现——只有投标报价单、项目级报价单、开关没覆盖的组织——这些情形里阶段记录确实没有自动推进，照旧准确；措辞写在 #445 归档的规格里，这次不改。
- **之前阶段的任务被标为「完成」而不是「取消」**（FIX-7 的规则）：第一家报价进来时，「[供应商询价] 跟进供应商回复」会被标为完成，哪怕别的供应商还没回。
- **项目的更新时间会变**：写阶段时间会刷新项目的更新时间，主动提醒里「阶段停滞」的计时从这一刻重新算。
- **审计挂名**：不知道是谁时挂在项目负责人名下（有「是否知道是谁」一项）；驾驶舱把它算系统动作，活动流写「（系统）自动推进了阶段记录」。
- **项目级报价单**（投标报价）不触发；老项目不补写。

### 3.5 独立审查的发现与处理

开 PR 前请了一个不带结论的独立审查（只给代码和规格）。它的发现：

| 发现 | 处理 |
|---|---|
| **阶段会往回退**：阶段只由招投标状态得出的项目（状态已提交、没有阶段时间），写上「供应商报价」的时间后阶段记录从「项目提交」退回「供应商报价」 | 已修：只在写上之后会变靠后时写；测试覆盖 |
| **人再推进到「供应商报价」变成什么也不做**，状态与回调就此跳过 | 没改代码，照实写进 §3.1 与设计，留给你定 |
| **开关关闭时并不「完全相同」**：每次多查一次库、多加载一个模块 | 已修：调用方先看总开关，关闭时不加载、不查库；纯逻辑测试核对顺序 |
| 测试没走真实入口：回信解析直接调录入函数；分析收尾的接线断言没要求在租约检查之后；读之后被放弃、来源系统回调、开关关闭时的询价、第二轮询价、几个结果状态都没测；把审计 / 建任务的错误吞掉的变异没被发现 | 已补：回信解析走它真实的写入函数；接线断言要求在租约检查之后；补上这些用例；用临时触发器让写时间、建任务、写审计各自失败 |
| 单独跑本分支的隔离库测试会失败 | 照实写进 §3.2：合并顺序 #447 在前 |
| 审计在驾驶舱里被算成人的操作，活动流显示原始代码 | 已修：标为系统动作，两张表加中文名 |
| 已提交的项目补上报价时间，时间轴上「供应商报价」排在「项目提交」之后 | 已修（同第一条：不会变靠后就不写） |
| 那行「阶段记录没有自动推进」会说错 | 核了：开关打开后仍出现的情形里这句话是对的；见 §3.4 |
| 电话询价（人工标记已发送）不触发，阶段会从项目解读直接跳到供应商报价；已取消的轮次里的报价会触发；记了授标日期的不算结果；项目类型区分大小写；执行时一封没发（全是此前已发）也触发 | 已修：标记已发送也触发；已取消的轮次不算；授标日期算结果；不分大小写；按这一次真的发出几家 |
| 设计里说询价发出只在 Muse 审批之后 | 改成「审批通过后（Muse 或网页审批）」 |

审查确认没有问题的：租户隔离（录入报价核对询价项 → 轮次 → 项目，接口先核写权限；回信解析的项目与组织取自库；执行器有跨组织检查；触发的人都来自服务端）；挂钩的位置（分析收尾在租约检查之后，询价在发出之后，都不在事务或租约里）；`tenderStatus` 为空时的条件写入；没有对外发送、没有模型调用；审计不含金额；测试跑完不留数据。
