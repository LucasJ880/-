## 1. 问题

PROC-1 每周从 CanadaBuys 官方开放数据拉新标、按关键词筛进「采购监控」，但候选上只能「关注 / 忽略」。看中一条要自己新建项目、手抄编号 / 截标日 / 采购方 / 链接，再手动关联——这是 H7「发现 → 跟进」的断点。

## 2. 做了什么

- 采购监控的**招标公告**候选多一个「跟这个标」。点了：建招投标项目（负责人 = 点的人；成员、环境、讨论区消息、台账与手工新建相同），预填名称、招标编号、截标日、发布日期、采购方、来源平台与公告链接；公告关联为「本项目」并改为「关注」；截标日写进负责人的日程。
- **只建一次**：事务里锁公告行；先认指向还在的项目的「本项目」关联（与卡片一致），再认跟标建过的项目（关联被改成前序 / 历史也认得出）；项目被删的关联不算。两人同时点只建一个。
- 不能跟：不是招标公告 400（即使有关联）、没跟过且已截标 409、只读成员 403、别的组织 404、组织已归档 403、监控未启用 503。跟过的截标后再点返回原项目。
- 卡片：「跟这个标」/「已跟进 · 打开项目」；只读成员不显示按钮（监控接口多返回 `canFollow`）；候选列表的关联按建立时间排、去掉指向已删项目的。
- 项目「最近变化」写「从采购监控跟进了采购公告「标题」」（活动流与驾驶舱都加了中文动作名；PROC-1 的手工关联也一并有了中文）。
- 新项目没有文件；上传招标文件后照现有流程自动分析。

## 5. 独立审查

开 PR 前请了一个不带结论的独立审查（只给分支、四件套、规格与调查文档；它写了一次性探针在隔离库里复现、做了 19 处变异）。处理：

| 编号 | 发现 | 处理 |
|---|---|---|
| H1 | 与 PROC-1 的手工关联（`tender-link`）不互斥，并发时一条公告可有两条「本项目」关联；卡片可能指向另一个项目 | 部分修。PROC-1 本来就允许多条「本项目」关联、不加锁，不改它（不在范围）；跟标与卡片都取**最早一条还在的**关联，结果一致；写进 design Risks |
| H2 | 手工把跟标建的关联改成「前序」后再跟，会建第二个项目 | 修。第二道查：本组织里由跟标建出、还在的项目（来源元数据里的公告 id） |
| M1 | 项目被删后关联还在，公告再也跟不了、卡片指向 404 | 修。只认指向还在的项目的关联；候选列表去掉已删项目的关联 |
| M2 | 截标日没进日程（文件回填遇到已有截标日会跳过，永远不会同步） | 修。建项后同步里程碑日程 |
| M3 | 有关联时合同 / 已截标也返回 200，与 spec 不一致；合同有关联也显示「已跟进」 | 修。先拒非招标公告；已跟过的截标后返回原项目写进 spec；按钮只对招标公告 |
| M4 | 成功 / 错误提示被重新读取清掉；只读成员看得到按钮、点了静默 403 | 修（成功提示在截图时已发现并修）；失败不再重新读取；只读成员不显示按钮 |
| M5 | 台账分支只有源码检查 | 补隔离库用例（台账开着写且只写一条） |
| L | 平台与链接可能来自不同证据；截标日按 UTC 显示可能差一天；spec 没写 201 / 200、返回体、审计；任务没打勾；源码断言多 | 前三项修 / 写进 spec；截标日显示是既有写法，写进 Risks；任务已打勾；源码断言保留（隔离库用例是行为上的把关） |
| 变异 | 19 处里 M7（不记分诊时间）、M14（跳过台账）存活；M12 等价 | 补断言后复跑见下 |

## 7. 已知限制

- 与 PROC-1 手工关联并发时可能有两条「本项目」关联（既有规则）；跟标与卡片都取最早一条。
- 项目字段是跟的那一刻的快照，公告修订不会自动改（P2-4 另做）。
- 项目页的截标日按 UTC 取日期显示（既有写法）。
- PROC-1 采购监控页原有的「保存配置」「人工导入」的成功提示也会被重新读取清掉（既有问题，没改）。

## 8. 没做的

早报里的新标（P2-3b）、预评分（P2-2）、新标视图与每天排期（P2-1 收尾）、自动拉公告附件（P2-3c）、自动跟进。

## 9. 上线

合并后照常部署。零 schema、没有开关：只有已启用采购监控（`PROCUREMENT_RECORDS_SCHEMA_READY`）的环境里出现按钮；点了才建项。回滚 = 回滚代码（已建的项目是普通招投标项目，照常可用或删除）。
