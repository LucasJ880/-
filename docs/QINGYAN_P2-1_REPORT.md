## 1. 问题

PROC-1 已经从 CanadaBuys 官方开放数据拉新标、按组织关键词筛进「采购监控」，但排期只能靠接口改（默认每周一、周四），候选页把公告、合同、信息公开请求混在一起按「资料申请优先级」排，也不按截标日过滤、看不到公告链接——「这几天新出的、还能投的标」要一条条找。

## 2. 做了什么

- **扫描时间可以在页面上改**：设置页多一块「扫描时间」——星期几多选与时刻，快捷按钮「每天」「工作日」「默认（周一、周四）」（只换星期几，不动时刻）。保存时排期改过才放进请求（别人刚改的排期不会被你改关键词时覆盖）；一天没选或时刻不合法就不发并写明原因；只有管理员能改。说明文字对七天写「每天」、周一到周五写「每个工作日」。
- **候选页的「新标」筛选**：只列招标公告中截标时间未过（或未知）、没被忽略 / 归档 / 标为历史记录的；按发布日期从新到旧，同一天的按首次发现新到旧，没有发布日期的排最后。按编号搜时已截标的也不会被带出来。
- **发布日期与「看公告」**：招标公告的卡片显示发布日期、截标时间（多伦多），有链接的有「看公告」（新窗口）。公告链接与「跟这个标」预填的同一规则、同一查询。
- 顺带：保存配置失败不再重新读取（错误与正在改的内容都保留）；扫描结束后的刷新不覆盖正在改的配置；「保存配置」「人工导入」的成功提示不再被重新读取清掉；停用后的刷新不再把接口返回值当成参数。

## 5. 独立审查

开 PR 前请了一个不带结论的独立审查（只给分支、四件套、规格与调查文档；它在隔离库验证、做了 16 处变异）。处理：

| 编号 | 发现 | 处理 |
|---|---|---|
| H1 | CanadaBuys 的发布日期只有日期（入库为 UTC 零点），按多伦多时间显示退一天 | 修。接口按 `YYYY-MM-DD` 返回，页面原样显示；用例用 UTC 零点 |
| M1 | PROC-1 解析不带时区的截标时间用服务器时区（生产 UTC），多伦多 14:00 存成 14:00Z，页面显示 09:00，新标视图与跟标早约 5 小时当成已截标 | 既有问题，不在本 change 改；写进 design Risks 与下面「已知限制」，下一个 change 修 |
| M2 | 首次发现时间排序、发布日期的值、搜索与截标过滤的组合、历史记录、说明文字反例都没测到（10 处变异存活） | 补齐用例；复跑见下 |
| L1 | 跟标只看最新 20 条任意证据，可能与列表挑出不同链接；同时间没有次序 | 修。两处同一查询（有链接的证据）与同一排序（抓取时间、id） |
| L2 | 合同的 `noticeUrl` 是开放数据接口地址 | 修。只给招标公告 |
| L3 | 证据逐行过滤 O(行 × 证据)、查询不限类别 | 修。按公告分组一次，只查招标公告 |
| L4 | spec 没写排除历史记录 | 修 |
| L5 | 保存失败照样重新读取（清掉错误与正在改的）；扫描结束的刷新覆盖正在改的配置；成功提示被清掉 | 修 |
| L6 | 任务没打勾、截图与报告没生成（审查时） | 已补 |

## 6. 变异核对

- 第一轮 23 处（筛选、排序、链接、接口参数、扫描时间规则、说明文字、页面接线）：22 处被发现；「快捷按钮重置时刻」存活，补用例后被发现。
- 处理审查后定向复跑 15 处（审查存活的与新规则）：14 处被发现；存活的「证据查询不限类别」是等价变异（结果由只给招标公告链接的规则决定，只差查询量）。

## 7. 已知限制

- **截标时间时区（既有，下一个 change）**：见 §5 M1。修好之前，CanadaBuys 公告的截标时间显示早 4–5 小时，当天截标的会提前从新标里消失、提前不能跟。
- 新标视图最多 100 条（沿用候选列表上限）。
- 改成每天后每天多拉一次两个 CSV（上限 60 MB、30 秒），仍由既有 cron 执行。
