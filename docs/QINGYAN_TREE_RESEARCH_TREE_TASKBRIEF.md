### TREE-1 `public-page-reader`：读公开网页（排第一）

新增 `src/lib/web-reader/`，对外只有一个函数 `readPublicPage(url, ctx)`。

**读网页的六条规则**（全部在代码里强制）。前三条对应 OpenAI 公开说明的做法；后三条是青砚自己的护栏，不是 GPT 的做法。第 4 条需求方于 20:02 提出取消，未采纳：绕过对方的访问限制（换地址、代理池、批量注册、过验证码、伪装浏览器）不做，见 Out of scope。
1. 只在人发起的调研任务里读；调用方必须带调研 Job 的标识，定时任务上下文直接拒绝。
2. 请求头表明身份：用户代理写明青砚与联系网址，不伪装成浏览器。
3. 不登录：不带 cookie、不带任何凭证、不填表单。
4. 被挡即停，临时故障可重试：遇到登录页、验证码、401 / 403 或跳转到登录地址，返回 `blocked` 并写明原因，不换地址、不换代理、不重试。超时、连接中断、5xx 属临时故障，最多重试 2 次，间隔递增；429 只在对方给出等待时间且不超过 30 秒时等够了再试一次，否则按被挡处理。
5. 限量：读页数只受每支 12 次的额度约束，所有站点一个标准，ImportYeti 不另设更低的数（Evan 2026-11-22 20:02 定）；对同一站点的两次请求间隔不少于 2 秒。
6. 同一网址在一棵树内只读一次，第二次直接取第一次的结果。

**其它**
- 安全：网址先过 `validatePublicHttpUrl`；解析出的地址是内网、回环、链路本地一律拒绝；最多跟 3 次跳转，每一跳重新校验；超时 15 秒；正文上限 2 MB，超出截断并标 `truncated`。
- 内容：HTML 转纯文本；PDF 用现有的 unpdf 抽文字，写入前清掉 U+0000（同 FIX-13）；其它类型拒绝。
- 站点名单（代码常量 + 组织设置覆盖，零数据库结构改动），三类：可以读 / 按人发起处理 / 不碰。「不碰」里预置要登录的站（1688 详情、MERX 等）。「按人发起处理」里预置 ImportYeti，读页上限与其它站相同。robots 见判断点 1。
- 返回 `{ untrusted: true, url, finalUrl, fetchedAt, text, truncated, blocked }`。审计只记网址、状态、字数，不记正文。
- 测试：内网地址与跳转到内网被拒；登录页、验证码、403 返回 `blocked` 且不重试；超时与 5xx 重试 2 次后放弃；429 带 10 秒等待时间 → 等够后再试一次，不带或超过 30 秒 → 被挡；限量与间隔；同址去重；定时任务上下文被拒；PDF 的 U+0000 被清。全部用注入的假网络，不连外网。

### TREE-2 `research-tree-runtime`：树的骨架

新增 `src/lib/tender-research-tree/`。

- **是一个独立的 Job**，`workDomain` 仍是 tender，但带一个「调研」标记；它的失败不触发 `job-failure-surfacing.ts` 的「AI 分析未完成」收尾（见「不确定处」第 1 条）。
- **图由服务端写死**，照 `tender-workforce/deterministic-plan.ts` 的做法，每步显式 `workerKey: "tender_worker"`，模型不参与编图。
- **两波**：第一波是固定分支（本批为 ① 条款、② 往期同标、③ 同类项目）；第一波的交接单回来后，按「分叉规则」确定性地编出第二波。运行时若支持中途加步骤，可以合成一波，但不为此改运行时。
- **分支步骤的工具** `tender_research_branch`（登记方式同 `tender-workforce/tools.ts`，不进全局目录）：一个有上限的循环——模型提出下一步（搜索 / 读页 / 结束），代码执行并扣减额度，直到结束或额度用完。每一次模型请求都受这一片的绝对截止时间约束，做法同 FIX-12。
- **被挡了换来源**：读页返回 `blocked` 时循环不结束，子代理接着用搜索摘要、别的公开网站、该公司官网去找同一件事，直到额度用完。这是换来源，不是换地址再去读同一个站：同一站点在这一支里被挡过一次，这一支不再读它。被挡只记在这一支的明细里；只有整支什么都没查到时，树干才写「这一支被挡，未查到」。
- **额度**：深度 5、分支 24、每支搜索 16 与读页 12，写成常量，可被组织设置调低、不可调高；并行数沿用 `WORKFORCE_JOB_MAX_PARALLEL_TASKS`。额度用完写「到上限，未查完」。
- **交接单** `research-handoff/v1`，放在现有交接信封的业务输出里，四栏：`found[]`（每条：事实类型、值、网址、原文摘录 ≤200 字、读取时间）、`notFound[]`（原因：没有 / 未接通 / 被挡 / 到上限）、`suggestedBranches[]`、`usage`。
- **分叉规则**（纯函数，表驱动）：② 查到中标方 → 记入「待反查」（第三批才长分支，本批只列出）；② 没查到 → ③ 全量；③ 不足 3 条 → 放宽到数量不限、近 6 年、加上美国；子代理建议的分支不属于规则表里的任何一类 → 进「未追的线索」，不自动长。
- **落库**：步骤与交接单用现有的 `AgentRunStep`；树干结论写进情报室的 `summaryJson.researchTree`（用 `patchRoomSummary`）。零数据库结构改动。
- 测试：分叉规则真值表；额度扣减与到上限的文案；一支失败不影响其它分支与树干；开关关时不建 Job。

### TREE-3 `research-branches-awards`：三个子代理

| 子代理 | 输入 | 能用的 | 交回 |
|---|---|---|---|
| 条款员 | 已解析的标书页 | 不联网。先用关键词规则命中条款（Equivalent Products、No Substitute、Canadian Content、Limited Tendering 等），再由一次模型调用判断并引页码 | 是否要求本地 / 加拿大含量、是否指定品牌、是否接受等效品及要什么证明；没写明就标「未写明」并给一条澄清问题草稿 |
| 往期同标员 | 采购方、品项、合同期 | `canadabuys.ts` 的联邦合同数据；搜索；读页 | 上一期的中标方、合同额、数量、年份，每条带网址与摘录 |
| 同类项目员 | 品项、数量、规格关键词 | 搜索；读页 | 一组（采购方、年份、数量、合同额、币种）及其来源 |

- 单价换算是纯函数：合同额 ÷ 数量，原币，不换汇；同时给出「口径」字段（含安装 / 含运费 / 多年期 / 多品项 / 不明），口径由子代理从原文判断并附摘录。
- 可比度四项打分（纯函数）：同采购方、同规格、数量在一半到两倍之间、近 3 年。
- 条款员的结果同时写回招标要求页可见的位置（只读展示，不改已确认的要求）。
- 测试：单价与可比度的表驱动用例（用下文验收里的合成数字）；条款关键词规则；子代理输出过不了结构校验时该支记失败、不编结果。

### TREE-4 `research-cross-verify`：交叉验证

每条要进树干的事实逐条过，八条规则：

1. 核对由另一个步骤做，输入只有「待核的值 + 网址」，不带原子代理的推理。
2. 重新读该网址，金额、数量、公司名必须在读到的文字里逐字找到——用 `verifyEvidence` / `numbersIn` 这一套，代码判断；找不到 → `REJECTED`。
3. 中标方、合同额、数量需要两个不同域名的来源，或一个官方来源（政府域名、开放数据接口）；否则 `SINGLE_SOURCE`。
4. 公司名用 `company-identity.ts` 的三档：同名自动认；「建议」档进待确认；不做相似度。
5. 口径不明 → `BASIS_UNCLEAR`。
6. 只有 `VERIFIED` 进入建议区间；其余照列、不计入；互相矛盾的并排、不取平均。
7. 核对用的模型与查找时不同：查找用主模型时核对用备用模型，反之亦然；两者相同时在结果里写明「未能换模型」。
8. 人可以把任何一条标成「不对」，标了即剔除并重算；记审计。

测试：数字不在页面里 → 被拒；只有一个非官方来源 → 单一来源；两条矛盾 → 并排且不进区间；人工剔除后区间重算；核对步骤读不到页面（被挡）→ 该条标「未能核对」，不当作已核实。

### TREE-5 `research-trunk-view`：树干结论与页面

- **证据表**：来源、采购方、年份、数量、合同额、换算单价、口径、可比度、核对状态、出处。
- **建议**（纯函数，不调模型）：已核实且口径一致的记录不少于 3 条时，给出区间与中位数；不足 3 条只列事实，不出区间；顶上一句话由规则拼，并写「N 条里 M 条已核实」。
- **页面**：项目「情报」页签里新增一张「调研树」卡（不新开页签）：左边是树，每支一行，状态为 在查 / 查到 N 条 / 没查到 / 被挡 / 到上限；右边是树干结论。点一支看交接单与每条出处。每支有「重新查」，每条有「这条不对」。等待时显示「正在查…」「上次查询时间」。用了多少次搜索与读页显示在卡底。
- 金额类内容的可见范围与情报页签现有的授标金额一致，不另设权限。
- 界面一律中文。
- 测试：区间与一句话的表驱动用例；不足 3 条不出区间；开关关时卡片不出现。

### TREE-6 `research-page-intake`：一键送页

登录墙后面的内容、要登录的平台，由人自己看、自己送进来。

- 调研树卡片上每一支都有「我来补一页」：粘贴网址加页面文字，或上传截图 / PDF。另提供一个书签小工具：在任何网页上点一下，把当前页的网址与正文带到青砚的补页框里，由人确认后提交。正文走请求体，不放进网址。
- 送进来的内容记为「人工提供」，带提交人、时间、网址；和读网页得到的内容一样按不可信资料处理；提交后这一支自动重算，树干跟着更新。
- 核对口径：这类内容没法由系统重读，核对员改为在提交的文字里逐字回查；状态记「人工提供，未复读」，按单一来源对待，除非网址是官方来源。截图里读出的数不自动采信，和原图并排给人确认。
- 青砚不替人登录、不保存任何外站的账号或登录状态；书签小工具只读当前页的文字，不读 cookie。
- 测试：粘贴、截图、PDF 三种入口；正文不出现在网址与日志里；提交后分支重算；人工提供的记录不进「已核实」除非是官方网址。

### TREE-7 `research-records-request-draft`：查不到金额就去申请公开

- 往期同标一支出现「查到中标方但没有金额」或「确知有上一期合同但查不到结果」时，这一支上出现「起草资料申请」。
- 点了之后带着采购方、合同或招标编号、起止年份进入现有的采购记录申请流程（PROC-1，`src/lib/procurement-records/` 的 `requests.ts`、`request-pure.ts`、`request-templates.ts`：联邦用信息公开模板，省市按各自法律的模板），预填一张申请卡草稿。缺的字段照现有规则保留方括号，由现有的就绪闸拦住。
- 本 change 只做预填与跳转，不改 PROC-1 的模板、状态与提交流程；提交仍按 PROC-1 现有的规矩由人办。
- PROC-1 受 `PROCUREMENT_RECORDS_SCHEMA_READY` 保护；未就绪时按钮不出现。
- 测试：两种触发条件；预填字段与来源一致；PROC-1 未就绪时不出现入口。

### TREE-8 `research-buyer-question`：直接问采购方

- 往期同标一支没查到中标方或金额时，自动往现有的澄清问题清单里加一条待确认的问题：上一期同类合同的中标方、合同额与合同期是否可以提供。走现有的澄清清单与导出（`projects/generate/rfi-export.ts`），不新增对外发送的通道。
- 同时给一段可复制的英文邮件草稿，收件人留空，由人按标书规定的提问方式发出。
- 页面上写明两点：提问有截止日，过了就不显示这一条；采购方的答复通常会以补遗形式发给所有投标人。
- 测试：触发条件；提问截止日已过时不出现；不产生任何待批卡与出站。
