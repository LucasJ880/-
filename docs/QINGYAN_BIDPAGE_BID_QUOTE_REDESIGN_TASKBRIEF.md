## 一条规则

**一页只做三件事，按做事的顺序排：找供应商询价 → 定报价 → 出文件。能自动带出来的不让人再填，对外发的照旧人批，界面一律中文。**

## Why

- 用户原话是「太复杂了」。复杂不在功能少，而在：九块东西没有先后、同一件事（找供应商）有三个入口、报价页把专业估算师才用得到的东西全摊给了每个人。
- Sunny 的投标有两种交法：有的要逐行填单价（官方价格表），有的只交一个总价、总价由货值 + 海运 + 关税 + 税等拼出来。现在的引擎只适合后者里最复杂的情形，逐行那一套又没存库，两头都不顺。
- 这一版主要给中国同事用，中英混杂直接增加了看错、点错的机会。

### BIDPAGE-1 `bid-page-v2-shell`：三步骨架 + 「下一步」提示（排第一）

- 新页面从上到下：顶部一条「下一步」提示 → ① 找供应商、询价 → ② 定报价 → ③ 出文件。每一步是一个可折叠分区，标题右侧一句话状态（例：「2 家已询价，1 家已回」「我方报价 12,345.00 加元，已定」）。默认展开「下一步」指向的那一步，其余收起。
- 「下一步」由确定性规则算出，不调模型。规则按先后命中第一条：招标要求还没批准 → 「先去『招标要求』确认要求」；项目没有关联供应商 → 「添加供应商或起草询价」；有供应商但没发过询价 → 「起草询价」；已发询价、无回复 → 「等供应商回复（已等 N 天）」；有供应商报价、没有报价草稿 → 「开始做报价」；有草稿未定 → 「检查后定为我方报价」；已定 → 「导出价格表 / 生成投标文件」。每条带一个按钮，直接跳到对应分区并展开。
- 版本历史按钮移到页面右上角的「更多」里。管理员才关心的运行信息（引擎版本、计算版本号一类）在新页面不显示。
- 只读接口：新增 `GET /api/projects/[id]/bid-page-summary`（或并入既有只读接口，实现者定），聚合三步的一句话状态与「下一步」；金额字段只对有 `project:cost:read` 的人返回，其余人拿到的是「已定 / 未定」这类不含数字的状态。

### BIDPAGE-3 `quote-line-mode-persist`：报价做法一「逐行报价」，成本存进系统

适用：招标方给了价格表、要逐行填单价的项目（只供货居多）。

- 新建报价时先问一句「这个标怎么交价？」——**逐行报价**（招标方有价格表，每行填单价）/ **只报总价**（BIDPAGE-4）。再问业务类型：只供货（默认）/ 供货加安装 / 长期供货协议。选择存在 `ProjectQuote.engineJson`（在 `engineConfigSchema` 里加可选字段，如 `entryMode: "LINE" | "LUMP_SUM"`；旧报价没有这个字段 → 按现在的界面打开，归入「专业模式」）。
- 逐行表默认 7 列：品名 | 数量 | 供应商报价（原币）| 到手单位成本（加元）| 我方单价 | 行合计 | 毛利率。行来自招标要求里已确认的价格表（`src/lib/tender-price-schedule/`）；没有价格表时可粘贴或手加行（复用 `src/lib/tender-bid-workspace/paste-import.ts`、`line-entry.ts`）。
- 「供应商报价」优先从第 ① 步已回的询价里选（选哪家的报价由人点），也可手填；手填时必须选证据类别（已签报价 / 平台标价 / 零售价 / 估计，词表在 `tender-bid-cost/contract.ts`）。
- 表下方一小块「共用参数」：汇率、海运费、报关费、关税率、国内运费，以及三项预置（管理费 3%、资金年化 8% × 月数、提成 = 毛利的 30%）和现金备用金 1%——预置值照 `templates.ts`，可逐项目改，旁边一句话说明算法。共用费用按既有分摊规则摊到各行（`tender-bid-cost/line-cost.ts`、`freight.ts`、`pricing.ts`）。
- 顶部四个数：报价合计 | 成本合计 | 利润 | 毛利率。没有成本权限的人只看到报价合计。
- **成本存库**：逐行成本输入与核算结果写入既有 `QuoteCostLine`（成本类别按 `tender-bid-cost/contract.ts` 已对齐的类别）与 `QuoteLineItem`（公开卖价行，`sourceJson` 记溯源），读写一律过 `requireQuoteAccess`。不再写浏览器本地存储；`BidIntelligenceRoom.summaryJson.bidWorkspace` 仍然只放非财务内容，不许把成本写进去。逐行核算与引擎汇总两条算路的合计必须对得上（用 `tender-bid-cost/reconcile.ts` 的做法做一致性校验，对不上就在页面顶部明说差多少、差在哪一项，不静默取其一）。

### BIDPAGE-4 `quote-lump-sum-mode`：报价做法二「只报总价」

适用：招标方只要一个总价，总价由货值、海运、关税、安装、税等拼成（对应 Sunny 的「报价分析总表」）。

- 界面是一张「总价构成表」，一行一个大项：项目 | 金额（或比例）| 备注。开始只有 4 行：货品、海运费、关税、销售税；其余通过「添加一项」从中文清单里选——国内运费、报关费、加拿大境内运费、包装、安装、测量、深化图、设备 / 场地、保函、保险、清洁、差旅、项目管理、售后预留、下错单 / 漏单预备金、其它。**不预置空行。**
- 每一项落到既有 `QuoteCostLine` 的既有类别与计算方式（如 货品 → `PROCUREMENT`，海运 → `FREIGHT`，关税 → `DUTY`，保函 → `BOND`，预备金 → `CONTINGENCY`，清洁 → `OTHER`），不新增类别、不新增计算方式。销售税走既有 `computeTax`（`engineJson` 的税配置），不当作成本行。
- 三项预置 + 现金备用金默认带上、可改、可关（同 BIDPAGE-3 的说明文字）。
- 定价一行：「目标毛利率（按售价）」+ 结果「税前报价 / 销售税 / 含税总价」，下方一句话写出算式：税前报价 = 成本合计 ÷（1 − 毛利率）；含税总价 = 税前报价 + 税。旁边是 BIDPAGE-5 的「AI 建议」。
- 货品一项可以展开成明细（型号 × 数量 × 单价），也可以直接填一个总数；从询价回复里选报价的做法同 BIDPAGE-3。
- 逐行与总价可以互转一次：逐行 → 总价（各行按类别汇总）随时可以；总价 → 逐行只在货品已有明细时允许，否则提示先补明细。

### BIDPAGE-5 `quote-margin-advice-market`：AI 毛利建议改成「先查市场，再给数」

- `adviseMargin` 的输入增加：货品品类与规格关键词（取自成本 / 报价行说明）、项目内已有的市场依据（既有情报：历史授标价、预计中标价、参考价——只读取已入库的记录，不新发检索）、以及一次网络检索（照 `adviseDutyRate` 的 Tavily 用法，最多 2 条查询）。
- 输出增加：品类判断（大宗通用 / 常规 / 特殊定制）、建议值、建议区间（低 – 高）、把握程度（高 / 中 / 低）、理由、出处链接。范围从 15%–30% 放宽到判断点 1 的默认值；大宗通用品类允许给到个位数。

## 合并授权、交叉验证与交接（Evan 2026-11-22 18:01 追加）

**授权范围**：实现者可以自行合并本任务书的八个 PR（BIDPAGE-1 ～ 8），不必逐个等人点。授权只覆盖这八个；其它轨道的 PR（#532 ～ #539、#543 ～ #546、CHAIN-2e 等）不在内，照原规矩办。改环境变量、打开开关、对外发任何东西，仍然不在授权内。
