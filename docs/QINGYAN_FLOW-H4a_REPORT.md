# FLOW-H4a 报告：项目页上能记「已提交」并留回执

| 项 | 值 |
|---|---|
| change | `tender-submission-record` |
| TASKFLOW | FLOW-H4a（Phase F 续） |
| 来源 | 交接文档 §0.5c 第 2 项的前半（方案 §7 的 H4）；Lucas 2026-11-12：「按照你的推荐开始吧」 |
| 分支 | `claude/flow-h4-submission`（从 main 开，直接指向 main，不叠层） |
| 性质 | 会写项目的提交时间。零 schema、零模型调用、没有新增出站。新开关 `TENDER_SUBMISSION_RECORD_ENABLED`（默认关），关闭时接口 404、页面与原来相同 |

## 1. 问题

投标在门户上交完之后，青砚里没有地方记这件事：

- 写提交时间的路径只有一条——项目对话里模型给出的「阶段推进建议」卡片；项目页上没有按钮。「提交」页签上那句「提交/开标日期在关键日期里维护」对提交时间是错的（那里改不了）。
- 那条路径写的是点击那一刻的时间，记不了「昨天下午交的」，也不留回执。
- 所以「截标日期已过、没有提交记录」的项目里，有一部分其实已经交了；FLOW-H1 的卡片遇到这种情形只能指到关键日期。

## 2. 做了什么

1. **接口** `GET` / `POST /api/projects/{id}/submission-record`：读取与记录提交——实际提交的时间、提交方式、回执编号（可空）、备注（可空）。
2. **三种情形**：

   | 情形 | 条件 | 做什么 |
   |---|---|---|
   | 第一次记录 | 没有提交时间，也还没有投标结果 | 走既有的阶段推进：提交时间写成人填的那个，招投标状态写成已提交；讨论区消息、审计、成员通知都沿用 |
   | 更正 | 已有提交时间 | 只改提交时间这一个日期；不动招投标状态，不发阶段通知 |
   | 补记 | 没有提交时间，但已经有投标结果（已中标、未中标等） | 只补上提交时间；**不改投标结果** |
   | 不能记录 | 项目已放弃 / 已归档；或投标结果是不投标、已放弃投标、已取消且没有提交时间 | 409，说明原因 |

3. **记录只追加**：每一次记录与更正存成一条审计行，读最新的一条；之前的都留着。
4. **页面**：「提交」页签多一块「提交记录」。有写权限的人能记录与更正；保存前先校验、再确认一次。所有能看项目的人能看到最新的记录与是谁记的。
5. **「下一步」卡片**：截标已过、没有提交记录时，按钮去这一块；关键日期放在顺带要办的事里。

## 3. 需要你知道的取舍

### 3.1 第一次记录不能撤销，而且会通知成员

「已提交」是项目阶段的最后一段，阶段不允许回退（既有规则）。所以第一次记录之后只能更正时间与回执，不能把项目退回「没提交」。靠三样东西兜着：只有写权限的人能点；保存前先校验、再弹一次确认，写明会发生什么；记错的日期与回执能更正。

第一次记录走的是既有的阶段推进，所以它原有的副作用都在：项目成员收到一条通知；项目有来源系统（BidToGo）时把「已提交」的状态回传给它——确认框里会多写一句。这个回传是既有行为，不是这次新增的出站。

### 3.2 main 上一个既有的错：阶段推进之后「为新阶段建任务」一直在失败

`src/lib/tender/stage-tasks.ts` 建任务时往任务表写 `sortOrder`，而任务表没有这一列，每次都报错；调用方把错吞掉了，只打一行日志。所以「[项目解读] 某某」「[项目提交] 提交投标」这类自动任务**从来没有建出来过**（「关掉上一阶段的自动任务」那一步在它前面，是正常的）。

这不是这次引入的，我没有在这个 change 里修：修了等于每一次阶段推进都开始真的建两三条任务，是一个影响所有招投标项目的行为变化。**要不要修、修了之后要不要这些任务，需要你定。**

对这个 change 的影响：我原先的理由之一是「不要在已提交之后再冒出『提交投标』的任务」。这个参数（`skipStageTasks`）仍然加了、也单独测了「带上它就根本不去建」，但今天在数据上看不出区别——因为建任务本来就是坏的。四件套里已照实写明。

### 3.3 回执只记编号，不传文件

现有的上传接口会把任何文件当招标文件处理：触发招标分析、计入文件包、把已生成的文档标为过期、通知成员。要安全地传回执，得先给项目文件加一个类别，那需要改表结构。所以这次回执只有一个人填的编号；页面上写的是「由记录人填写」，不说「已核实」。

### 3.4 备注里的金额过滤只是提醒

备注里出现常见的金额写法（`$128,000`、`12.8 万元`、`毛利`、`5%`）会被拒绝并说明原因。但纯数字、全角符号、中文数字写的金额拦不住；反过来「上传进度 100%」这样的正常备注也会被拦。硬约束是记录里没有金额字段。回执编号不拦（门户的编号可能长得像 `CAD-2026-00123`）。

### 3.5 财务侧的数字会动

给已中标、未中标但没有提交时间的项目补记之后，它们在财务的投标统计里会从「未提交」变成有提交。这是把数据补对，但报表上的数字会变。没投的标（不投标、已放弃投标、已取消）不能补记，不会被算成投了。

### 3.6 其它

- 保存之后整页会重新载入（提交时间与阶段都变了），人会回到页面顶部。沿用的是页面既有的重新载入。
- 提交时间不与截标时间、项目创建时间比较：迟交照实能记。
- 第一次记录时，提交时间由阶段推进写入，回执记录紧随其后写；万一后一步失败，项目是「已提交、没有回执记录」，页面上可以再补。
- 开关关闭时每次打开「提交」页签会多一个返回 404 的读取请求。

### 3.7 独立审查发现的问题与处理

开 PR 前请了一个不带结论的独立审查。它查出的问题：

| 发现 | 处理 |
|---|---|
| **时间差一小时**：页面拿「今天」的时区偏移去换算所填的日期。在 11 月补记 10 月（夏令时期间）的提交，会整整错一小时——而补记过去的提交正是这个功能的主要用法 | 已修：按所填那一天的偏移换算；测试在多伦多时区下核对夏令时两侧 |
| 「不再建那两条任务」的理由不成立：建任务在 main 上本来就是坏的 | 四件套照实改写；参数保留并单独测；见 3.2 |
| 只补回执、没动时间，也会把已有提交时间的秒数抹掉，并多出一条「提交时间变了」的消息；更正时备注被清空 | 已修：没动过时间就原样保留；方式、回执、备注都带出 |
| 没投的标（不投标、已放弃投标）也能补记，会被财务算成一个还在等结果的投标 | 已修：不能记录，说明原因 |
| 记录的同时别人记了「已中标」或放弃了项目：结果会被冲成「已提交」 | 已修：第一次记录带着读到的状态去推进，状态变了就不推进，转到锁里重新判断 |
| 两个人同时第一次记录、填的不一样：页面可能把 A 的回执配上 B 的时间 | 已修：显示「与项目提交时间对得上的最新一条」 |
| 超级管理员在还没分发的项目上：页面说不能记，实际能记 | 已修：「能不能记录」与写接口逐条一致 |
| 提交时间收「2026-11-08」「11/08/2026」这类写法，会按服务器的时区去猜 | 已修：只收带时区的 ISO 时刻 |
| 回执编号被金额过滤误伤（`CAD-2026-00123`） | 已修：回执编号不按金额拦 |
| 来源系统回调只写在设计里，用户看不到 | 已修：项目有来源系统时确认框写明 |
| 「提交状态」那一栏按 UTC 日期显示，与下面按本地时间显示的记录可能差一天 | 已修：提交记录可用时按本地日期 |
| 几条源码断言是空的；一批情形没覆盖（已归档、负责人 / 项目管理员、成功响应里的权限……） | 已补：隔离库测试 42 → 62 项，纯逻辑 62 → 78 项 |
| 规格没写的行为（已放弃 / 已归档 409、状态刚变 409 等） | 规格补上 |

审查确认没有问题的：权限与租户隔离（组织只取自项目记录，请求里的字段影响不了）；项目行锁不与外键检查、别的锁冲突；阶段推进的改动对既有调用方没有可见差异（除了同时点两次不再重复发消息）；更正不会发第二条「提交了项目」。

## 4. 与八条硬纪律的关系

| 纪律 | 情况 |
|---|---|
| 零 schema | 记录存既有的审计表；只写既有的 `submittedAt`、`tenderStatus` |
| 出站先审批 | 没有新增出站。第一次记录沿用阶段推进既有的 BidToGo 状态回调（只在项目有来源系统时），与在对话里推进阶段时相同，由人在页面上确认后触发。不发邮件，不碰门户 |
| 禁止第三套队列 | 没有后台执行 |
| 脱敏 | 记录里没有金额字段；备注与回执编号带金额时拒绝保存 |
| 不爬登录页 | 回执编号由人填，系统不去门户核实 |
| 邮箱分离 | 不涉及 |
| 确定性优先 | 不调模型 |
| 测试注册 | 两个新测试已注册进 `scripts/test-all.sh` 与 `scripts/test-ci-unit.sh` |

## 6. 没做的

- 青砚代为提交、登录门户、抓取回执：不做。
- 上传回执文件：没做（现有的上传接口会把任何文件当招标文件处理）。
- 撤销「已提交」：没做（阶段不允许回退）。
- 交付前检查清单改成确定性生成、替掉模型生成的「投标准备清单」：FLOW-H4b，下一个 change。
- 把提交记录传给投标工作区的可投标判定：没做。
- 修「阶段推进后建任务一直失败」那个既有的错：没做，见 §3。
- 生产开关：没有动。
