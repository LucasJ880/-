## 1. 问题

招标分析（V2）抽出的每条要求本来带着数量与单位，价格表的行、数量上限还会被抽成「数量类事实」。但把结果入库的那一步（`v2-map.ts`）只留了类别、原文、是否强制、页码——**数量与单位在这里被丢掉了**。

投标工作区的价格表因此只有「粘贴导入」一条路：人从发标方的文件里把价格表整块复制出来。一个标几十行，就要转录几十行；PDF 里的表格常常复制不成整齐的列。

## 2. 做了什么

1. **入库时不再丢。** 每条带数量的要求、每条数量类事实，记下说明、分析给出的数量与单位文字、出处（文件名 · 位置）、来自哪条要求。存在这次分析「价格与评标」一节已有的结构化字段里（这一节原来是空的），不加表、不加列。
2. **带入时用确定性的规则变成价格表的行。** 不调模型。数量只在整段文字「就是一个数字」时才取；单位查一张固定的对照表。
3. **一个只读接口** `GET /api/projects/{id}/bid-workspace/schedule-candidates`：取项目最新一份等待审核或已批准的分析，返回带入的行、粘贴文本、没带入的条目与原因。
4. **「粘贴导入」里多一个按钮「从招标分析带入」**：把文本填进粘贴框，下面列出每一行是分析从哪里抽到的。**不保存**——人核对、修改后仍点原来的「保存」。

截图（本地库、演示数据）：

- `docs/acceptance/fix-2/prefill-filled.png`：带入 5 行、没带入 5 条各有原因；价格表仍是 0 行。
- `docs/acceptance/fix-2/prefill-confirm.png`：粘贴框里已有内容时再点，先确认。
- `docs/acceptance/fix-2/prefill-saved.png`：人补上单位、把 `LF` 改成 `ft` 后点保存，价格表 5 行。

截图那次实际发出的请求：带入时只有一次 `GET …/schedule-candidates`；点保存时才有一次 `PUT`。

## 3. 需要你知道的取舍

### 3.1 规则偏严：宁可让人多填几个数，不带进一个错的

第一版的规则是「文字里恰好一个数字就取」。独立审查实际跑出来它会**悄悄取错**（见 §5）。现在改成白名单：

| 取 | 不取（列在「没带入」里，写明原因） |
|---|---|
| `2,367` → 2367 | `100-200`（范围） |
| `approx. 120` → 120 | `3 lots of 50`（不止一个数字） |
| `estimated 2,500 EA` → 2500 | `$5,000`、`10%`、`CAD 5000`（金额或百分比） |
| `60 pcs` → 60、单位 Each | `5k`、`12 dozen`、`Item 3`、`Dec 2026`（除了数字还有别的说明） |
| `2,500` 配单位 `Each` → 2500 | `approx. 120 per year`、`minimum 50`、`up to 300`（按期间计的用量、上下限——填多少由人定） |
| | `1.500`、`0,500`、`2,500 kg`（可能是小数，也可能是千位） |
| | `5 years`、`90 days`（单位是时间） |

代价是带不进来的比第一版多。它们都列在按钮下面，分析给出的文字与出处就在旁边。

**仍然取不准的一种**：没有单位、只有一组千位的 `1,500`，在法语文件里可能是一点五。无法与英文的一千五区分，照英文取。

### 3.2 说法不一致的不带入，不替人选

招标文件写 2,367、补遗写 2,900、补遗里又没有「改为」之类的话——分析不替人选，两条都标成待复核。这里跟着它：两条都列在「没带入」里，原因是「两处说法不一致，还没有定」。

### 3.3 不收哪些要求

行政、投标提交、质保、保函、保险、安全、样品、深化图、培训、踏勘、工期、报告这十二类不收（「深化图 3 套」「质保 5 年」不是价格表的行）。其余类别照收——类别是模型判的，供货的行常被标成技术、安装或强制，收窄了会漏行，而漏掉的行人看不到。

### 3.4 重复的行不合并

说明、数量、单位都相同的两条线索都带入，后一行标明「与第 N 行相同，可能是重复」。上游的去重已经把确实重复的并过了，剩下的可能就是两行（同一种货两个地点）；并掉了人看不到。

### 3.5 没有单位的行保存时会被略过

这是既有粘贴导入的行为（缺单位的行报红、不进保存）。带入后数量类事实常常没有单位，所以说明文字里写明「不补的行保存时会被略过」，解析结果那一行也加了「有问题的行不会保存」。

### 3.6 叫「分析抽到的数量」，不叫「原文」

要求的数量与单位是模型填的字段，上游没有逐字对过原文片段（只有数量类事实的原文值对过）。界面、规格都按这个叫法；出处写文件名与位置，表格来源用它自己的定位（`Sheet「…」· 行 …`），不说成页码。

## 5. 独立审查

开 PR 前请了一个不带结论的独立审查（它自己跑代码、自己做变异）。结论：多租户隔离、只读、取哪一份分析这三件事成立；问题在数量会悄悄取错、说法不一致的被带入、测试看不住「不保存」。逐条处理如下。

| 发现（它实际跑出来的） | 处理 |
|---|---|
| 数量文字在 160 字处截断：一段有两个数字的话被截成「…approximately 2,」，取出了 **2** | 整段保留（上限 300）；超长的截断处带「…」，不会再被当成完整的数量 |
| 「恰好一个数字就取」取错：`5k`→5、`12 dozen`→12、`Item 3`→3、`Dec 2026`→2026、`CAD 5000`→5000、`$1 500`→500、`.5 kg`→5、`50 per month`→50 等四十余例 | 规则改成白名单（§3.1）；它列出的每一例都进了测试 |
| 招标文件与补遗说法不一致的两条要求被带成两行、没有任何提示；测试里用的状态是生产上不会出现的 | 记下并标明、不带入（§3.2）；测试改为经真实的去重与补遗处理 |
| 合并过的要求，页码指向另一处 | 取原文片段里出现了这个数量的那一处（顺带发现并修了「100 对上了 1,100」） |
| 质保、样品、深化图的数量变成了价格表的行 | 按类别排除；单位是时间的不带入（§3.3） |
| 重复的线索被悄悄并掉；要求与它的数量事实又各成一行 | 不合并，标明（§3.4） |
| 300 条上限悄悄截断 | 记下原本多少条，说明文字里写明 |
| 被人驳回的数量类事实仍被带入 | 不带入（事实没有编号，按说法对上） |
| 表格来源被说成「第 N 页」，没有文件名 | 出处写「文件名 · 位置」 |
| 说明里带双引号（`20" x 30"`）经既有解析读回会少引号 | 按表格软件的写法引用，读回逐字相同 |
| 控制字符、NUL 没有去掉（NUL 存不进 JSON 列，会让整次入库失败） | 都并成空格 |
| 数量字段不是字符串时入库会抛错 | 当作没有 |
| 大写 `M` 被规整成米（它也表示每千件） | 原样保留 |
| 面板：取的过程中敲的字会被冲掉；改过之后对照清单仍像是最新的；失败时旧说明还在 | 取的过程中只读；换项目后作废；标明「是带入那一刻的」；失败时清掉 |
| **测试看不住**：给带入加上自动保存、让确认永不出现、跳过确认、把分析中的也算可用——四项测试全过 | 面板的判断抽成纯函数；带入那段代码里不许出现保存的动作；真库测试改用真实的七种状态。**30 处变异逐个核对，全部被发现** |
| 「响应不含任何金额」字面上不成立（招标文件里自己写的金额会原样显示） | 规格改为「不含我方的成本、报价、毛利」 |

没有改、写进了已知限制的：要求的数量没有逐字核对过原文（改叫法，不改上游）；公式开头的说明（`=…`）与手工粘贴同样的暴露面；一节的 JSON 变大。

## 7. 已知限制

- **分析抽得不全或不准，带入的行就不全或不准。** 界面写明要逐行核对；不保存。
- **本功能上线之前做的分析没有数量线索**，要重新分析才有；用旧版分析（V1）做的也没有。
- **尺寸、包装数、认证要求几列不带入**（分析结果里没有可靠的对应字段）。
- **没有单位、只有一组千位的数字照英文读**（§3.1）。
- **被驳回的事实按说法对上**：两条说法逐字相同的事实，驳回一条会让两条的线索都不带入。
- **按类别排除可能少带一行**（一条真的供货行被模型标成了质保或样品）。
- **真库测试在 CI 里是跳过的**（CI 没有隔离库），只在本地跑得出来。
- **一节的 JSON 变大**：300 条、说明都写满时约一百多 KB；读分析详情的接口会把它读出来再丢掉（既有的写法，没有改）。
- **功能在开关后面**：`TENDER_BID_WORKSPACE_ENABLED` 没开的组织看不到这个按钮。
