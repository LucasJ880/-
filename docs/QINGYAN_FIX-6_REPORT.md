## 1. 问题

分析完成、询价发出（FLOW-H1c 打开后还有录入报价、标记已发送）只写阶段时间，不改招投标状态。对话 AI 读的是招投标状态，于是会按落后的状态提议推进；人点确认之后：

- 落后正好一段（记录在「供应商报价」、状态「供应商询价」，AI 提议「供应商报价」）→「无需重复推进」；
- 落后不止一段（记录在「供应商询价」、状态「新导入」，AI 提议「项目解读」）→「不允许回退」。

两种都什么也不改，招投标状态和那一次 BidToGo 状态回调永远补不上。这在 main 上已经存在（分析完成、询价发出两处），FLOW-H1c 打开后会更常见。

## 2. 做了什么

人确认推进（推进卡片 → `/api/projects/{id}/advance-stage`）时，如果：

- 是招投标项目、进行中；
- 阶段记录已在人确认的那一段或更靠后；
- 招投标状态落后于人确认的那一段（为空，或它对应的阶段更靠前；认不出的状态不动）；

就只把招投标状态改成**人确认的那一段**对应的值（不替人多推），写一条讨论区的状态变化（「项目阶段从 X 变更为 Y」）与一条审计（标明补状态、人已确认、阶段记录与人确认的阶段），项目有来源系统时发一次状态回调。返回成功，提示「阶段记录已在「供应商询价」；招投标状态已同步为「跟进中」」。

不写阶段时间、不建不关任务、不写「推进到某某」、不发「项目已推进」的成员通知。写入带条件（读到的状态、进行中），同时点两次只补一次，读之后被放弃或记了结果就不补。其余情形与原来完全一样。

改动的文件：`src/lib/tender/stage-transition.ts`（两处提前返回之前加一步、新函数 `catchUpLaggingTenderStatus`）、`src/lib/tender/stage.ts`（导出 `tenderStatusStageOf`）、新文件 `src/lib/tender/stage-status-catch-up.ts`（判断规则，不读库）。

## 3. 需要你知道的取舍

### 3.1 没有开关，会在人点确认时发回调（已定：不加开关）

以前点了没反应的那一下，合并之后会改状态，并在项目有来源系统时给 BidToGo 发状态回调。已经落后的项目，下一次点确认就会发。回调和正常推进一样由人的点击触发，没有单独的审批卡；推进卡片上写的仍是「确认推进到某某」，没提会同步给 BidToGo。同类的 FLOW-H1c、FLOW-H4a 都有开关，这个没有：它只在人点确认时发生，走的是正常推进同一条路。**Lucas 2026-11-12：「不用加开关，按照你推荐的做吧」。**

### 3.2 一次只补一段

落后好几段时（状态「新导入」、记录在「供应商报价」），每确认一次补一段，要点几次。没有一次补到底，是因为回调会告诉 BidToGo 一个人没确认过的阶段。

### 3.3 与另外几个 PR 的接口

- **#446**：它给推进加了一个「事务里发现阶段时间已被写入」的出口，那个出口不补状态（读与写之间恰好被自动写入，极少见）。它的「记录提交」把「不是无需操作的成功」当作「提交时间已写入」；补状态的返回不满足这个前提，今天到不了（提交时间只由推进或「记录提交」写，都同时写状态）。#446 合并后我会在它的调用处加一道检查。
- **FLOW-H1c（#449）**：自动前进按读到的招投标状态做条件写入；补状态恰好在它读与写之间提交时，那一次自动前进不写（每家报价只触发一次，窗口很窄）。
- 与 #446、#447、#449 试合并，代码都没有冲突。

### 3.4 成员通知

点确认时不发「项目已推进」。审计用的是通用的「状态变更」，成员之后刷新通知会看到一条由它派生的「变更了状态」——与任何一次状态变更相同，是真实发生的事。

### 3.5 独立审查的发现与处理

| 发现 | 处理 |
|---|---|
| **只修了落后一段的情形**：最常见的是状态还是「新导入」、记录已在「供应商询价」，AI 提议「项目解读」→「不允许回退」（隔离库复现） | 已修：「不允许回退」的分支也先试补，补到人确认的那一段；测试走一遍「项目解读」→「供应商询价」两次确认 |
| **非招投标项目会被写上招投标状态**（外贸项目被写成「审核中」，而外贸助手把「有招投标状态」当政府采购） | 已修：只对招投标项目 |
| 「出站先审批」的「遵守」只是断言：点击会新发回调，没有开关 | 照实写进设计与 §3.1；Lucas 定不加开关 |
| 审计会派生「变更了状态」通知，规格与测试说「没有成员通知」说多了 | 规格改成只说不发「已推进」；测试调派生函数照实核对 |
| 第三处调用到不了；规则里两条判断改变不了结果；判断规则间接读库 | 已删；规则不再读库 |
| 提示语用阶段名当状态名（「跟进中」显示成「项目解读」） | 已修：用状态的中文名 |
| 与 #446、FLOW-H1c 的接口 | 写进 §3.3 |
| 测试：「没有成员通知」在只有一个人时是空的；「没有来源系统不发回调」在没有外部关联时是空的；讨论区只数了条数；回调的操作人、审计的组织没核；读之后被放弃没测；否定用例只等 150 毫秒、最后不复核 | 已补：由第二个人点确认并加正常推进的对照；造有外部关联、没有来源系统的项目；核对消息内容；补这几项断言；最后逐个项目核对回调数 |

审查确认没有问题的：条件写入与并发（两个变异都被测试杀掉）；只往前补，不会写回退的状态；权限与正常推进相同（写权限、已分发），没有新暴露；同一处重复点击不会重复发回调；`notifyProjectStatusChange` 全仓库只有推进这一处调用；AI 上下文确实只读招投标状态；测试跑完不留数据。
