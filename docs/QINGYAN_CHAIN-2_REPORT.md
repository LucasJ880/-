## 1. 做了什么

| 场景 | 以前 | 现在（开关打开） |
|---|---|---|
| 批准招标分析（或批准后再确认 / 驳回 / 批量确认要求） | 什么都不发生，候选池要人去供应链页建、点「发现」 | 自动起草之前，系统用内部来源（记忆、历史成功、已存供应商，每个最多 30 家）给这份分析建一个候选池；不调模型、不外查；每份分析只建一次；写审计 `tender.supplier_auto_run` |
| 建池出错 | — | 只记日志；审核动作照常成功，自动起草照常判定；执行途中出错的运行标为失败，下一次审核动作会重建 |
| 情报页签 | 看不到「该问谁、大概什么价」 | 调查区块之后多一张「寻源建议」卡：推荐型号 + 价格对照三栏 |
| 推荐型号 | — | 排名里首选 / 备选、强制项通过的前 3 个（名次、供应商、型号、五项分数、强制项那一句、「查看完整排名 →」）；没有就照实说：供应商情报没开 / 分析没批准 / 还没评估 / 都没过强制项（卡得最多的几条，不满足与资料不足分开数）/ 过了强制项但待核实 / 取数出错；另写自动建的候选池几家（未筛选） |
| 价格对照 | 三处各看各的 | 三栏并排、不合并：历史中标总额（同一采购方、剔除我方结果、同口径同币种、≥3 个样本的区间）/ 网上公开单价（外部情报已存的结果，原文照录）/ 我方落地成本（比价矩阵选定那家，加元，带税务与数量口径；只给有财务查看权的人）；卡上写「三种价格口径不同，不合并成一个数；报价由人定。」 |
| 自动起草询价（情报推荐开关打开） | 只用操作者的常用供应商或分组 | 名单里至少有一家能发时，名单之后补上排名里首选 / 备选、强制项通过、在用有邮箱的供应商（去重、合计 ≤ 8）；卡摘要与结果说明写「另外补了 N 家供应商情报推荐的：…」；审计另记。名单为空照旧不起草 |

两个开关都关时：四个审核接口的行为与响应、自动起草的结果与卡摘要与之前逐字相同（测试证明）；寻源建议接口 404，卡不显示。

**与任务书的两处出入（design D2、D4）**：

1. 任务书写「外部检索门开着时同时跑外部发现」。外部检索要几十秒，放在「批准」请求里会让人干等，异步补跑又要队列（硬纪律第 3 条）。所以自动建池只用内部来源；外部检索仍由人在供应链页点一次。
2. 任务书设想自动建的运行就能给出「强制闸通过、主选 / 备选」。实际上发现只产出强制项「待定」、没有分数的候选，结论要靠逐个评估（逐条判定要求；确定性规则只覆盖「点名认证」「数值阈值」两类）。所以推荐型号读已完成的评估；没评估时照实说，并给去供应链页评估的链接。

## 5. 多维审查

Lucas 2026-11-19 要求「分多个子 agent 多维度审核提意见修复」，并要求以后每次开 PR 都这样做——已写进 `openspec/config.yaml` 工作约定与 `CLAUDE.md`（本 PR 第一个提交）。

**第一轮（实现后，四个子 agent 各审一个维度，只给代码与规格）**——逐条核实后：

| 维度 | 意见 | 处理 |
|---|---|---|
| 安全与硬纪律 | ① 可比授标把我方结果也算进区间（本组织项目回灌的记录金额是我方报价 / 中标价；`ownWinnerNames` 只管竞争者那一块） | **已修**：先剔除 `projectId` 非空与中标方是本组织的记录；隔离库用 3 条他人 + 1 条我方中标 + 1 条项目回灌验证 |
| | ②③ 已被移出组织、但项目成员记录还在的人仍能读寻源建议、能触发建池 | **已修**：接口与建池都要求组织有效成员（平台超级管理员除外）；隔离库验证 404 与不建 |
| | ④ 报价表助手接口把落地价给任何能读项目的人（既有问题，不是本 change 引入） | **另开任务**「Gate landed cost in pricing-helper by finance access」 |

| | 「只留最早」在「后建的先提交、先查」时两边都会执行 | **已修**：开始执行前再查一次；隔离库并发两次只留一个 |
| | 「都没有通过强制闸」在候选过了强制项、只是待核实时是假的 | **已修**：分成「都没过强制项」与「过了强制项但待核实、风险高或分数不全」两句 |

## 6. 已知限制

- 推荐要人先在供应链页评估；没评估时卡上照实说。
- 候选池≈本组织在用的供应商（内部来源「已存供应商」不看简报，供应商情报既有行为）。
- 「批准」多出建池的时间（≤ 90 个候选的小事务，一两秒到几秒）。
- Serverless 超时杀掉进程时运行可能停在「执行中」，按供应商情报既有规则须有人在供应链页取消后重搜。
- 生产要先对 Sunny 打开 `SUPPLIER_INTEL_ENABLED`（CHAIN-0 第 6 项），再开 `TENDER_AUTO_SUPPLIER_RUN_ENABLED`；情报推荐并入收件人等评估做起来、推荐稳定后再开（需要 Vercel 权限）。
