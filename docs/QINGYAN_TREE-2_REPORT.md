## 1. 做了什么

- **人发起接口** `POST /api/projects/[id]/research-tree`：第一步项目写权限守卫（FIX-21 写法）；项目没有组织或开关关 → 404、不建 Job；请求体可省略（`action` 省略即 start，给了别的 → 400）；只收招投标项目（409）；同项目在查（排队或运行中）的调研 Job 复用并返回状态；`requestId` 重放；不阻塞的咨询锁收敛并发双击。
- **调研 Job**：工作域 tender 的独立 Job，元数据平铺 `researchTree / researchTreeVersion / researchTrigger / researchProjectId / researchStartedAt`，不设 `metadata.projectId`——一键分析的卡片、复用、取消与失败收尾都认不出它（失败不标「AI 分析未完成」）；调研标记只由发起服务写、发起服务只被接口引用（守卫测试）。
- **六步写死的图**：① 条款（本批交「未接通」）、② 往期同标、③ 同类项目（初查，额度减半）、第二波甲「补查」（② 没查到才跑）、乙「放宽条件」（③ + 甲不足 3 条才跑），树干；完成条件只看树干的工具结果（验证器不调模型）。
- **分支循环** `tender_research_branch`：一轮一次模型请求（搜索 / 读页 / 结束 + 针对刚读到那一页的事实），代码执行并扣额度（每支搜索 16、读页 12、模型 30，③ 减半；组织只能调低，含每棵树分支数与深度）；被挡换来源、同站这一支不再读、同一网址一棵树只请求一次；跨切片续跑，每一次模型请求、搜索、读页之前先记审计 `research.branch_step`。
- **安全**：搜索词外发闸（敏感词、本项目估值 / 我方报价 / 中标价的各种写法、0–9 以外的数字），网址只查数字；被拦的词不进审计；进模型的只有项目公开资料六项；网上来的与模型写过的文字都在不可信块里；事实只收「摘录逐字在刚读到的页上、值逐字在摘录里、数字对得上」的；跳到别的站的页不收事实。
- **交接单** `research-handoff/v1` 与**树干** `tender_research_trunk`：树干确定性汇总，写情报室 `summaryJson.researchTree`（每支中文名、短状态、理由、条数、未查到原因、用量；待反查的中标方名；未追线索只存类别；不含金额、摘录、网址、被挡站与模型自由文字）；没有情报室不新建。
- **登记**：两个工具进 `tender-workforce/tools.ts` 的执行集合（不进 LLM 规划面与一键分析的确定性面）。

## 6. 没验证到的地方与任务书出入

- **真实外部服务未验证**：本地没有搜索 key 与模型 key，搜索、模型与真实网站都只用假的；第一次真实请求在预发验收。实测用量见 §8。
- **一支只扛得住一次崩溃**（运行时语义：每步最多 2 次尝试，崩溃或丢租约那次不退回）：第二次这一步失败、Job 停在「需要人工处理」，不挡同项目再发起（D13、D16）。
- **出入**（都写进 design，待 Evan 确认）：③ 第一波「初查」用一半额度、第二波甲「补查」用全额（D2，对「③ 全量」的解释）；「任何定时任务都不发起」的口径——建好的调研 Job 每一片都由既有 agent-runs 处理器执行（D20）；条款一支本批交「未接通」（D15）；「确认招标要求时自动起一次」挪到 TREE-5（proposal Out of scope）；事实不从搜索摘要里收（D10）；同一网址一棵树只请求一次，别的支读过的页这一支拿不到正文（D7）。
- **定时任务的排队**：agent-runs 每次只取 2 条 Job、与一键分析共用；一棵树跑满额度要几十片（挑错实测 29 片），开关打开后一键分析排队可能变慢（生产影响未核实，打开开关前与 D20 一起确认）。
- **网页自写的「事实」**：只核对了「逐字在页上」，网页自己写的「winner is Fake Corp」会被收下、进待反查（挑错实测）；真假由 TREE-4 核对，TREE-4 / TREE-5 要把没过核对的标「未核实」。
- **给 TREE-5 的**：情报室里没有「在查」状态（树干最后才写），读取接口要查 Job 与步骤；没有情报室的项目读取接口要回退到树干那一步的结果；状态要显示「未接通」「无需追查」「未开启」；「查到 N 条」现在数的是事实。
