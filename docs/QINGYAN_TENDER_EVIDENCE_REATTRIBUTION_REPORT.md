# 证据归属纠正 + 抽取 prompt 定位规则

**起因**：docx/xlsx 纳入分析后（PR #114），生产真实包出现 `SNIPPET_NOT_ON_PAGE×115`
（此前纯 PDF 只有 3）。含义是 115 条候选被证据硬门拒收 —— **真实丢掉的内容**。

`SCHEMA_CHANGE = NONE`。

---

## 1. 先诊断，不猜

生产 run 的 `workerCursor` 缓存了全部 70 个窗口的**原始模型输出**，因此可以
**零 LLM 成本**离线重放验证（`scripts/tender-evidence-rejection-replay.ts`）。

拒收 125 条的分类（run `cmsvqyzq80001n1i6y24b51ss`）：

| 分类 | 条数 | 含义 |
| --- | --- | --- |
| **A 引错单元号，文档内唯一定位** | **92** | 引文逐字存在于本文档**另一个**单元；**零歧义** |
| B 仅跨单元拼接才存在 | 0 | — |
| C 文档内根本不存在 | 23 | 改写/臆造，**本就该拒** |

其中 105/115 发生在 xlsx 的 `sheet` 单元；出问题的窗口分别含 **4、4、3 个单元**
——多单元窗口是引错单元的温床（模型把整窗候选归到同一个单元号）。

## 2. 修法一：归属纠正（不放松纪律）

`verify.ts` 新增 `locateUniqueUnit`：引文不在被声称的单元上时，在**同一文档内**
寻找逐字所在单元；**恰好唯一**才接受，并把 `pageNumber` 纠正为真实单元号。

保持不变的铁律：
- 引文必须**逐字**存在（归一化仅限空白/NFKC，与既有一致）
- 位置必须**真实**（纠正后的单元号指向引文真正所在处）
- **跨文档不纠正**（说是 A 文档却在 B 文档 = 实质性错误，照旧拒收）
- 多处命中（歧义）不纠正；归一化后 <24 字符的短引文不纠正（防偶然唯一命中）
- 语义门 / 值支持门 / mandatory signal 判定全部不变

新增可观测字段 `AnalysisMetadataV2.evidenceReattributed`（纠正条数），
用于持续观察 prompt 改动的效果。

**效果（同一批生产模型输出重放，零成本、可复现）**：

| | 修改前 | 修改后 |
| --- | --- | --- |
| 通过验证 | 1392 | **1484**（+92） |
| 拒收 | 125 | **33**（−92） |
| 其中臆造类（应拒） | 23 | 23（不变） |

## 3. 修法二：抽取 prompt 定位规则（治本，已 A/B）

`PROMPT_EXTRACT` 升 `@3 → @4`，在每个窗口 prompt 末尾加 LOCATION RULE：块标记行
（`=== documentId X UNIT 3 (sheet: …) ===`）+ 「引文必须逐字取自**单一**块、
禁止跨块拼接、pageNumber 必须取自该块标记行」。

**A/B（真实模型调用，`scripts/tender-extract-prompt-ab.ts`）**：只重跑基线里引错
最集中的窗口——恰好就是全部 3 个出问题的窗口（含 4/4/3 个单元）：

| 指标 | 基线 @3 | 处理组 @4 |
| --- | --- | --- |
| 引在正确单元 | 0 | **84** |
| **引错单元** | **92（100%）** | **0（0%）** |
| 文档内不存在（臆造） | 0 | 1（1.2%） |
| 候选总数 | 92 | 85 |

**诚实边界**：样本 = 3 个窗口、每侧各跑一次。效应量极端（100%→0%）且方向明确，
但 n 很小；候选总数 −7.6% 与新增 1 条臆造都落在单次调用方差范围内，无法与噪声区分。
两项改动是**互补**关系：prompt 在源头减少引错，纠正逻辑是兜底安全网。

## 4. 冻结语义的显式修订（评审重点）

`v2-evidence` 套件里「错页 = FAIL」是 #97 建立的冻结纪律，本次**显式修订**为：

| 场景 | 旧 | 新 |
| --- | --- | --- |
| 错页 + 文档内唯一定位 | FAIL | **接受并纠正 pageNumber**（V2-E1a） |
| 错页 + 文档内多处出现 | FAIL | FAIL（V2-E1b） |
| 错页 + 引文过短 | FAIL | FAIL（V2-E1c） |
| 页码不存在 + 唯一定位 | FAIL | **纠正**（V2-E6b） |
| 页码不存在 + 无法定位 | FAIL | FAIL（V2-E6c） |
| 跨文档错配 | FAIL | FAIL（V2-E5 / E6，永不纠正） |

理由：该纪律的目的是「不让引用指向文本并不存在的位置」。纠正到**已验证的真实位置**
完全满足这一目的，同时把 92 条可核验证据从丢弃中救回来。
