## 1. 问题

在途询价散在各个项目的询价区里，要逐个项目点开才知道谁没回、谁该催、哪张催单卡在等批。首页「供应商未回复」查的是早已不用的 `pending / contacted` 状态，列出来的不准；它的按钮指向一个每次都跑一次模型、结果没人用的旧接口（W-1 已经删掉它在页面上的调用方）。

## 2. 做了什么

- **`/bids/rfq` 询价追踪页**：顶部计数（需要我处理 · 等回复 · 已报价 · 未响应），默认「需要我处理」（催单卡待批、回信没报价、报价缺字段、过了回复截止还没回）；按项目 → 轮次分组；每家一行写明状态、发出日期、已催几次、**系统下一步**（下次自动催哪天 / 哪天标未响应 / 催单卡待批及不批时哪天标未响应 / 手工联系不会自动催）、缺哪些字段、回复截止。
- **价格**：已报价的行显示原币种单价 / 总价、交期、有效期，以及**比价矩阵**给出的落地价（CAD）与「最便宜」；换算不出写矩阵给的原因并给「去比价」；没算矩阵的轮次（超过 50 轮上限）写「请到比价面板查看」。不另算汇率、不另排序。
- **原地操作**：待批催单卡用 W-1 的审批面板「批准并发送 / 驳回」；一轮 ≥ 2 张时「全部批准」逐张调用既有接口；等回复且没有待批卡的「现在就催」（起草审批卡，原地出现审批面板）；「打开项目」。
- **`/bids` 汇总卡**：只有计数，不出现金额。
- **首页建议**：「供应商未回复」改为只算招投标项目里已发出、超过负责人催单天数的，按钮「去询价追踪」（按项目定位，默认停在第一个有内容的页签）。顺手：销售「发送跟进邮件」按钮原来什么都不做，现在到客户页。
- **下线** `POST /api/projects/[id]/inquiries/batch-followup`（410）。
- **系统下一步与判定一致**：只读 `chase-pure` 导出的函数反推，测试对每种情况在那一刻与早 1 毫秒各跑一次 `decideChases`。催单间隔与扫描同一来源：把 `runForItems` 里算间隔的三行抽成 `chaseDaysForRound`（跟进授权生效的轮次用定格天数）。

## 5. 独立审查

开 PR 前请了一个不带结论的独立审查（只给分支、四件套与任务书；它在自己的工作区里跑测试、用真实路由验证、对一致性做了 20 万例随机检查、做了 28 处变异）。处理：

| 编号 | 发现 | 处理 |
|---|---|---|
| H1 | 追踪接口按「组织成员可见」筛项目：普通组织成员能看到所有招投标项目的报价，而项目里的询价与比价接口用的是项目读权限 | 修。改为与 `requireProjectReadAccess` 同一规则（平台超管 / 负责人 / 该组织 org_admin / 项目成员）；隔离库测试覆盖三种成员 |
| M1 | 有待批卡时只写「催单卡待批」，但扫描先判未响应、待批卡挡不住，到截止会照样标未响应 | 修。待批卡也写出不批时哪天标未响应；一致性表加一例 |
| M2 | 先按更新时间截 200 个项目再看有没有在途询价，老项目里的在途询价会被挤掉 | 修。先筛有在途询价的项目再截 |

## 7. 已知限制

- **接口没有工作区门禁**：任何登录者都能调追踪接口，但只能看到自己有项目读权限的项目（与项目里的询价明细一致）。
- **扫描停了没有提示**：催单扫描挂在收信之后，收信失败时不跑，过期的日期会一直写「今天」。
- **跟进授权生效的轮次**：追踪页用定格天数（与扫描一致）；首页建议按负责人的催单天数。
- **「未响应」只显示近 14 天**。
- **读取较重**：可见项目的在途条目、待批卡、最多 50 轮比价矩阵、审批信息（并发 5）。
