## 1. 问题

报价表助手的「我方成本」只能手填。比价矩阵已经按贸易条款算出每家供应商到加拿大的落地价（CAD），但人只能自己抄过去，看不出抄的是哪一家、哪一轮、含不含运费关税。比价矩阵的结论还写着「到目的地含税」，实际含的是关税，不含 GST/HST。

## 2. 做了什么

**报价表助手卡片（开关开启时）**

- 多一行「来自比价矩阵」：最近一轮有人工「选定」的询价里（已取消的轮次不算），选定的那一家的落地价——供应商、第几轮、数量口径、逐项（货值 / 内陆 / 海运 / 保险 / 关税 / 清关）、换算依据（汇率及其日期与来源、运费口径、关税率），并写明**不含 GST/HST（进口 GST/HST 可抵扣，不计入成本）**；DDP 报价写「是否已含 GST/HST 以供应商报价为准」。
- 按钮「用这个作为我方成本」**只把数字填进输入框**，点「保存并重算」才生效；手填随时可以覆盖。读取永远不改已保存的成本。
- 保存时，服务端按当前登录者有权访问的项目与组织重新取选定的那一条、重新换算；保存的成本与落地价**到分相同**才记「来自比价矩阵」（轮次、条目、当时的落地价、数量口径、时间），否则记手填；成本数字没变时保留原来的来源。请求里只认条目 id，不认金额、轮次、组织。来源存在既有的 `pricingInputs` JSON 里（零 schema）。
- 已保存的成本来自比价矩阵、而矩阵现在换了一家或落地价变了：一句提示「比价矩阵现在是 B 第 N 轮 Y CAD；已保存的我方成本 X CAD 是按 A 第 M 轮的落地价记的，没有自动更新」。
- 毛利列与目标毛利写作「毛利率（按售价）」，旁边显示等价的成本加成（m ÷ (1 − m)，只是换算显示，计算不变）。
- 没有选定：说去询价区选定一家；换算不出（缺汇率、贸易条款、关税率）：写原因，不给数字、没有按钮；之后还有已发出、未选定的轮次：写出来；取数出错：只这一行说暂不可用，卡片其余照常。

**比价矩阵与 Muse（不跟开关）**

- 落地价换算多返回逐项金额；逐项各自到分，舍入差记到最大的一项费用上，之和正好等于落地总价。总价、排序、推荐、最低价不变。
- 结论与 Muse 比价理由里「到目的地含税」改为「到目的地，含关税，不含 GST/HST；DDP 以供应商报价为准」（Q5）。Muse 的数字、字段、`price_scenario` 的取法都不变（决定 A）。

## 7. 已知限制

- **首档数量 ≠ 招标总量**：建议的落地总价按询价单首档数量（或供应商总价），不换算到招标总量（Q4），口径写在卡片上。
- **组织设置缺参数时没有数字**：汇率、运费估算、关税率没填的组织，开了开关多半先看到「换算不出」。
- **备忘录、标书草稿不知道来源**：它们照旧只读成本数字。
- **「到分」核对**：人点按钮和点保存之间矩阵参数被改，会记成手填（成本数字没变时保留原来的来源）。
- **报价表助手读取多一串查询**（开关开着时）：选定条目一次 + 比价矩阵取数。

## 8. 没做的

- 成本加成作为另一种计算口径；投标工作区成本核算表（TI-2）与询价报价逐行对接。
- 用推荐或最低价代替选定；自动覆盖已保存的成本；把来源写进备忘录或标书草稿。
- 改谁能看到成本与毛利（现在项目读者都能看到，Q3 另定）。
