# FIX-24 报告：供应商的附件文件名与证据不能在报价备注里冒充回读字段

> **白话说明（合并后谁会发现什么变了）**：
> - **界面上**：普通的回信，报价备注一个字都不变。只有供应商在附件文件名里写了「；」、换行，或在报价证据里写了 `"）` 的回信，备注附件一栏里的「；」会显示成「;」、换行会显示成空格。
> - **比价、Muse 比价 / 定价情景、报价表助手的成本线、询价追踪页、自动追问**：以后都不会再被文件名或证据里写的「贸易条款=DDP」「缺：币种」「强制项满足」这类文字带偏。
> - **币种**：模型读出来的币种不是三个英文字母时（如「(((」），以前整封回信记「解析失败，请手工录入」，现在照常入表、按「缺币种」处理。
> - **合并后要做一件事**：有生产只读权限的人跑一次只读核查（第 9 节），这是三个询价自动化开关打开前的前提 ⑤。

## 3. 需要你知道的取舍

- **库里已有的伪造整行仍生效（L07）**：读取侧没有按「时间晚于现在」丢段（GATE 2 未采纳 C）。V5 那种行要靠 Gmail 原样交出文件名里的换行（未核实）。部署之后不会再写出新的；已有的由第 9 节 A 段列出，A 段为 0 行或已处理是开关前提 ⑤。
- **按写入顺序、不重复的成对注入仍生效（P1、P3、P4）**：只可能存在于本次改动之前写进库的数据里。改动之后证据里的「"）」都写成「")」，不会再产生。价格 / 交期 / 有效期证据里的由 C 段从审计列出；贸易条款 / 强制项证据里的（P4）不进审计，查不出。
- **R3 误伤（L13）**：证据里本来就合法带「"）」的旧段整段不认，比价会显示「贸易条款未注明」，追问退回更早一段。B 段会列出。
- **R5 误伤**：人手改过、改乱了顺序或复制出重复字段的自动行，以后整段不认（L17 就是一例）。系统从不这样写，B 段会列出。
- **显示变化**：文件名里的「；」显示成「;」、「"）」显示成「")」、换行显示成空格；审计里是原样。证据里控制字符（含 NUL、NEL）一律变空格后再归一——以前 NUL 由 FIX-14 换成空格、但不与旁边的空白合并，现在合并成一个；FIX-14 的测试照过（81 项）。
- **零宽与双向控制字符（Unicode Cf 类）不处理**：它们不参与切分（实测不生效），但仍可能让人在界面上看错文件名。
- **币种更严**：模型输出带符号的币种（`US$`、`CA$`）以前也作废，现在同样作废；三个字母的写法照旧按原文核对。
