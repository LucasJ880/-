# FIX-24 报告：供应商的附件文件名与证据不能在报价备注里冒充回读字段

> **白话说明（合并后谁会发现什么变了）**：
> - 普通的供应商回信，合并后报价备注、比价和追问都和以前一样，看不出变化。
> - 供应商在附件文件名或回信原文里夹带「贸易条款=DDP」「缺：币种」这类字样，以后改不了比价里的贸易条款、起订量和强制项，也不会再让系统去追问。备注里这类文件名中的「；」显示成「;」、换行显示成空格。

> - 合并后跑一次只读核查，把名单列出来交项目负责人。这也是三个询价自动化开关打开前的前提。

## 3. 需要你知道的取舍

- **库里已有的伪造整行仍生效（L07）**：
  - 读取侧没有按「时间晚于现在」丢段（GATE 2 未采纳 C）。V5 那种行要靠 Gmail 原样交出文件名里的换行（未核实）。
  - 部署之后不会再写出新的；已有的由第 9 节 A 段列出。
- **按写入顺序、不重复的成对注入仍生效（P1、P3、P4）**：只可能存在于本次改动之前写进库的数据里。价格 / 交期 / 有效期证据里的由 C 段从审计列出；贸易条款 / 强制项证据里的（P4）不进审计，查不出。
- **整段不认的后果**（误伤与真注入一样）：
  - 这家有更早一封有效回信时，比价**悄悄改用更早那封的贸易条款、起订量与强制项答复**，界面上没有提示（后续 6）。
  - 只剩这一段时：比价显示「贸易条款未注明」、强制项按未答计；追踪页「缺什么」为空、「系统下一步」为空，不会追问。
- **R3 收窄后仍误伤的极少数**：证据里或旧文件名里合法写成「"）；…」的旧段。B 段会列出，标「不再采信」。
- **R5 误伤人手改乱的行**：人手改过、改乱了字段顺序或复制出重复字段的自动行，以后整段不认（L17 就是一例）。B 段会列出。
- **人手追加在附件一栏之后的字段，以后被悄悄忽略**（R2）。系统从不这样写。
- **以回车结尾的旧自动行（L10）**：以前整段丢掉，现在能读出，这是改善。这一段的值会开始参与比价与追问。
- **显示变化**：
  - 文件名里的「；」显示成「;」、「"）」显示成「")」、「（证据：」显示成「（证据:」、换行显示成空格；审计里是原样。
  - 证据里控制字符（含 NUL、NEL）一律变空格后再归一。以前 NUL 由 FIX-14 换成空格、但不与旁边的空白合并，现在合并成一个；FIX-14 的测试照过（81 项）。
- **币种**：模型输出带符号或长度不对的币种（`US$`、`US`、`USDT`）作废、按缺币种追问。作废或没写币种时，询价表与比价先按默认的 CAD 显示和计算，USD 报价会被算低（现状，后续 5）。
- **零宽与双向控制字符（Unicode Cf 类）不处理**：它们不参与切分（实测不生效），但仍可能让人在界面上看错文件名。
- **只读核查 A 段可能列出真实行**：写库成功、但「已入表」审计写失败时，只落下一条「失败」审计（`inbound-sync.ts:239-247`、`:262-269`）。这种行原因写「审计记的是失败」，修完也不会消失，要按前提 ⑤ 逐行确认。
