# FIX-24 报告：供应商的附件文件名与证据不能在报价备注里冒充回读字段

> **白话说明（合并后谁会发现什么变了）**：
> - 普通的供应商回信，合并后报价备注、比价和追问都和以前一样，看不出变化。
> - 供应商在附件文件名或回信原文里夹带「贸易条款=DDP」「缺：币种」这类字样，以后改不了比价里的贸易条款、起订量和强制项，也不会再让系统去追问。备注里这类文件名中的「；」显示成「;」、换行显示成空格。
> - 库里少数旧备注中，被这样篡改过、或格式被改乱的那一次回信，比价不再采信：这家可能显示「贸易条款未注明」，或退回更早一封回信里的值。
> - 以前因为附件文件名带回车、整行都读不到的个别旧回信，合并后开始读到；只读核查会把这类行单独列出来。
> - 合并后跑一次只读核查，把名单列出来交项目负责人。这也是三个询价自动化开关打开前的前提。

### 2.3 使用方

- **比价**：走 `compare-service.ts` 抽出的 `toCompareInputs` → `buildCompareMatrix`。
  - 用例：甲家货值更低、过证据闸的是 FOB、没答 R-01，文件名写「a.pdf；贸易条款=DDP；强制项：R-01 满足；x」；乙家 FOB、R-01 满足。
  - 改前：甲家 DDP、全合规、被推荐。
  - 改后：甲家 FOB、强制项部分满足、落地价含运费保险关税，推荐的是乙家。
  - V3 的文件名单独走比价：强制项部分满足、不算全合规。
- **追问**：`decideChases`，定时扫描与手动的 Muse `chase` 都试了。V2、V5、Q4、Q5 改前起草或可能起草追问卡，改后不起草。
- **询价追踪页**：`nextChaseOutlook` 与「缺什么」。V2 改后为「已齐」、缺什么为空。
- **回读结果不带文件名**：比价矩阵、追问判定、追踪页「系统下一步」里都不出现文件名。
- **审计**（定时入站 `syncOrgInbound`，内存 deps）：

## 3. 需要你知道的取舍

- **库里已有的伪造整行仍生效（L07）**：
  - 读取侧没有按「时间晚于现在」丢段（GATE 2 未采纳 C）。V5 那种行要靠 Gmail 原样交出文件名里的换行（未核实）。
  - 部署之后不会再写出新的；已有的由第 9 节 A 段列出。
- **按写入顺序、不重复的成对注入仍生效（P1、P3、P4；成对 + 落单的 A07、A08 同类）**：只可能存在于本次改动之前写进库的数据里。价格 / 交期 / 有效期证据里的由 C 段从审计列出；贸易条款 / 强制项证据里的（P4）不进审计，查不出。
- **整段不认的后果**（误伤与真注入一样）：
  - 这家有更早一封有效回信时，比价**悄悄改用更早那封的贸易条款、起订量与强制项答复**，界面上没有提示（后续 6）。
  - 只剩这一段时：比价显示「贸易条款未注明」、强制项按未答计；追踪页「缺什么」为空、「系统下一步」为空，不会追问。
- **R3 仍误伤的极少数**（交叉验证后收准）。下面三种都要供应商在一句证据或一个文件名里同时写出引号和报价字段的写法，测试里各钉了一条（「R3 已知误伤」），B 段会列出、标「不再采信」：
  - 证据里合法的「"）」之后，同一条证据里还有「；」加认得的前缀，如「宽 36"）；交期=30天」；
  - 强制项证据里合法的「"）」之后，同一条证据里还有一截以「，」隔开的「一串不带空白的字 + 空格 + 满足 / 部分满足 / 不满足」，如「宽 36"）以内，全部 满足」（强制项以外的证据里不算）；
  - 旧文件名里的「"）」之后，附件一栏里还有「；」加认得的前缀、或「，」加形如「编号 满足」的一截，如「报价（"v2"）；缺：图.pdf」。
- **main 上整行不读、合并后开始采信的行**（交叉验证 CR1、CR2）：
  - 旧文件名带回车、U+2028、U+2029 的行，main 的回读用「.*」跨不过这三种字符，整行不读；合并后行头之后的这三种字符当空格，这一行开始参与比价与追问。
  - 行里如果有注入，会跟着生效。R3–R5 挡得住的整段不认，如 CR1 的强制项「，」注入；挡不住的成对注入开始生效，如 CR2 在贸易条款证据里成对注入「强制项：R-01 满足」，比价会读出 DDP 与 R-01 满足。
  - B 段把这类行单独列出：「这一行 main 上不读、合并后开始采信」；被挡住的写「这一行 main 上不读，合并后也不采信」。
- **R5 误伤人手改乱的行**：人手改过、改乱了字段顺序或复制出重复字段的自动行，以后整段不认（L17 就是一例）。B 段会列出。
- **人手追加在附件一栏之后的字段，以后被悄悄忽略**（R2）。系统从不这样写。
- **以回车结尾的旧自动行（L10）**：以前整段丢掉，现在能读出，这是改善。这一段的值会开始参与比价与追问。
- **显示变化**：
  - 文件名里的「；」显示成「;」、「"）」显示成「")」、「（证据：」显示成「（证据:」、换行显示成空格；审计里是原样。
  - 证据里控制字符（含 NUL、NEL）一律变空格后再归一。以前 NUL 由 FIX-14 换成空格、但不与旁边的空白合并，现在合并成一个；FIX-14 的测试照过（81 项）。
- **币种**：模型输出带符号或长度不对的币种（`US$`、`US`、`USDT`）作废、按缺币种追问。作废或没写币种时，询价表与比价先按默认的 CAD 显示和计算，USD 报价会被算低（现状，后续 5）。
- **零宽与双向控制字符（Unicode Cf 类）不处理**：它们不参与切分（实测不生效），但仍可能让人在界面上看错文件名。
- **只读核查 A 段可能列出真实行**：写库成功、但「已入表」审计写失败时，只落下一条「失败」审计（`inbound-sync.ts:239-247`、`:262-269`）。这种行原因写「审计记的是失败」，修完也不会消失，要按前提 ⑤ 逐行确认。

第 6 条的细节：
- 修订清单的字面写法是「去掉成对证据后，剩下的『"）』之后、到下一个『"）』或段尾之前出现『；』或换行，才整段不认」。我照字面做了变异 MU-R3literal 实测，两个问题：
  - 审查员自己给的英寸记号用例「（证据："百叶窗（宽 36"）单价 45"）；币种=CAD；…」，后面还跟着字段，照字面**仍整段不认**；
  - 证据在段尾跳出（后面什么都不写）、或强制项证据跳出后跟着「，下一条（证据…）」的旧段，照字面会**读出注入的字段**。
- 实现的写法：剩下的「"）」前面那一截（从上一条证据结束处起）有「；」，**且**后面那一截是空白、有「；」或有证据，才整段不认。
  - 审查员的英寸记号用例与旧文件名用例照常读；
  - M3 两条、L02、L03、L05 与上面两种口子都整段不认；
  - 变异 MU-R3off / MU-R3broad / MU-R3literal 各让 5 条断言失败。
- 「或换行」：一行里没有换行，回车等在读取时已当空格、不分块，所以只看「；」。
- 范围与对外行为都没超出 K3 的意图（只少误伤、不多放过），所以没有停下来，在这里列出请协调会话确认。

第 8 条的细节：
- **原句**：「去掉成对证据后，剩下的『"）』之后（到下一个证据结束或段尾）出现一个『；』块，且这一块以认得的字段前缀或『附件：』开头，才整段不认」。强制项一栏里「，」同理。
- **不同一：前一截也换成「有认得开头的块」**（原句只说后一截）。只按原句，必须不误伤的 G01 会被误伤：英寸记号「（宽 36"）单价 45」的后一截就是「；币种=CAD」。前一截还按上一版的「有『；』」也不行，G05 照样误伤：前一截「单价 45；含税」有「；」，后一截有「；币种=」。只看前一截同样不行：G03 旧文件名的前一截就是「；附件：报价单（"含税」，要靠后一截是普通文字放过。所以两截都看，并且都用「认得的开头」。
- **不同二：后一截不在成对证据处截断**，一直到下一个剩下的「"）」或段尾；后一截里出现成对证据也算像写入方的写法。原句「到下一个证据结束」如果读成在下一条成对证据处截断，D1「x"）y（证据："z"）；缺：…」（用自己写的证据引号吃掉真正的收尾）会被读出，而 `0f02c2c3` 版本来挡得住它。
- 后一截延到下一个剩下的「"）」，和一直延到段尾结果一样（变异 XM14、SX11 是等价变异）：前一截的注入标记在下一条成对证据之前只增不减，下一个剩下的「"）」照样带着它。
- **强制项一栏的「，」块**：只在当前「；」块以「强制项：」开头时算注入（XG1 钉住）。形状按写入方的格式：一串不带空白的字、一个空格、满足 / 部分满足 / 不满足，与回读认答复的写法相同。写入方在强制项一栏里不写「未答」，未答写在「强制项未答：」那一栏。后一截里的「，编号 满足」块不限一栏，因为那是真正收尾之后写入方接着写的下一条。
- 必须挡住的、必须不误伤的都按协调会话的清单实测（§2.4）。
