# 青砚 UI/UX 更新：Phase 3 项目详情样板页

日期：2026-08-06  
范围：项目详情的决策摘要与青砚上下文面板；保留所有现有项目功能、权限、API、路由和审批机制。

## 本次交付

项目详情首屏新增“项目决策摘要”，能够直接回答：

- 当前处于什么阶段；
- 哪些基础信息或工作尚未完成；
- 当前主要风险；
- 最近发生了什么变化；
- 推荐下一步是什么；
- 有多少 AI 动作等待人工确认。

项目页面同时接入 Phase 2 的 Shell 上下文：顶部显示当前项目名称、阶段和待确认数量；用户打开“青砚上下文”后，右侧展示阶段、任务完成度、风险、缺失项、最近业务变化、推荐下一步及该项目的 Pending Action 摘要。

## 数据与安全边界

- 阶段来自既有 `getProjectStage`，项目状态、文件、组织、日期、情报和任务进度继续使用既有接口数据。
- Pending Action 复用 `GET /api/ai/pending-actions?status=pending`，只展示既有权限体系已经允许当前用户看到、且 `projectId` 与当前项目一致的未过期动作。
- 右栏不新增批准或执行接口。需要处理时进入既有项目 AI 工作区，继续使用原来的人工确认机制。
- 普通业务用户的项目动态过滤 `Runtime`、`Tool Call`、Prompt、Agent、Environment 等技术活动；平台管理员仍保留完整诊断可见性。
- AI 风险和建议仅作为提醒，不会写回项目阶段，也不会代替人工决定。

## 下一步推导规则

当前推荐动作按业务依赖顺序推导：项目归属 → 项目文件 → 项目解读 → 待确认动作 → 供应商询价/报价 → AI 项目建议。该规则只控制页面提示与跳转，不执行任何业务写操作。

## 响应式行为

- `>=1280px`：右侧项目上下文与主工作区并列。
- `768–1279px`：上下文使用 Drawer，点击处理动作后自动关闭并进入对应项目区域。
- `<768px`：桌面右栏不显示；首屏“项目决策摘要”仍保留，保证手机端能看到阶段、风险、最近变化和下一步。

## 保留的现有结构

本轮没有强制拆分现有四个项目 Tab，也没有移动或删除询价、报价、文件、技术标、讨论、活动、成员和通知组件。Phase 3 先建立稳定的决策首屏和上下文入口；后续若要扩展为“概览、要求、文件、询价、报价、技术标、讨论、活动记录”八区，应另做一个只改变导航归属的可回滚提交。
