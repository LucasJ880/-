## 1. 做了什么

| 以前 | 开关开着时 | 开关关着时 |
|---|---|---|
| 「标书与报价」页签九块从上往下堆 | 「更多」（版本历史，只给看得到金额的人）→「下一步」→ ① 找供应商、询价 → ② 定报价 → ③ 出文件；每步可折叠、标题一句状态 | 与改版前完全相同（页签直接渲染改版前的 `BidTab`） |
| 没有页内「下一步」 | 确定性查表（不调模型），每条一个只导航的按钮 | 无 |
| — | 新接口 `GET /api/projects/{id}/bid-page-summary` | 先做项目读权限检查，然后 404 |

金额（附录 C 决定 C）：汇总接口的金额门 = 报价内部成本权限（`resolveQuoteCapabilities`，与 `requireQuoteAccess` 同一判定）∧ 财务查看权（`resolveFinancePrivilege(...).canReadAll`），与报价引擎开关无关；我方报价金额另要引擎开通。看得到金额的：负责人、超级管理员、`ORG` 范围持 `project.finance.manage` / `read` 的人；看不到的：项目只读 / 测试 / 操作员 / 项目管理员、不是负责人的组织管理员、只有分派范围 `finance.read` 的招投标岗。带金额的旧组件（询价区、我方报价卡、报价区、投标工作区、「更多」里的版本历史）在新页面上只给看得到金额的人挂，其余人看到一句说明。对任何人都不出成本、毛利、供应商报价。这一门只决定新页面挂不挂组件，不是对旧接口的数据保护（决定 C 留给 CHAIN-2e，见 §6）。

改动的已有文件只有：`src/app/(main)/projects/[id]/page.tsx` 两行（`BidTab` → `BidTabEntry`）、`scripts/test-all.sh` / `scripts/test-ci-unit.sh` 的注册行、`.env.example` 的说明、`docs/QINGYAN_MUSE_BRIDGE_TASKFLOW.md` 新增一节。`bid-tab.tsx` 一个字不动。零 schema，无新增模型调用、出站、队列。

## 2. 与任务书的出入

见 design D3（「下一步」8 条）与 D5（决定 C 的落点），摘要：

1. 「下一步」顺序：「已定」「有未定的报价」挪到找供应商之前；招标分析那条只在没往下走时命中，往下走了顺带一句「招标分析还没批准」。
2. 「有未定的报价」包括「已批准但没选为我方报价」。
3. 「开始做报价」只认「有人报价」；新增「看供应商回复，把报价录入」；有待批的发询价卡（含新一轮）时说「询价已起草，等批准后发出」；询价按每家供应商最近一次发出的那一轮算。
4. 看不到金额的人要做的事顺带「这一步要项目负责人或有财务查看权的同事来做」；等待 0 天写「发出不到 1 天」。
5. 金额门按附录 C 决定 C，不按任务书原文的 `project:cost:read`；看不到金额的人在新页面 ① ② 暂时不能起草询价、编辑报价（临时，BIDPAGE-2 / 3 / 4 / 6 恢复）。
6. 开关关着时每次进页签多一次返回 404 的请求（页面渲染结果不变）。
7. 任务书「运行信息在新页面不显示」：已做到（专业模式只在独立路由，不在页签里）。

## 4. 浏览器抽检

本地起应用（隔离库合成数据，平台超级管理员身份——普通用户被页面准入挡在 `/tasks`，配齐岗位太绕），截图在 `docs/acceptance/bidpage-1/`：

- 开关开：`flag-on-quote-draft.png`（有草稿 → 「检查后定为我方报价」、② 展开、① 状态「2 家已询价，1 家已回」）、`flag-on-requirements.png`（分析待审 → 「先去「招标要求」确认要求」）。
- 交互：带 `#rfq-section` 打开 → ① 展开且询价区在视口里；「更多」里有「版本历史」；收起 ② 后点「下一步」→ ② 展开；点「去「招标要求」」→ 地址变为 `?tab=requirements&from=list`、页签切过去。
- **抽检发现并修了一个问题**：起初切页签用原生 `history.replaceState`，地址变了但页签不切（这个版本的 Next 不把原生 `replaceState` 同步给 `useSearchParams`）；改为 `router.replace`（与项目页自己切页签同一做法），复测通过，并加了源码断言。
