## 1. 做了什么

| 以前 | 开关开着时 | 开关关着时 |
|---|---|---|
| 「标书与报价」页签九块从上往下堆 | 「更多」（版本历史）→「下一步」→ ① 找供应商、询价 → ② 定报价 → ③ 出文件；每步可折叠、标题一句状态 | 与改版前完全相同（页签直接渲染改版前的 `BidTab`） |

金额（附录 C 决定 C）：汇总接口与新页面的金额只给「能看报价内部成本 且 有财务查看权」的人（负责人、超级管理员、`ORG` 范围持 `project.finance.manage` / `read` 的人）；项目只读 / 测试 / 操作员、不是负责人的组织管理员都看不到。带金额的旧组件（询价区、我方报价卡、报价区、投标工作区）在新页面上只给看得到金额的人挂，其余人看到一句说明。对任何人都不出成本、毛利、供应商报价。

改动的已有文件只有：`src/app/(main)/projects/[id]/page.tsx` 两行（`BidTab` → `BidTabEntry`）、`scripts/test-all.sh` / `scripts/test-ci-unit.sh` 的注册行、`.env.example` 的说明、`docs/QINGYAN_MUSE_BRIDGE_TASKFLOW.md` 新增一节。`bid-tab.tsx` 一个字不动。零 schema，无新增模型调用、出站、队列。

## 2. 与任务书的出入

见 design D3 / D5，摘要：

1. 「下一步」顺序：「已定」「有未定的报价」挪到找供应商之前（否则不走询价、直接按自己成本定价的项目永远停在「添加供应商」）。
2. 招标要求那条只在「还没往下走」（没发过询价、没有引擎报价）时命中；往下走了的项目照实际进度，另顺带一句「招标要求还没批准」。
3. 「有未定的报价」包括「已批准但没选为我方报价」（两份以上已批准时不会自动选中）。
4. 「开始做报价」只认「有人报价」；回复了没报价、没人在等时新增一句「把供应商的报价记下来」（去 ①）；有待批询价卡时说「询价已起草，等批准后发出」。
5. 金额门按附录 C 决定 C，不按任务书原文的 `project:cost:read`；看不到金额的人在新页面的 ① ② 里暂时不能起草询价、做报价（带金额的旧组件整块不挂），BIDPAGE-2 / 3 / 4 / 6 换上新区块后恢复。
6. 任务书「运行信息在新页面不显示」：新页面自己不写；② 里旧专业模式的漂移提示由 BIDPAGE-3 收口。
7. 「等供应商回复（已等 0 天）」写成「等供应商回复（发出不到 1 天）」。

## 4. 浏览器抽检

本地起应用（隔离库合成数据，平台超级管理员身份——普通用户被页面准入挡在 `/tasks`，配齐岗位太绕），截图在 `docs/acceptance/bidpage-1/`：

- 开关关：分支与 main 各起一个应用（依次起，内存不够两个同时跑），同一项目「标书与报价」页签区截图**像素完全一致**（差异框为空），页签区 HTML 逐字节相同（23,300 字节）。`flag-off-main.png` / `flag-off-branch.png`。
- 开关开：`flag-on-quote-draft.png`（有草稿 → 「检查后定为我方报价」、② 展开、① 状态「2 家已询价，1 家已回」）、`flag-on-requirements.png`（分析待审 → 「先去「招标要求」确认要求」）。
- 交互：带 `#rfq-section` 打开 → ① 展开且询价区在视口里；「更多」里有「版本历史」；收起 ② 后点「下一步」→ ② 展开；点「去「招标要求」」→ 地址变为 `?tab=requirements&from=list`、页签切过去。
- **抽检发现并修了一个问题**：起初切页签用原生 `history.replaceState`，地址变了但页签不切（这个版本的 Next 不把原生 `replaceState` 同步给 `useSearchParams`）；改为 `router.replace`（与项目页自己切页签同一做法），复测通过，并加了源码断言。
