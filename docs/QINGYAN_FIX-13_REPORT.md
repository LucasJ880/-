## 0. 一句话

以前：PDF 里有一种勾选框（或类似符号），解析时会变成一个数据库存不了的隐形字符，整份文件就存不进去，被标成「文件解析失败」，而且哪里都看不到原因。现在：这个字符存库前换成空格，文件能正常解析；以后再有文件解析失败，分析面板和项目文件列表都会直接写出系统记下的原因（写出的是系统原始的英文报错，给开发看的，不是中文解释），面板上还多一句「下一步怎么办」。（原因是按本地复现推断的：Lucas 本地读出了这个字符，本会话在测试库上复现了存库失败；生产上的原始报错还没人看过，§5 第 0 步就是去把它留下来。）

已经失败的两份附录 B 不会自己恢复，上线后要按 §5 操作一次。**§5 第 0 步很重要：先别打开文件抽屉。**

术语：U+0000 = 一个不可见的「空字符」；「落单代理字符」= 表情符号这类由两个编码单元组成的字符被从中间截断后剩下的半个；「页级解析」= 招标分析用的逐页文字；「整份文字解析」= 项目文件列表用的那条旧路径；「隔离库」= 本机专门跑测试的数据库，和生产无关；`parseStatus` / `parseError` = 系统给每个文件记的解析状态与失败原因；「覆盖清单」= 页面上「上传 N · 纳入分析 M · 排除 K」这一行和它下面的文件列表；「快照」= 分析完成那一刻存下来的那份清单，之后不随文件变化；「需要 OCR」= 这一页抽不出文字，要靠图像识别（本次不做）；「模型密钥」= 调用 AI 模型的账号凭据，本机没有，所以本机跑不了 AI 摘要与分析。

## 1. 原因与复现

- Lucas 本地用 unpdf 1.4.0 读英文版附录 B：第 2 页利益冲突一节的勾选框（SymbolMT 字体，Identity-H 编码，没有 ToUnicode 表）被抽成 U+0000（`"...check the box.\n\u0000 The Bidder declare..."`）；去掉权限加密后的版本同样如此——**与加密无关**。
- PostgreSQL 的文本列不收 U+0000（错误码 22021）；截断把一对代理字符劈开时，Prisma 报 `unexpected end of hex escape`。两条解析路径都是把文字原样写库，于是整份文件写库失败、被标成 `failed`。
- 本会话在隔离库上用现拼的 PDF 复现了这一机理（不入库任何客户文件）：见 §3「改动前」。
- **没核对的**：生产上这两份文件 `parseError` 的原文（§5 第 0 步会把它留下来）；法文版 `-f(PDF).pdf` 没有单独实测，按同一来源推断相同（§5 第 1 步核对）。

## 2. 做了什么

1. **清理函数**（新文件 `src/lib/files/extracted-text.ts`）：U+0000 → 空格（不删，免得左右两个词粘在一起）；落单代理字符 → U+FFFD；其它字符（中文、表情符号、制表、换行）原样不动。
2. **页级解析**（`page-parse.ts`）：PDF 每页先清理再判断「近乎空白 / 需要 OCR」（整页都是 U+0000 的页面清理后是空白，落到「需要 OCR」）；Word / Excel / CSV / 纯文本在切单元之前清理原文、切完把每个单元的文字和标签再清理一遍（按 6000 字切块、取标题前 60 个字都会劈开代理对）；整份文字截断之后再清理。
3. **整份文字解析**（`parse-content.ts`）：先清理、再去首尾空白、截断后再清理一遍；重新解析开始时清掉上一次的失败原因。
4. **纯文本 / CSV 按实际编码读**（多维审查后补，§6）：带 UTF-16 字节序标记的按 UTF-16 读；读出来有 U+0000、且「U+0000 与无法解码的字符」合计超过 10% 的（没有字节序标记的 UTF-16、UTF-32、二进制内容）记为解析失败，原因写「文本文件不是 UTF-8 编码或含二进制内容，无法读取（请另存为 UTF-8 后重新上传）」。原因：这类文件以前是碰巧因为写库失败才被挡住的，清理之后会变成「解析成功、内容是隔一个字一个空格的乱码」并进入分析，比失败更糟。
5. **失败原因的写入收口**：凡是把外部报错文字写进失败原因的地方都经同一个纯函数——不超过 500 字（旧路径有一处原先没有上限），写入前同样清掉不可入库的字符。
6. **覆盖清单带出原因**（`package-coverage.ts`）：被排除文件多一个 `parseError` 字段，只有因解析失败被排除的文件有值。只有分析详情接口带原文；投标简报、工作台汇总两个接口不显示原文，它们拿到的清单里这个字段恒为空。
7. **原因不进模型**：存进综合解读的覆盖快照显式只取原来的六项——综合解读会经投标草稿进模型提示，失败原文（可能含数据库报错与服务端路径）不能跟着进去。
8. **界面三处**（文案集中在不依赖数据库的 `exclusion-text.ts`，界面与测试共用）：
   - 分析面板「上传 N · 纳入分析 M · 排除 K」下面：`〈文件名〉 · 未纳入：文件解析失败（原因：〈原文〉）`；没有记录时写「（原因：系统未记录原因）」。只要有解析失败的文件，清单下面加一句：「解析失败的文件 AI 没有读到。请到右上角「项目文件」里重新处理，再回到这里重新分析；仍然失败请把上面的原因发给管理员。」
   - 分析结果里「排除 K（原因）」展开列表：「文件解析失败」后面按同样的写法带原因，原文取文件当前的记录；文件之后已经不在解析失败之列的，写「文件解析失败（上次分析时的记录，文件状态之后已变，重新分析后更新）」。
   - 项目文件列表：失败的文件在行下方显示「原因：〈全文〉」，不截断、不用悬停（原来只截前 60 个字，Prisma 报错时只剩「Invalid `prisma…` invocation:」）；没有记录时写「原因：系统未记录原因」。注意：抽屉每次打开都会自动重新处理失败的文件，一开始原因就被清掉，再次失败后才重新出现；要稳定地看原因，看分析面板那一处。

### 7.2 本次走查与审查发现、不在本 PR 范围的

1. **文件抽屉的自动处理会循环**（既有行为，读代码确认）：一轮处理结束后页面整体刷新，抽屉重新挂载，重新判断一遍——只要还有文件处于解析失败 / 解析中、AI 摘要失败 / 生成中，就带着「重置」再来一轮；项目里有停在「已解析、摘要待生成」的文件（图片、压缩包、没有文字层的 PDF）时，不带重置也会一直循环。每一轮会给被重置的文件重新生成 AI 摘要；情报分析与两块自动面板在「有比上次情报更新的摘要」时也会重跑。本机 80 秒内 3 轮（本机是没有模型密钥触发的）。**后果**：抽屉开着期间可能反复调用模型，产生费用。FIX-13 之前的两份附录 B 属于「一直解析失败」，会让抽屉一直重试；是否每轮都调用了模型取决于上面的条件，生产上是否发生未核对。尚未登记任务。
2. **两个文件接口只查登录、不查项目权限**（既有问题，读代码确认，**安全问题**）：`POST /api/projects/[id]/files/process-next` 与 `DELETE /api/projects/[id]/files/[fileId]` 只用了「已登录」的检查。任何登录用户只要知道项目 id，就能让别的企业的项目重新处理文件（会调用模型、返回文件名与失败原因），或删除它的文件。同目录下的文件列表与上传接口是查了项目权限的。本次没有改这两个接口；design 里「原文只给有项目读权限的人」对本次新增的显示成立，对 `process-next` 的既有响应不成立。**建议尽快单独修**，尚未登记任务。
3. **`parseError` 里有服务端路径与代码片段**（旧路径把 Prisma 报错连同堆栈第一行写进去；数据库连接类的报错还可能带数据库主机名）：按 Lucas 的要求原样显示给有项目读权限的人。需要 Evan / Lucas 决定：保持现状，或只保留报错正文、去掉路径与代码行。未决定前保持现状。另：报错在 500 字处截断、没有省略号（截图里末尾是「transien」）。
4. **重新解析之后、重新分析之前，面板不提示有文件等着重新分析**：接口其实返回了这句说明（「2 个可分析文件尚未纳入本次分析」），情报页显示了，分析面板没有显示。**后果**：用户可能以为 6 个文件都已分析，直接点「批准分析」。并入「降级结果用白话说清楚」（任务书 T6，尚未登记）。同一句说明在有解析失败时拼出来是「2 个文件文件解析失败」，「文件」重复，一并处理。
5. **「AI 数字员工 · 投标分析」卡片上的「重新分析」没有底色与边框**（样式里引用的颜色名 `primary` 没有定义，生产上应同样如此）：既有问题，未改。
6. **文件抽屉里的绿色提示写「可到「概览」Tab 查看完整报告」**，现在没有这个页签。既有文案，未改。
7. **编码的限制**：没有字节序标记的 UTF-16、GBK 等编码的文本不会被识别——没有标记的 UTF-16、UTF-32 会明确失败并提示另存为 UTF-8（判断靠「有 U+0000 且 U+0000 与无法解码的字符合计超过 10%」，极短的文件或很特殊的内容仍可能漏判）；GBK 这类不含 U+0000 的会照旧被当成 UTF-8 读出乱码（既有行为，本次没有变）。
8. **「需要 OCR」的判断**：一页里只有页眉页脚是正常文字、正文全是 U+0000 时，该页不会被判成「需要 OCR」，正文是空白（design D8）。这类文件以前是整份失败。整份文字解析里，夹在中间的整页 U+0000 会在整份文字中间留下一串空格。
9. **分析任务把页级解析的报错带进任务错误信息**（既有行为，`tender-workforce/tools.ts` 的 `unparsedDocuments`、旧管线的 `ENSURE_PAGES failed: …`）：这条路不经过本次新增的字段，没有改；它会不会进模型提示没有追到底。
10. 不做 OCR、不升级 unpdf、不换解析库（proposal「Out of scope」）。
