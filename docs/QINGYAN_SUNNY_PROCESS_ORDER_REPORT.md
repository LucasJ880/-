## 2. 对照检验（最重要）

**方法**：`scripts/sunny-process-oracle/oracle.py` 用 LibreOffice 直接打开你给的 5 份原件（按 SHA-256 识别），把测试输入写进原件的输入格、整本重算、读出结果，生成夹具；系统引擎对同样的输入逐项比对。金标准来自原件本身重算，而不是我对公式的理解。输入格按原件实际存储类型写入（例如 Vinyl「外框数」下拉的 `4` 是数字、`3+1` 是文本，写错类型原件会静默算成 0）。

| 原件 | SHA-256（前 12 位） | 用例 | 比对项 | 失败 |
|---|---|---|---|---|
| Blinds 工艺单_圆盒侧盖加厚标准版（20241007 新） | `85d45d627762` | 459 窗（3 产品 × 3 操控 × 8 罩盒 × IN/OUT/Tight × 2 + 27 个拉绳分档边界） | 9,488 | **0** |
| Blinds 国内下单表 1 | `32830359e00d` | 12 单 / 322 行 / 305 张标签 | 2,211 | **0** |
| 6cm 窗帘工艺单（**新版**：真实订单 G1024 所在工作簿） | `c10789aba32e` | 40 单 / 410 行 | 11,267（两版合计） | **0** |
| 7cm 窗帘工艺单（旧版原件 + 新版成品高公式补丁） | `acb309364313` | 40 单 / 366 行 | （同上） | **0** |
| Vinyl shutters 工艺单 AIV1 | `70fc3cdb5c95` | 40 单 / 758 窗 / 3,937 行下料 / 2,674 张标签 | 89,401 | **0** |

| **合计** | | | **112,531** | **0** |

**窗帘金标准换版（第二轮）**：你给的两张真实订单用的是新版窗帘模板（2026-10-26），与旧版 6cm 原件逐格比对只差成品高 F 列：旧版"英寸扣减后 ×2.54 向下取整"，新版"×2.54 后减厘米（顶装 6；方单轨/圆单轨 8；圆双轨 9；方双轨 6）再四舍五入"。按拍板 6cm / 7cm 都用新版：6cm 直接以 G1024 工作簿为金标准（清空输入后填测试数据）；7cm 在旧版原件里写入新版 F 列公式后重算。"成品帘子高 = 成品高 − 2cm"同样写进两本原件的 I 列再重算。这些补丁逐条记录在夹具 `source.patches`，`oracle.py` 的 `PATCHES` 可重放。变异检验：去掉 −2、把圆双轨扣减改成 8、把四舍五入改成向下取整，测试分别失败 1,432 / 252 / 6 项。

**真实订单回归**：用订单里销售填写的值重算，与工厂收到的单逐值比——G0927 的厘米、平方、8 张标签全一致；G1024 / G1025 的测量宽、成品高、韩褶上端宽、成品帘子宽、颗数、走珠扣、杆子 / 走珠布袋 / 安装码 / 韩褶走珠全一致；G1025 的成品帘子高（268 → 266，正是你说的那张）和布料平方也一致。G1024 是拍板前的单，成品帘子高没减 2（245），按偏离 X-6 跳过并打印。

Vinyl 用例覆盖 2.5"/3.5"、6 种受支持外框组合 + 4 种不受支持组合、无框、1–9 扇、25 种开合编码、T柱/挂柱、单/双中分档（含错误的第二档）、全部 19 种切分；每单一次填满 1–30 窗，所以下料总表的跨窗合并与排序也一起比对了。原件出 `#N/A` 的位置，系统同样标为错误（不是凑出一个数）。

**修正前的旧引擎**跑同一份 Blinds 夹具：裁切尺寸全对，但 **拉绳分档 71/459 错**（阈值与原件不一致、"1.0 & 0.7" 显示成 "1 & 0.7"），**斑马帘裁剪位 124/144 错**（旧引擎只支持 3:2 布纱比）。

## 3. 原件缺陷与系统偏离

### 3.1 原件 Blinds 工艺组装：52 个窗位里有 10 个与第 1 窗位模板不一致

两种方法交叉证实，证据在 `src/lib/sunny-process/__tests__/fixtures/blinds-slot-defects.json`：一是每个窗位填不同的探针输入、与"只填第 1 窗位"的结果比；二是公式按块内相对行号归一化后逐格比。

| 窗位 | 原件问题 | 后果（数值实证） |
|---|---|---|
| #22 | 测量方式取了第 29 行（别的窗）的值 | 两窗测量方式不同时，**罩盒 / 38管 / 下杆 / 圆芯杆 / 面料宽 / 插片全差 3/16"**（例：43 → 43 3/16） |
| #15 | 布纱比取了第 26 行（别的窗）的值 | 斑马帘裁剪位错（例：0.55 → 3.675） |
| #45 | 裁剪位引用了错位的纵向Ref 块 | 斑马帘裁剪位恒为 0 |
| #4、#31、#34、#43、#49 | 拉绳分档公式少了 ≤0.6 档 | 矮窗（高 ≤ ~29.5"）分档给成 "0.8 & 0.5"，应为 "0.6 & 0.3" |
| #5、#8 | 斑马帘 / 香格里拉数量公式被改写 | 裁剪数量与模板不同 |

**系统一律按第 1 窗位模板计算，不继承上述缺陷。** 如果工厂目前直接用这份 Excel 填到这些窗位，建议抽查近期订单。

### 4.1 发给国内 / 退回自产

- 「发给国内」把自产行按当前字段原样带到国内下单表：IN/OUT → 内装/外装（Tight 写进备注），电动 → 电机，L/R → 左/右，罩盒、货号、安装、备注原样。斑马帘布纱比不带过去（国内下单表没有这一列）。
- 「退回自产」只对国内下单表里的卷帘 / 斑马帘 / 香格里拉；罩盒不在减尺表里时取默认并提示，斑马帘重新查布纱比对照表。
- 服务端一个事务完成（与保存工艺参数同一把锁 + 版本号校验）：重建自产行、追加一版工艺参数；跟着被挪行的提示一起移走，其余提示按新行号重排。非草稿 / 版本过期返回 409。

### 4.2 斑马帘布纱比对照表

- 存在组织设置里，**只影响之后生成或退回自产的行**，已生成的工艺单不回写。
- 匹配：大小写不敏感，空格 / 下划线 / 斜杠当作连字符；完全相同优先，否则编码作为完整的一段出现在 SKU 里就算命中（`AQUAWIDE3` 命中 `AQUAWIDE3-GRAY-LF`，`BL201` 命中 `LOUIA-WHITE-LF-BL201`），多条命中取最长的。不做模糊匹配（`F1091` 不会误中 `F10912`）。
- 种子 = 原件 Sheet1 W2–W29 的 24 条（括号里的国内编码并入同一条）。**注意**：这些是工厂面料号，报价目录的斑马帘 SKU（AQUAWIDE3、Bagoda、FARO… 共 31 个系列）一个都对不上，所以在工厂把报价 SKU / 系列名补进表之前，斑马帘仍会默认 3:2 并提示。
