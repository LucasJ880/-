## 0. 现在能说的和还不能说的

**能说的**（青砚与开源两方已核对）：

1. 青砚的问题不在某一步做得差，而在**步与步之间没连上**。读标书和询价各自很深；要求确认之后，页面不再告诉用户该做什么，定价、提交靠人手推进（基线 G1、G2、G7、G10）。
2. 青砚已经有一张确定性的「下一步」查表（10 条规则），但只接在已冻结的 Muse 通道上，Web 用不到（G1）。把它搬上 Web 是改动最小、体感最大的一步。
3. 开源项目里**没有一个**覆盖「读标书 → 询价 → 比价 → 定价」，这条链青砚领先；开源强在写标书和交付前检查，正好是青砚薄的地方（开源调研 §1）。

**还不能说的**（等 ChatGPT 一方）：

- 同事觉得「顺」的到底是哪几步。可能是读得深、可能是能边问边改、可能是查资料、也可能只是不用在五个页签之间找入口。**这决定方案的优先级，现在不猜。**
- 青砚读标书的质量与 ChatGPT 比谁强。仓库里唯一的旁证是 2026-08 的一次对照：ChatGPT 深读发现了青砚漏掉的现任供应商与评分标准，之后青砚补了这两类抽取。需要同一份标书实测（§2 第 4 轮）。

## 1. 目标、范围、不做什么

**目标**：一个标从进系统到提交，用户在任何时刻打开项目页都知道「现在卡在哪、下一步点哪里」，并且每一步的产出自动成为下一步的输入。

**范围**：招投标类目的主流程（S0 发现 → S10 复盘，坐标见基线 §2）。

**Out of scope**

- 分析引擎 V2 上生产。它有自己的发布闸门（评测指标），不并入本线；本线只需要知道生产跑的是哪一代（§9 第 3 条）。
- Muse / 任何机器人、插件、Connector 接入（TASKFLOW 已决定第 10 条，永久冻结）。
- 自动向招标平台提交投标。
- 销售、安装、外贸等其它类目。
- 开源调研 §4「明确不借」的五项。

## 2. 方法：三方对比怎么做

### 2.1 统一坐标

三方都按 S0–S10 这 11 段对齐。每一段、每一方记同样的七项：

| 项 | 含义 |
|---|---|
| 触发 | 这一步由什么启动（人点、定时、上一步完成） |
| 输入 | 用到什么（文件、上一步产物、人补充的信息） |
| 做法 | 确定性规则，还是模型；模型的话有没有证据约束 |
| 产物 | 输出什么，什么格式，带不带出处 |
| 人工闸门 | 哪里必须人确认；确认之后放行什么 |
| 传递 | 产物是否自动进入下一步 |
| 失败时 | 缺信息、出错时怎么表现（停下说明 / 用默认值 / 编造） |

### 2.2 证据规则

- 青砚：只认代码与已合并的文档，带 `文件:行`，按 A / B / D 标可信度。
- 开源：只认读到的源码；README 自述单独标出。
- ChatGPT：**自述不算证据**。模型总结自己的 workflow 容易写成理想版本。每一段要有原文佐证——固化的指令 / Skill 原文，或一次真实对话的产出片段（§5 模板 C、D 两部分）。只有自述、没有佐证的格子标「自述」。

### 2.3 五轮

| 轮 | 做什么 | 状态 |
|---|---|---|
| 1 | 青砚基线：三路调研分头读代码 → 主会话复核关键结论 → 分歧记更正记录 | 完成（基线 §10：3 条更正） |
| 2 | 开源初筛：搜索 → 读 13 个仓库源码 → 主会话抽查 3 处 | 完成（开源调研 §5） |
| 3 | 收 ChatGPT workflow 摘要 → 按坐标填矩阵（§6）→ 逐格标「有佐证 / 自述」→ 列出「它有青砚没有」「青砚有它没有」「都有但做法不同」 | **等输入** |
| 4 | 同标实测：同一份标书，ChatGPT workflow 与青砚各跑一遍，用 `tender-eval` 现成的评分表打分（强制要求召回、关键事实准确、证据准确、误报）。询价与定价没有金标，改用一个已结束的真实项目对时间线 | 等第 3 轮；需要 Lucas 或同事在 ChatGPT 侧操作（§9 第 4 条） |
| 5 | 独立复核：另起一个只看证据、不看结论的审查，逐格核对矩阵与方案里的每条事实；分歧进更正记录 → 方案定稿 → 拍板 | 等第 4 轮 |

### 2.4 怎么判「该学谁」

不数功能个数。一项做法进入方案要同时过三关：

1. **有人要**：同事点名的具体场景，或实测里青砚明显输的地方。
2. **有证据**：对方确实这么做（不是自述），且在加拿大货物类投标上成立。
3. **能落地**：在八条硬纪律之内；越界的单列为「需例外」，逐条拍板，不默认放行。

## 4. 开源一方（摘要）

详见开源调研。可借三样、已具备三样、明确不借五样：

- **借**：废标项检查（交付前）；补遗取代关系与结论失效；规则 → 模型 → 人的判定阶梯。
- **已具备，不用借**：抽取带原文出处并由代码复核；模型匹配、代码算钱；逐供应商报价状态与比价。
- **不借**：绕反爬采集、登录后采集、批量生成多家投标文件规避串标筛查、「AI 去痕」、确认超时自动提交。

## 5. ChatGPT 一方：要这样问

把下面整段发给同事在用的那个 ChatGPT 对话（或 Project / 自定义 GPT）。目的是让它交回来的东西能直接填进矩阵，并且带得出原文。

回来的内容会提交进仓库，**发之前请去掉毛利率、我方最终报价、项目估值**（与 Muse 通道同一口径），客户与供应商名称可留可不留。

```text
我要把你帮我做投标的整个流程写成一份可以交接的说明。请严格按下面的结构回答，
不要概括成原则，要写你实际做的事。凡是标了【原文】的地方，逐字贴出，不要转述。

A. 阶段清单
按我们实际做一个标的先后顺序，列出所有阶段（从看到招标公告到提交之后）。
每个阶段一行：阶段名 / 一句话说明 / 通常谁发起（我还是你）。

B. 逐阶段说明（每个阶段都按这七项写）
1. 触发：我说了什么或给了什么，这一步才开始
2. 输入：用到哪些文件、链接、上一步的结果、我口头补充的信息
3. 做法：你具体做了哪几步；哪些是查表 / 计算，哪些是你的判断
4. 用到的能力：联网搜索 / 读文件 / 运行代码 / 记忆 / Project 指令 / 自定义 GPT / Skill / 代理模式——用了哪个写哪个
5. 产物：交给我什么（表格 / 清单 / 邮件草稿 / 文档），是否标出处（页码、链接）
6. 需要我决定的点：哪里你会停下来等我确认，我确认之后你接着做什么
7. 出问题时：信息缺失、文件读不全、搜不到的时候，你怎么处理、怎么告诉我

C. 固化下来的东西【原文】
逐字贴出：Project 指令 / 自定义 GPT 指令 / Skill 文件 / 你记住的关于我们公司和
做标习惯的记忆条目 / 我常用的提示词 / 常用的输出模板。没有的写「无」。

D. 一个真实走完的标
选最近一个从头做到提交的标，按时间顺序写：每个阶段我发了什么、你交了什么
（每个阶段贴一段真实产出【原文】，不超过 30 行）、从开始到提交大约几天、
中间返工了几次、为什么返工。

E. 你不做或做不了的
例如：发邮件、盯供应商回信、催单、记录谁批准了什么、跨多个标汇总进度、
保存文件版本、提交到招标平台。逐条写清是「不做」还是「做不了」，现在是谁在用什么补上。

F. 汇总表
最后给一张表，行 = A 里的阶段，列 = 触发 / 输入 / 产物 / 需要我决定的点 / 大约耗时。
```

另外请同事单独回答一句，不经过 ChatGPT：**「哪三个具体时刻让你觉得它比青砚顺？」**（例如「把标书丢进去十分钟就知道投不投」这种粒度）。方案优先级按这三条排。

## 6. 三方对比矩阵

ChatGPT 列已于 2026-11-11 据 `qyane-tender-intelligence` Skill 原文填入（Skill 属于 §2.2 所说的「固化指令原文」，算有佐证；真实对话产出与同事的「三个时刻」仍未收到）。青砚、开源两列是摘要，细节看各自底稿；ChatGPT 一方的逐项差距见 `docs/tender-intelligence-gap-analysis.md`。

| 段 | 青砚 | 开源里最好的做法 | ChatGPT workflow | 初步判断 |
|---|---|---|---|---|
| S0 发现 | 手工建项；外部推入；PROC-1 候选不建项 | 不用模型的加权分拣，三档并留理由（mcp4tender） | 不做自动发现；入口是用户给出招标公告与文件。流程状态从「已发现」起步 | ChatGPT 不比青砚多；缺口仍是 P2-1～3 |
| S1 预筛 | Go / No-Go 只是记录，无下游效力 | 契合表保留「未知」态；有条件投（THINK-school，非开源） | PURSUE / HOLD / DECLINE，只作建议，由 Owner 决定；决定前要看到阻断项、敏感性、缺失事实 | 思路一致。青砚缺的是「决定前的阻断项清单」与决定对下游生效 |
| S2 读标书 | 整包分析，带页码证据；V1 / V2 差距大 | 抽取带原文块 + 代码复核（rag-tender）——青砚已具备 | 全文件清单与哈希；逐行抽价格表（行号、数量、单位、包装数、尺寸），保留页 / 表 / 单元格出处；补遗优先 | **ChatGPT 领先**：青砚没有价格表行项，抽到的数量与单位还被丢弃 |
| S3 合规矩阵 | 人工逐条标注，沉淀为合规记忆 | 规则 → 模型 → 人的判定阶梯（rag-tender） | 逐行对照政府规格与实际品牌、型号、尺寸、包装、认证；状态 MISSING / PENDING / MATCH / CONFLICT；强制认证未核验即阻断 | **ChatGPT 领先**在「按行」与「阻断」；认证核验青砚已有七成 |
| S4 澄清补遗 | 澄清清单可导出；补遗接受不改要求 | 取代关系 + 结论失效（rag-tender） | 最新补遗取代旧规格，并使受影响的匹配与成本假设失效、通知 Owner | **ChatGPT 领先**，与开源结论一致 |
| S5 询价比价 | 起草 → 审批 → 发送 → 回信入表 → 催单 → 落地成本矩阵 | ERPNext 有询价比价但无投标侧；其余没有 | 只出询价草稿与供应商短名单，不发信、不追踪回信；另有青砚没有的一环：文件领取方 → 历史授标 → 进口线索 → 反查厂家 | 发信与追踪**青砚领先**；「反向寻源」是 ChatGPT 独有 |
| S6 定价 | 情景计算；成本线手填 | 代码算成本与毛利（mcp4tender）——青砚更严 | 逐行落地成本：汇率、贸易条款、HS 与原产地、运费方案、进口 GST 与可抵扣、本地配送、预备金；毛利率与加成分开；两套模型对账 | **ChatGPT 领先**：青砚不按行、无税费现金流、无对账 |
| S7 写标书 | 英文草稿 + 中文说明，PDF，无 Word | 评分标准驱动大纲；要求编号贯穿（多个项目） | 保留官方表格原样（Form of Tender、补遗确认、价格表），不改格式 | ChatGPT 强调「按官方价格表原样导出」，青砚没有 |
| S8 审查 | 零散的数字校验 | 废标项检查；要求覆盖与评分覆盖两张表 | 逐行、逐版本、逐来源、逐审批核对；缺强制证书、价格表、授权、交付计划任一项即不得提交 | **ChatGPT 领先**，与开源的「废标项检查」同向 |
| S9 组包提交 | 手工时间戳 + 模型清单 | 都只做到导出文件 | 不自动提交；「已提交」必须有平台回执，否则是「提交结果不明」 | 三方都不自动提交；「回执才算提交」值得采纳 |
| S10 复盘 | 结果 → 授标情报 → 画像 → 盈利分析 | 基本没有 | 收集非官方开标结果与正式授标，对比估算与实际，沉淀供应商情报 | **青砚领先**（授标情报、画像、盈利分析已建） |
