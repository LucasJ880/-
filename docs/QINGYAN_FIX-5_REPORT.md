| 项 | 值 |

## 1. 问题

招投标项目每推进一个阶段，`src/lib/tender/stage-tasks.ts` 本该做两件事：把上一阶段的自动任务标为完成；为新阶段建两三条任务（「[项目解读] 精读招标文件」之类）。第二件事建任务时给每条写了 `sortOrder`，任务表没有这一列，每次都报「Unknown argument `sortOrder`」；调用方不等结果、只打一行日志。所以**这些任务从来没有建出来过**。这个文件没有任何测试。

另外，模板把「准备投标文件」「提交投标」排在「项目提交」阶段——可进入那个阶段就意味着标已经交了。修好之后不调整，每次记下「已提交」都会冒出一条三天后到期的「提交投标」。

## 2. 做了什么

1. **建任务不再写那个不存在的列。** 要建哪些任务抽成一个纯函数 `buildStageTaskRows`，只产出任务表里有的八项。
2. **「准备投标文件」「提交投标」挪到「供应商报价」阶段**的末尾；进入「项目提交」不建任务。进入「项目提交」时，它们随「[供应商报价]」的任务一起被关掉。
3. **到期日**：「提交投标」取项目的截标时间；截标还没到时，别的任务也不晚于截标时间；没有截标时间、或已经过了，一律按天数。
4. **关掉之前所有阶段的自动任务**，不只上一阶段（见 §3.2）。
5. **不重复**：同一项目加锁再「查有没有、没有才建」，同时推进两次也只建一批。
6. **已放弃、已归档的项目不建任务；放弃项目时**在同一个事务里把还没完成的自动任务标为「已取消」（人自己建的任务不动）。改了一个既有文件：`src/app/api/projects/[id]/abandon/route.ts`。

每个阶段建的任务：

| 进入阶段 | 任务 |
|---|---|
| 项目分发 | 分配项目负责人、初步评估项目可行性 |
| 项目解读 | 精读招标文件、确认投标资质要求、编制投标计划 |
| 供应商询价 | 发送供应商询价单、跟进供应商回复 |
| 供应商报价 | 汇总供应商报价、生成项目报价单、报价内部审核、**准备投标文件**、**提交投标**（到期日 = 截标时间） |
| 项目提交 | 不建 |

## 3. 需要你知道的取舍

### 3.1 没有开关，合并即生效；你会突然看到这些任务

之后每一次有人推进阶段，都会给推进的人建 2–5 条任务。这是这些任务本来的设计，只是以前从没生效过。还有两点：

- **项目里所有成员都会收到到期提醒**：任务到期提醒覆盖成员所在项目里的所有任务（「只看我的」默认是关的），所以每条自动任务会给每个成员一条到期提醒（每条任务只提醒一次），也会进每天早上发到自己邮箱的摘要。觉得太吵，可以以后把提醒改成只给负责人，这次没动。
- **实际会建任务的主要是「供应商询价」「供应商报价」两段。** 分发、分析完成、询价发出这三处会绕过阶段推进直接写阶段时间：项目一分发就已经在「项目分发」，所以那一段的模板在生产里用不到；「项目解读」的任务只在分析完成之前就有人推进时才建。

### 3.2 独立审查找到的大问题：只关「上一阶段」会留下永远挂着的任务

原来的规则是「进入新阶段时关掉上一阶段的自动任务」。可「上一阶段」是按项目上的阶段时间算的，而询价发出时会直接写入「供应商询价」的时间。常见的流程——推进到项目解读、建出 3 条任务 → Muse 发出询价（直接写时间）→ 有人推进到供应商报价——上一阶段算出来是「供应商询价」，「[项目解读]」那 3 条没人关，两三天后开始逾期，并一直出现在逾期提醒、每小时的「任务逾期」主动提醒、摘要邮件和 AI 上下文的逾期数里。审查在隔离库里复现了。

改成：进入新阶段时关掉**之前所有阶段**还没完成的自动任务。跳级推进也一并覆盖。剩下的一点：三处直接写阶段时间之后，之前阶段的任务要等下一次有人推进才关。让它们也关 / 建任务，放到「阶段记录自动前进」那个 change 里一起做。

### 3.3 模板调整是我的建议，可以改回去

「准备投标文件」「提交投标」原来在「项目提交」阶段。不挪的话，修好之后每次记下「已提交」都会冒出一条「提交投标」。挪到「供应商报价」之后，它们在交标之前出现，交标时被关掉。不同意可以改回去。

### 3.4 其它

- **顺序**：任务表没有排序列；任务列表按更新时间排、任务页按到期日与优先级分组排。我初稿给创建时间错开 1 毫秒想保住模板顺序，审查指出没有地方按创建时间排，已去掉。
- **截标时间只给了日期的项目**：接入接口把日期存成 UTC 零点，在多伦多看「提交投标」会显示为截标前一天晚上到期，偏早。
- **截标时间已过**仍建「提交投标」（按天数）：截标可能延期，不猜。
- **与接入时按模板建的任务重复**：v1 接入接口在请求带了投标模板时会另外建一组「[投标制作]」「[报价准备]」任务，它们不会被阶段推进关掉。BidToGo 实际带不带，我没有核实。
- **按标题前缀识别自动任务**（既有做法）：人把自动任务改了名就不会被自动关；人自己建一条以「[阶段名]」开头的任务，会被当成自动任务关掉，也会让那个阶段不再建一批。
- **与 #446 的关系**：#446 也改了 `stage-tasks.ts`（加「只关不建」的参数，这里原样带上了同一段）。试合并：只有两个测试注册脚本冲突（两边都保留）；合并后本 change 的两份测试、#446 的两份测试、`web-next-step-db` 都通过。

### 3.5 独立审查的发现与处理

开 PR 前请了一个不带结论的独立审查。第一次因为额度用完中途停了，换模型后重跑了一次完整的。

| 发现 | 处理 |
|---|---|
| **只关上一阶段**：阶段时间被绕过阶段推进写入后，更早阶段的任务永远不关、一直逾期（隔离库复现） | 已修：关之前所有阶段的；测试按审查的复现步骤走一遍真实的阶段推进 |
| **并发会多建一批**：同时推进两次，6 次里 2 次建了两批 | 已修：同一项目加咨询锁再查重；测试 5 个项目各同时调 8 次。去掉锁这个变异会被发现 |
| **「建任务失败不让推进失败、留下日志」没被真正测到**：用不存在的人去推进，失败发生在阶段推进本身，断言走的是「或者推进没成功」那个分支 | 已修：用临时触发器只让这个项目的任务写入失败，核对推进成功、阶段时间写上、日志里有原因。把错误吞掉这个变异会被发现 |
| 项目分发的任务在生产里建不出来，规格却写成「进入项目分发时 SHALL 建」 | 规格改成「以项目分发被调用时」，设计与报告写明 |
| 每个成员都会收到到期提醒，风险里没写 | 写进 §3.1 |
| 已放弃的项目照样能建任务，放弃之后自动任务一直挂着 | 已修：不是进行中的项目不建；放弃接口撤掉。审查说「已放弃项目的任务会一直提醒」，我核了不对（提醒只看进行中的项目），但任务列表不看项目状态、会一直列着，所以仍然撤 |
| 截标只剩 1 天时「准备投标文件」在截标 4 天后才到期 | 已修：截标还没到时，任何任务都不晚于截标 |
| 创建时间错开 1 毫秒没有用处，设计里「任务列表按创建时间排」是错的 | 已去掉 |
| 提案说 Muse 读到的任务会变多：Muse 只读询价来源的任务 | 改成「Muse 读不到」 |
| 到期日的断言容差 ±12 小时，把时间整体挪 11 小时也测不出 | 改成按调用前后的时间窗核对 |
| 查重的两个变异（`> 1`、只看待办）没被发现 | 补了「已有一条待办 / 进行中的同前缀任务」两个用例 |
| 提案引用的 FLOW-H4a 报告还没合进 main | 改成「随 #446 合入」 |
| CI 没有数据库，隔离库测试在 CI 里跳过 | 照实写；隔离库测试在本地跑过 |

审查确认没有问题的：阶段推进只有一个入口（对话里的推进卡片，推进的总是登录用户，不会因为「系统用户」撞外键）；没有新增对外发送（这些任务没有来源类型，Muse 的提醒、询价、证据都不读；也不触发「任务指派」通知）；`sortOrder` 在任务表上从来没有过，所以生产里不可能有「[项目提交]」的自动任务；没有任何地方依赖那两条任务留在「项目提交」阶段；测试跑完不留数据。
