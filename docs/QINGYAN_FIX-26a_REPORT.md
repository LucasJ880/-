## 4. 没验证到的与已知限制

- **已发出去的 PDF 系统里查不到**：PDF 在浏览器里生成、不经服务器、不留痕，查不到哪些客户收到过带利润率的报价单；要不要通知客户、通知谁，由人定。
- 编辑器屏幕上的内部成本与利润率、Excel 导出的「内部成本」「利润率」「成本价（内部）」、旧报价单接口照旧对项目读者可见——FIX-26（叠在 CHAIN-2e 上做）处理。
- `isInternal` 为真的行照旧印进 PDF 并算进 Subtotal（`src/lib/quote/calculate.ts:28-37`）。旧编辑器界面不会写 `true`，但接口会原样保存、修订复制会保留：旧报价单 PATCH 把请求里的 `isInternal` 原样存下（`src/app/api/projects/[id]/quotes/[quoteId]/route.ts:88`，只要项目读权限 `:30`），报价引擎修订复制时保留（`src/lib/quote-engine/service.ts:331`）。正确修法要同时动计算、编辑器与接口，归 FIX-26；生产里有没有这种行没查（见 §6）。
- 合计区没有换页逻辑（既有）：行项很多、合计落到页底以下时会被截掉，本 change 没改，登记为后续。
- 旧报价单列表会列出报价引擎与新页面逐行报价建的报价（既有），归 FIX-26。
- 中文模板名在 PDF 上显示成乱码（helvetica 没有中文字形），与本 change 无关，没改。
- 没在真实浏览器里点导出看 PDF（测试用的是同一段生成代码在 Node 里的输出）。

## 5. 回退办法

`git revert` 本 change 的合并提交即可（只有 `export-pdf.ts` 三行与一个测试、两行注册）；回退后 PDF 重新印利润率，不涉及数据。

## 6. 合并后要人做的事

- 决定要不要通知已经收到过带利润率报价单的客户（见 §4 第 1 条），由 Lucas 定。
- 生产只读查询，看有没有会被印进 PDF 的内部行：`SELECT count(*) FROM "QuoteLineItem" WHERE "isInternal" = true;`（结果交给 FIX-26 定修法）。
- 业务同事知会一声：PDF 上不再有利润率，内部核算看编辑器或 Excel（FIX-26 之后只给有财务查看权的人）。

## 7. 与八条硬纪律的关系

1. 零 schema：不涉及。 2. 出站先审批：不涉及（PDF 由人自己发，本 change 让它少带一项内部数字）。 3. 队列：不涉及。 4. 脱敏：触碰——利润率是决定 A 明列不出的「毛利率」，旧报价单 PDF 对任何人都不再带它，内部成本、成本价、内部备注由测试看住。 5. 不爬登录页：不涉及。 6. 邮箱分离：不涉及。 7. 确定性优先：不涉及（不调模型）。 8. 测试注册：新测试已注册进两个脚本，注册校验通过。
