## 2. 与任务书的出入

proposal「与任务书的出入」七条，理由见 design：

1. 没有财务查看权的人在新页面上连「报价合计」也看不到（验收 5 写「只看到报价合计」；Evan 对 CHAIN-2e 的答复 ② 也支持给他们看客户视图）——取更保守的决定 C（D7）。
2. 有编辑权、没有财务查看权的人在新页面上不能做报价——Evan 对 CHAIN-2e 的答复 ①；BIDPAGE-1 记的「恢复编辑」义务改判为不恢复（D7）。
3. 「逐行」只配「只供货」；供货加安装、长期供货协议转去专业模式，它们的我方报价不能按价格表导出（D1）。
4. 提交、批准、选为我方报价仍在专业模式里做（只有一份已批准时系统自动选中），一次定价是 BIDPAGE-6。
5. 新页面开着时界面上没有地方能存价格表，逐行表的行实际从「招标分析带入 → 核对 → 导入 → 保存」来（D5）。
6. 逐行合计与系统记的我方报价之差上限是 Σ(数量 × 0.005)，不总是附录 C 说的「几分钱」（D4）。
7. 货品类别用 `PROCUREMENT`、预置说明照引擎真实算法、不复用 `line-entry.ts`（D3 / D5）。

不写 `QuoteLineItem`（附录 C 决定 H）；只有引擎一套算法、四个数取引擎（不确定处 1 / 4 的结论，D4）；`engineConfigSchema` 加可选字段的核对（不确定处 2，D1）。
