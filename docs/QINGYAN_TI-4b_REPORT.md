## 2. 面板做什么、不做什么

**做：**

- 顶部一张判定卡：「不可投标」或「可提交 Owner 决定」，逐条列阻断项。
- 一张阶段卡：缺的材料、未接通的来源、等批准的动作三张清单，加十三个阶段各自的决定。**没有任何「要不要查某某数据」的询问**——只读的阶段材料齐就直接做，只有对外发送、付费、提交和 Owner 决定才停。
- 价格表：从发标方的表里整块复制粘贴即可导入；单位和数量按原文保存，不换算。
- 文件领取方：粘贴一行一个的公司名；卡片固定写着「领取文件不等于投标」；没有开标记录时投标人数显示「未知」。
- 成本核算：逐行填采购类型、报价、报价方式、币种、证据类别、关税率、运费、本地配送；填汇率（来源、日期）、进口 GST 是否可抵扣、定价口径（按售价毛利率 / 成本加成）、预备金；点「计算」后显示核算表——行项分进口 / 本地两组带小计，合计块同时列毛利率与加成率并写明「不含 HST」，另有「阻断与提示」和「假设与出处」。
- 点「计算」后，顶部判定改用接口随核算表一并返回的判定（已计入成本）；保存工作区、清空输入、计算失败后回到未计入成本的判定。

**不做：**

- 组件里没有任何金额运算——所有数字来自 TI-2 的核算函数经 TI-4a 接口返回。
- 没有发送、提交、批准、删除之类的动作；只调用 `GET` / `PUT …/bid-workspace` 与 `POST …/bid-workspace/cost-sheet`。
- 成本输入**不上传保存**：只存在这台设备的浏览器里（按项目分键），提供导出 / 导入 / 清空。原因见 TI-4a 报告 §3（现有 JSON 位对所有项目读者敞开）。

## 6. 已知限制

1. **成本输入不跨设备、不跨人**：只在浏览器本地。这是存储方案未定之前的过渡做法，TI-4a 报告 §3 的三个候选仍待 Owner 决定（推荐：专用表，按财务查看权读）。
2. **拟投品牌型号、产品尺寸、证书、补遗还没有界面**：接口（TI-4a）已支持，面板目前只显示核对结果。所以「尺寸尚未核对」「认证未过」这类阻断项现在只能通过接口消除——下一个 change 补逐行录入。
3. **阻断项逐条列出**：18 行的标会列很长。规格要求逐条，暂未合并同类项。
4. **运费只能逐行填固定金额**：TI-2 支持的整柜 / 拼箱方案分摊在面板里没有入口，接口可用。
5. 面板没有组件级自动化测试（仓库没有组件测试设施）；靠源码断言 + 真实应用截图。
