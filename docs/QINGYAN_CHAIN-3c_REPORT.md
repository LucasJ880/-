## 1. 做了什么

| 场景 | 以前（CHAIN-3） | 现在 |
|---|---|---|
| 谁能裁决「疑似同一家」 | 能修改本项目的人 | 只有本组织的组织管理员（含组织所有者）；平台超级管理员按既有规则（与授标记录的确认 / 撤回同一口径）。其他人 403 `只有组织管理员能确认、否决或撤回「是不是同一家」（对本组织所有项目生效）。`，不写库 |
| 不是组织管理员的人看到待确认的一对 | 有「是同一家 / 不是同一家」按钮 | 没有按钮；写明 `只有组织管理员能确认或否决（对本组织所有项目生效）；在那之前，这些记录不进出口商汇总，也不能加入供应商库。请组织管理员打开本项目的进口线索处理。` |
| 裁决错了 | 不能撤回 | 组织管理员在「已裁决的（对本组织所有项目生效）」一节点「撤回」：在这一对下面展开，先写后果（按结论两句，写出两个名称），再**必须填撤回原因**（1–200 字，Lucas 2026-11-20 GATE），撤回写一条审计 `tender.import_lead_alias_revoked`（指向被撤回的那条审计行），这一对回到待确认、本组织所有项目随之改变，之后可以重新裁决 |
| 「已裁决的」一节 | 没有 | 本项目涉及的每一对：两个名称（本项目写法）、结论、裁决人（只取本组织现有成员的名字；否则写「本组织以外的人」，没填名字写「本组织成员（未填姓名）」，不带邮箱与用户 id）、日期、涉及几条记录（不含不采用的）；按日期从新到旧 |
| 裁决前的确认框 | 「……不能撤回」 | 「……组织管理员可以撤回」；否决那句加「之后各项目再导入这家进口商的记录会被跳过、不保存（撤回后也要重新导入）」 |
| 撤回的冲突 | — | 不是本项目涉及的一对 404（`本项目已没有涉及这一对的记录……页面已更新。`）；没有裁决或已被同事换掉 409（`同事已经撤回或改过这一对的裁决，页面已更新；请看清现在的结论再操作。`）；中标者读不出 422；与裁决同一对串行（同一把锁） |
| 写接口返回的视图 | 导入、加入供应商库的视图写死 `canEdit: true`，裁决权限没有 | 都带调用人真实的 `canDecideAliases` |
| 槽里与导入结果的说法 | 「等你确认」「要你确认」「另有 N 对要确认是不是同一家」 | 「等组织管理员确认」「要等组织管理员确认」「另有 N 对等组织管理员确认是不是同一家」；只读说明去掉「确认」 |

**撤回怎么认（design D2）**：撤回行的 `afterData.revokedAuditId` 指向被撤回的裁决审计行；一条裁决「有效」当且仅当没有撤回行指向它，每一对取最新的有效裁决。不靠时间先后（同一毫秒、时钟回拨都不会认错）。裁决与撤回都在 `import-lead-alias:{组织}:{中标者}` 锁内重读再写。

**撤回不做的**：不解除已建立的供应商关联、不删除供应商或线索；否决期间导入时被跳过的记录没有保存，撤回后不会自动回来（撤回否决后的提示写明要重新导入原表）。

**与拍板的出入**：没有出入。开 PR 时留给 GATE 的三个问题，Lucas 2026-11-20 答了两个（平台超级管理员也能裁决；撤回要填原因，已做），见 §6。

## 7. 已知限制

- 没有组织级的「全部别名裁决」管理页：只能在有相关记录的项目面板里看到与撤回。一对只在别的项目里有记录时，要去那个项目撤回。
- 撤回否决后，否决期间被跳过的记录要重新导入原表（已导入的不会重复）。
- 生产开关默认关；若生产已有 CHAIN-3 的裁决，照旧有效，组织管理员可以撤回。
