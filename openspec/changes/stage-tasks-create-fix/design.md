# Design：修好阶段推进之后的自动任务（FIX-5）

## Context

- `src/lib/tender/stage-tasks.ts` 的 `onStageAdvancedTasks` 做两件事：把上一阶段的自动任务标为完成；按模板为新阶段建任务。唯一的调用方是 `advanceProjectStage`（`src/lib/tender/stage-transition.ts`），调用后不等结果，出错只打一行日志。
- 建任务用 `db.task.createMany`，每条数据带 `sortOrder`。`Task` 表没有这一列（`prisma/schema.prisma`；迁移里也从来没有），Prisma 每次都抛「Unknown argument sortOrder」。所以第一件事一直正常，第二件事从来没成功过。没有任何测试覆盖这个文件。
- 模板：项目分发 2 条、项目解读 3 条、供应商询价 2 条、供应商报价 3 条、项目提交 2 条（「准备投标文件」「提交投标」）。进入「项目提交」= 写入提交时间、招投标状态变成已提交，也就是说模板在标交完之后才建「提交投标」。
- 走阶段推进的入口：项目对话里的「阶段推进建议」卡片（`/api/projects/{id}/advance-stage`，推进的人总是登录用户）；FLOW-H4a（#446，待合并）的「记录提交」也走它，并且指明不建任务。
- 有三处绕过阶段推进直接写阶段时间：分发时写项目分发（`src/lib/project-intake/service.ts`）、分析完成写项目解读（`src/lib/tender-auto-analysis/worker.ts`）、询价发出写供应商询价（`src/lib/tender-rfq/execute.ts`）。所以实际上：
  - 项目分发的任务在生产里建不出来——项目一分发就已经在这个阶段，对话卡片也不提议推进到这里；
  - 项目解读的任务只在人在分析完成之前就推进时才建；
  - 「上一阶段」常常不是建过任务的那个阶段（解读 → 询价发出直接写时间 → 人推进到供应商报价：上一阶段是供应商询价，项目解读的任务没人关）。
- 任务一旦真的建出来，会被这些地方读到：任务到期 / 逾期提醒（项目里所有成员都会收到，按每条任务去重）、每小时的「任务逾期」主动提醒、每天早上的摘要邮件（发到成员自己的邮箱）、AI 上下文里的逾期数。提醒与主动提醒只看进行中的项目；任务列表（`/api/tasks`）不看项目状态，已放弃项目里没完成的任务会一直列在那里。

## Goals / Non-Goals

**Goals**

- 阶段推进之后，新阶段的自动任务真的出现。
- 不留下永远挂着的自动任务：之前阶段的、已放弃项目的都要收掉。
- 不在标交完之后建「提交投标」；不出现截标之后才到期的任务。

**Non-Goals（具体到文件）**

- 不改 `src/lib/tender/stage-transition.ts` 的推进规则。
- 不改 `prisma/schema.prisma`（不为排序加列）。
- 不改 `src/lib/tender-auto-analysis/worker.ts`、`src/lib/tender-rfq/execute.ts`、`src/lib/project-intake/service.ts`（三处直接写阶段时间的地方）：它们写了时间之后，之前阶段的任务要等下一次人推进时才关。让它们也建 / 关任务，放到「阶段记录自动前进」那个 change。
- 不改提醒、主动提醒、摘要邮件（`src/lib/reminders/`、`src/lib/proactive/`）。
- 不给老项目补建任务。

## Decisions

### D1 去掉 `sortOrder`，不另外安排顺序

删掉那一列的赋值。任务表没有排序列；任务列表按更新时间排、任务页按到期日与优先级分组排，没有地方按创建时间排，所以不在创建时间上做文章。

- 否决：给任务表加 `sortOrder` 列。零 schema；为了一个排序不值得。
- 否决：创建时间依次加 1 毫秒（初稿的做法）。独立审查指出没有任何地方按创建时间排，加了也看不出来。

### D2 「准备投标文件」「提交投标」挪到供应商报价阶段，项目提交阶段不建任务

- 否决：原样保留。修好之后，每次把项目推进到「项目提交」（这时标已经交了）都会冒出一条三天后到期的「提交投标」。
- 否决：把这两条删掉。它们是交标之前确实要做的事；进入供应商报价阶段时建出来，进入项目提交时随「[供应商报价]」前缀一起被关掉，正好对上。
- 这是对模板的一处调整，写在 PR 最上面；不同意可以改回去，只是会带着上面那个毛病。

### D3 到期日：「提交投标」取截标时间，其余不晚于截标时间

挪到供应商报价阶段之后，离截标可能还有几周，也可能只剩一天。「提交投标」取截标时间；别的任务按天数算出来晚于截标时间的，也取截标时间。没有截标时间、或已经过了，一律按天数。

- 否决：只有「提交投标」看截标时间（初稿的做法）。截标只剩一天时，「准备投标文件」会在截标四天之后才到期。
- 否决：所有任务按截标时间倒推。那是在重新设计模板。

### D4 关掉之前所有阶段的，不只上一阶段

进入新阶段时，关的是新阶段之前所有有模板的阶段里还没完成的自动任务。这样三处直接写阶段时间、跳级推进都不会留下没人关的任务。

- 否决：只关上一阶段（原来的做法）。见 Context 的第三点；独立审查在隔离库里复现了。
- 否决：让三处直接写阶段时间的地方也去关任务。那是在改它们的行为，放到「阶段记录自动前进」。

### D5 同一项目加锁再查重

「新阶段是否已有没完成的同前缀任务」这个查重本身不改，但放进事务、先取一个按项目的咨询锁（仓库里已有同样的写法）。同一张卡片能在几条消息、几个页签里出现，两次推进会同时到达；没有锁时独立审查复现了多建一批。

- 否决：去掉查重。并发时会重复。
- 否决：靠任务表的唯一约束。要改 schema。

### D6 已放弃的项目不建；放弃项目时撤掉

阶段推进与写权限都不看项目是否已放弃。建任务前看项目状态，不是进行中就不建。放弃项目的接口在同一个事务里把还没完成的自动任务标为已取消（不是「完成」：事情没做）。

- 否决：放弃时不管。提醒不会再提，但任务列表会一直把它们列为没完成。
- 否决：在阶段推进里拦住已放弃的项目。那是改推进规则。

## 与八条硬纪律的关系

1. **零 schema**：遵守。只是不再写那个不存在的列。
2. **出站先审批**：遵守。没有新增出站。新增任务会出现在成员自己的每日摘要邮件里，那是发给自己邮箱的既有摘要，不是对外发送。
3. **禁止第三套队列**：遵守。仍在阶段推进之后执行，没有新的后台机制；加的是一个事务内的咨询锁。
4. **脱敏**：不涉及。任务标题与说明是固定文字。
5. **不爬登录页**：不涉及。
6. **邮箱分离**：不涉及。
7. **确定性优先**：遵守。固定模板，不调模型。
8. **测试注册**：新测试注册进 `scripts/test-all.sh` 与 `scripts/test-ci-unit.sh`。

## 验证方式

- `npx tsx src/lib/tender/__tests__/stage-tasks.test.ts`（新，纯逻辑，CI 里跑）：模板的内容；到期日的几种情形；要关哪些阶段的；任务数据里没有任务表不认识的列；接线。
- `npx tsx src/lib/tender/__tests__/stage-tasks-db.isolated.test.ts`（新，隔离库，CI 里没有数据库所以跳过）：逐个阶段真的建出来；到期日；关掉之前阶段的（含阶段时间被直接写入、跳级）；只动该动的；不重复（含同时调 8 次）；已放弃不建；放弃项目接口撤掉任务；从阶段推进的入口走一遍；任务写入被拒时阶段推进照样成功并留下日志。同一份测试在改动之前的代码上要失败。
- 变异核对；独立审查。
- 全量：`npm run test:ci`、`npm run typecheck`、`npm run lint:baseline`、`bash scripts/check-test-registry.sh`、`bash scripts/test-runtime-architecture.sh`、`openspec validate stage-tasks-create-fix --strict`。

## Risks / Trade-offs

- **合并之后行为立刻变**（没有开关）：之后每一次人推进阶段，都会给推进的人建 2–5 条任务。这是这些任务本来的设计，只是以前从没生效过。
- **项目里所有成员都会看到提醒**：任务到期提醒覆盖成员所在项目的所有任务（默认不是只看自己的），所以每条自动任务会给每个成员一条到期提醒（每条任务只一次），也会进每日摘要。
- **实际会建任务的阶段**：主要是供应商询价（分析完成之前就推进时还有项目解读）和供应商报价。项目分发的模板在生产里用不到。
- **三处直接写阶段时间之后**：之前阶段的任务要等下一次有人推进才关。比如分析完成之前推进到了项目解读，之后询价由 Muse 发出，「[项目解读]」的任务会挂到有人推进到供应商报价为止。
- **截标时间按 UTC 零点存的项目**（接口只给了日期）：「提交投标」在多伦多会显示为截标前一天晚上到期，偏早。
- **截标时间已过仍建「提交投标」**（按天数）：截标可能被延期，不猜。
- **与接入时按模板建的任务重复**：v1 接入接口在请求带了投标模板时，会另外建一组「[投标制作]」「[报价准备]」任务（BidToGo 实际带不带，我没有核实），它们不会被阶段推进关掉。不在这次范围内。
- **按标题前缀识别自动任务**：人把自动任务改了名，它就不会被自动关掉；人自己建一条以「[阶段名]」开头的任务，会被当成自动任务关掉，也会让那个阶段不再建一批。既有做法，不改。

## Migration Plan

无数据迁移。回滚 = 回滚代码（回到建不出任务的状态）；已经建出来的任务留着。
