# Proposal：修好阶段推进之后的自动任务

TASKFLOW：FIX-5（Phase F 续）
来源：做 FLOW-H4a 时发现的既有错误（见 `docs/QINGYAN_FLOW-H4a_REPORT.md` §3.2）；Lucas 2026-11-12「要修，要这些任务」。

## Why

招投标项目每推进一个阶段，本该为新阶段建两三条自动任务，但建任务时多写了一个任务表没有的列，每次都报错，调用方又把错吞掉——这些任务从来没有建出来过。另外模板把「准备投标文件」「提交投标」排在进入「项目提交」阶段之后，而进入那个阶段就意味着标已经交了。

## What Changes

- 去掉建任务时那个不存在的列，让阶段推进之后的自动任务真的建出来。
- 把「准备投标文件」「提交投标」两条从「项目提交」阶段挪到「供应商报价」阶段；进入「项目提交」阶段不再建任务。
- 让「提交投标」的到期日取项目的截标时间（没有截标时间、或截标时间已过时，仍按进入阶段后的天数算）。
- 让同一阶段的任务按模板里的先后顺序排列。
- 新增测试：每个阶段建出哪几条、关掉上一阶段的、不重复建、从阶段推进的入口走一遍。

## 受影响的 Muse 意图

无。不改 `src/lib/muse-bridge/` 下任何文件。阶段推进之后项目里会多出任务，Muse 的任务类意图读到的任务数会相应变多。

## Out of scope

- 给已经推进过阶段的老项目补建任务：不做。只对之后的阶段推进生效。
- 改任务模板的其它内容（各阶段的任务名、说明、优先级）：不改。
- 任务指派给谁：不改，仍然指派给推进阶段的那个人。
- 分析完成、询价发出时自动写入阶段时间的两处（它们不经阶段推进，所以不建任务）：不动。要不要让它们也建任务，在「阶段记录自动前进」那个 change 里定。
- schema 变更、模型调用、定时任务：没有。

## Capabilities

### New Capabilities

- `tender/stage-tasks`：阶段推进之后的自动任务——每个阶段建哪几条、到期日怎么定、怎么关掉上一阶段的、怎么不重复。

### Modified Capabilities

无。
