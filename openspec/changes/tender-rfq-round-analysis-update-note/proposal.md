# Proposal：询价发出之后招标分析更新过，在那一轮上标出来

TASKFLOW：FLOW-H3（Phase F 续；方案 §7 的 H3 按调查结果改写）
来源：交接文档 §0.5d 第 2 项与「H3 调查要点」。Lucas 2026-11-15「454已经合并，继续按照你推荐的做」。

## Why

补遗来了会产生一份新的完整分析、要求全部重新抽取，但已经发出的询价轮次不知道——轮次只存了当时渲染好的邮件正文，人看询价区时看不出这一轮是按旧的要求问的。

## What Changes

- 让询价区里由询价引擎发出的每一轮，在「起草这一轮之后又有一份可用的招标分析完成」时显示一句提示：这一轮在哪天起草、分析在哪天更新过、引用的要求可能已经变了、请对照最新的要求核对，需要时另发一轮。
- 让「问供应商要价」的入口接口多返回一项：按轮次的这句提示（只有满足条件的轮次才有）。
- 新增开关 `TENDER_RFQ_ANALYSIS_UPDATE_NOTE_ENABLED`（可配组织名单），默认关；关闭时接口不返回这一项，页面与现在相同。

## 受影响的 Muse 意图

无。不改 `src/lib/muse-bridge/` 下任何文件。

## Out of scope

- 说出具体哪条要求变了：不做（轮次不记它用了哪些要求，要求编号跨分析不稳定）。
- 自动重发、自动起草新一轮、通知供应商：不做（出站先审批）。
- 改要求的审核状态、补遗变更候选的显示与「接受」按钮：不做。
- 人工标记已发送、不经询价引擎的轮次：不做（它们的正文不是这里生成的）。
- schema 变更、模型调用：没有。

## Capabilities

### New Capabilities

- `tender/rfq-round-analysis-update`：已发出的询价轮次在招标分析更新之后的提示——什么时候出现、写什么、不做什么。

### Modified Capabilities

无。
