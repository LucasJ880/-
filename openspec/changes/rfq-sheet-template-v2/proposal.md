# Proposal：询价单模板第 2 版（RFQ-PDF-2）

TASKFLOW：RFQ-PDF-2（Phase F（续）— 询价单 PDF；任务书 `docs/QINGYAN_RFQ-PDF_TASKBRIEF.md` §5「T2」，Evan 2026-11-20 七项已拍板；2026-11-21 授权「全权负责……有问题按你推荐的做」）。核对基线：main `22a87fb7`（RFQ-PDF-1 #544 已合并、#553 已归档；#533 已归档，`tender/rfq-web-entry` 现为 14 条）。交接：`docs/QINGYAN_RFQ-PDF_HANDOFF.md`。

## Why

现有询价单问了单价、起订量、交期、有效期却没有填写处，请工厂「拍照或扫描」发回而回信解析读不了图片，「序号」与「要求编号」两套编号和回信解析对不上；同样的内容排得比需要的长。RFQ-PDF-1 的审查还带出四件要在同一次版式升级里一起改的事（回复截止会落在截标当天导致整份生成不了、内部字段词表太窄、两句说明没有出路、归档时主规格丢了两句）。

## What Changes

单个 change、单个 PR（8 条 task 装得下，不拆）；版式版本只升一次（1 → 2）。

- 改询价单首屏：标题「询价单」；抬头印公司名、联系人（组织投标档案报价抬头里的默认经办人，为空不印）、邮箱（询价设置里的展示发件人）；右侧印询价编号、询价日期、回复截止（加粗）；其下「一、询价内容」印范围说明（有时）、数量、贸易条款与目的地、交付要求（有时）。
- 改数量的写法：发起人填了数量阶梯就印阶梯；没填而有可用的数量事实时印这条事实的中文原文（带单位）；都没有时印「客户未明确数量，请按贵司常规阶梯（如 100 / 500 / 1000）分别报价。」。数量事实原文进招标身份检查与内部字段检查，命中即整份失败、位置写「数量」。
- 加报价表「二、报价」：每个数量档一行（数量、单价（含包装）、币种、贸易条款、备注），另有一行「其他数量档」，下面三格（最小起订量、生产交期（天）、报价有效期至）；六个栏目与回信解析的六个缺字段一一对应。
- 改规格确认表：只留要求编号一套编号（去掉序号列）；一格里中文在上、英文对照小字在下（相同只印一遍）；去掉「招标文件 p.N」；「强制 / 评分」改「必须 / 加分」；「是否满足」印三个勾选框；按类别分四组、组内按要求编号升序、组标题带条数；长编号在自己的格子里换行；规格栏不少于表宽 45%；表头每页重复、行不跨页。
- 标出没有中文译文的要求：判为非中文的，中文位置印「（暂无中文译文，以原文为准）」，下面照印原文；询价入口状态与菜单生成结果提示「有 N 条要求还没有中文译文」并指向「招标要求」里投标合规矩阵的「翻译成中文」。只提示，不阻止生成与送审。
- 改固定文字：规格表上方加一句说明原文里的 bidder / vendor / supplier 指我方；回复方式改为按编号逐条写明或把填好的表以 Excel / 可复制文字的 PDF 发回、不要只发照片或扫描件；附件不再印固定的 Q1–Q5，发起人填的附加问题仍印（标题「请另外回答」）。
- 改「请随报价提供」为勾选清单，既有派生项之后固定追加一组「首次合作或尚未提供过的，请一并提供」六项（营业执照、工厂照片、劳工与安全生产制度、原材料来源、材质证书、审核报告）。
- 同步邮件正文：规格行按同一分组顺序，每行以要求编号开头、不再有序号，【强制】【评分】改【必须】【加分】，去掉「（招标文件 p.N）」，材料清单与附件同序同条数，结尾统一为按编号回复；固定问题 Q1–Q5 在正文里保留。回信解析读取强制要求编号的那一处同时认旧写法（`【强制】{编号}`）与新写法（`{编号} 【必须】`）。
- 改回复截止的算法：回复截止不晚于截标前一天（按组织时区的日期）；算出来已不晚于今天时写「请尽快」。截标前 2 天与提前量为 0 时不再因「回复截止 = 截标日期」被招标身份防护拦下。
- 扩内部字段检查：招标原文那一档的词表加「我方报价 / 我方成本 / 内部成本 / 目标毛利 / our bid price / target margin / internal cost」等；要求编号与数量事实也过这一档。
- 改两句说明：菜单询价单「没有已确认的要求」与「含招标身份信息」两种情形都写明没有生成、没有保存、下一步去哪里。
- 签章栏做成带边框的一块、不与上一行拆页；页脚、内容安全策略、同输入同输出、PDF 检查不变；版式版本 1 → 2，旧版式起草的卡执行时照旧返回 `RFQ_ATTACHMENT_TEMPLATE_CHANGED`。
- 出样张：同一份联邦标样例，英文对照 8pt 与 7.5pt 各一份（页数 + 首页截图进报告）；上线默认 8pt，**字号由 Evan 打印后定，定之前不合并**。

## 受影响的 Muse 意图

`rfq`：起草出的邮件正文与卡上预览文字变了（分组、编号在前、【必须】【加分】、去掉页码、材料清单多一组）。不改 `src/lib/muse-bridge/**`。`status`、`compare`、`chase`、`price_scenario`、`next_step` 不变；催单与缺字段追问的模板与模板指纹不动。

## Out of scope

- 随询价附 Excel 回复表；按投标工作区价格表行项逐行询价。
- 回信解析的其余部分与比价（只改读取强制要求编号的那一个正则，使新旧正文都读得出）。
- 抬头印电话、微信、地址；邮件正文印联系人。
- 催单与追问邮件的模板；打开 `TENDER_RFQ_ATTACHMENT_ENABLED`；staging 收信核对。
- 内部文件；任何 schema 改动；任何新的模型调用。
- RFQ-PDF-1 报告 §6 里另开任务的几项（CI 不跑隔离库测试、地址与日期的变体写法绕过禁出清单、兜底 500 回显异常原文、内容安全策略与 meta refresh、并发版本号、既有说明里的「需求」叫法、菜单的「可能过期」提示）。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `tender/rfq-supplier-attachment`：「附件的内容」「附件的回复说明、签章栏、页脚与安全」「附件不输出什么」「邮件正文提到附件」四条改；新增首屏、报价表、规格确认表、没有中文译文的要求、勾选清单、询价邮件正文的写法六条。
- `tender/supplier-identity-guard`：「询价邮件用中性询价编号」（正文里数量行与要求标记的写法）、「供应商侧生成文件」（补回归档时丢的两句、标题改「询价单」）、「供应商侧文件命中时不生成」（说明文字；回复截止落在截标当天的场景改为照常生成）三条改；新增「回复截止早于截标日」一条。
- `tender/rfq-requirement-selection`：「询价单只收已确认的供应商侧要求」的场景措辞（不再带来源页码）、「行项类别与附件提示按归一后的类别」（材料清单多一组固定项）两条改；新增行项的分组与顺序、招标原文的内部字段检查两条。
- `tender/rfq-web-entry`：新增「缺中文译文的提醒」一条（入口状态多一句不阻断的提醒）。
- `tender/rfq-sheet-download`：「没有可收入的要求时不生成」（说明文字）、「菜单入口与说明」（提示引文与界面对齐、显示生成结果里的提醒）两条改；新增「生成结果里的缺译文提醒」一条。
