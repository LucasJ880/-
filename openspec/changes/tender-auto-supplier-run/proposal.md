# Proposal：批准分析后自动给出寻源建议——推荐型号与价格对照（CHAIN-2）

TASKFLOW：CHAIN-2（Phase F（续）— 情报串联；任务书 `docs/QINGYAN_CHAIN_TENDER_INTEL_CHAIN_TASKBRIEF.md` 2026-11-19 13:05 修订版）。核对基线：main `3c8f1626`（CHAIN-4a 已合并并归档之后）。判断点 1 取 A（批准分析 / 确认要求时）、判断点 4 取 B（情报推荐进自动起草的收件人，独立开关）（Lucas 2026-11-19「之后是 CHAIN-1、2、3……你全权负责」）。

## Why

供应商情报的候选、评分与主选 / 备选已经做好，可比授标、市场价格基准、比价矩阵的落地价也各在一处，但都要人一个个入口点进去：分析批准后系统不会自己建候选池，情报页签上也看不到「该问谁、大概什么价」。

## What Changes

- 新增开关 `TENDER_AUTO_SUPPLIER_RUN_ENABLED`（默认关，+ `TENDER_AUTO_SUPPLIER_RUN_ORG_ALLOWLIST`）：打开且该组织的供应商情报开着时，招标分析批准后（与自动起草询价同一处：批准分析、确认 / 驳回 / 批量确认要求这四个审核动作成功之后，起草之前）为项目自动建一个供应商候选池（供应商情报的搜索运行），每份分析只建一次。
- 自动建的候选池只用内部来源（记忆、历史成功、已存供应商），不调模型、不做外部检索；建池出错不影响审核动作本身，也不影响后面的自动起草；建成后写一条审计。
- 新增只读接口与情报页签上一张「寻源建议」卡：
  - 推荐型号：取本项目当前排名里主选 / 备选、强制闸通过的前 3 个，写供应商、型号、五项分数与强制要求有几条有证据；没有可推荐的照实写原因（还没评估过 / 评估过但都没过强制闸 / 供应商情报没开）。
  - 价格对照：可比授标（同采购方同口径、≥3 个样本的区间）、市场价格基准（外部情报已存的结果，原币）、我方落地价（比价矩阵里人选定的那家），三栏并排，缺哪栏写明缺；我方落地价只给有财务查看权的人。三栏不合并成一个数，不给「建议报价」。
- 新增开关 `TENDER_RFQ_INTEL_RECIPIENTS_ENABLED`（默认关，+ 组织白名单）：打开时，自动起草询价在操作者自己的名单之后并入情报推荐的供应商（本项目排名里主选 / 备选、强制闸通过、在用、有邮箱），去重后总数仍不超过 8 家；审批卡摘要写明哪几家来自情报推荐。

## 受影响的 Muse 意图

不改 `src/lib/muse-bridge/**`。`rfq` 意图起草的询价不受影响（并入情报推荐只发生在自动起草）。其余意图不涉及。

## Out of scope

- 自动评估候选（逐条判定要求、算强制闸与分数）：确定性规则只覆盖「点名认证」「数值阈值」两类要求，强制闸要求全部强制条款通过，自动评估几乎不可能给出结论；评估仍由人在供应链页做。
- 自动建池时的外部检索（要几十秒，放在审核请求里会拖慢「批准」）：外部检索仍由人在供应链页点。
- 任何「建议报价」或把三种价格合并成一个数（硬纪律第 4、7 条；目标报价由人定）。
- 换汇；市场价格基准的重新检索（不调 `researchMarketPricing`，只读已存结果）。
- Muse 发起的询价、网页手动发起的询价并入情报推荐（只在自动起草）。
- 进口线索（CHAIN-3）。

## Capabilities

### New Capabilities

- `tender/auto-supplier-run`：分析批准后自动建候选池；情报页签的寻源建议（推荐型号、价格对照）；开关。

### Modified Capabilities

- `tender/rfq-auto-draft`：「供应商只取操作者保存的常用供应商」加一个例外——情报推荐开关打开时，在操作者自己的名单之后并入情报推荐的供应商。
