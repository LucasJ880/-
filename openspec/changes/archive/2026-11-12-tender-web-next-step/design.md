# Design：项目页的「下一步」（FLOW-H1）

## Context

读代码确认的现状：

- 确定性的查表已经有了：`src/lib/muse-bridge/next-step.ts` 的 `decideNextStep`，十条规则，纯函数、零依赖。唯一调用方是 Muse 通道的 `next_step` 意图，而 Muse Connector 已冻结。
- 网页上另有两处「下一步」：`deriveTenderWorkbenchState`（三步：上传 → 确认要求 → 准备标书，第三步永远不结束）与 `deriveProjectCommandState`（「项目决策摘要」上的按钮，要求确认之后靠手工推进的阶段来猜）。它们都在浏览器里用项目基本信息算，看不到询价、报价、审批。
- Muse 那张表直接搬上网页有三处不合适：
  1. 没有「分析完、等你确认要求并批准」这一步——这种状态它会落到「还没问过供应商」。网页上的询价入口要求的是至少一条已确认的要求（不是批准分析），而批准之后就不能再确认，所以这一步不能跳过不提。
  2. 「三天内截标」是排第二的规则，命中后只说截标、不说该做什么——恰好是最需要指路的时候。它按天向上取整（25 小时说成「2 天后」）；而手工填的截标时间只有日期，存成当天中午，钟点是假的。
  3. 「没回该催」取的是提问人的等待天数，也不看回复截止；定时催单扫描取的是项目负责人的天数（或该轮授权里定格的天数），截止过了就不催（基线 G12）。而且网页上没有起草催单的按钮，催单只由定时检查起草。
- 页面已有的定位办法：`?tab=`、询价区块认 `#rfq-round-<id>` 与 `#rfq-rounds`、招标分析区有 `id="tender-analysis"`。没有通用的「切到某页签并滚到某处」。
- 这个人可见的待批审批：`loadPendingMineWhere` 给出条件，`PendingAction` 上有 `projectId` 列，可以直接按项目查。
- 投标工作区的判定（TI-3b）在读取接口里现算；其中成本类的阻断项永远在（成本输入只存浏览器），截标已过的阻断项不看提交时间。

## Goals / Non-Goals

**Goals**

- 打开项目页就知道现在卡在哪、点哪里。
- 只有一张表：Muse 与网页共用的状态不出现两套判断。
- 卡片说的话与页面上实际能做的事对得上（没有按钮的动作不假装有）。

**Non-Goals（具体到文件）**

- 不改 `src/lib/muse-bridge/**`（包括 `next-step.ts`、`router.ts`）。
- 不改 `src/lib/tender/workbench-state.ts`、`src/lib/tender/stage*.ts`、`src/components/project-onboarding/**`：三步卡与六段进度条照旧。
- 不改询价、催单、审批、投标工作区的任何判断与接口；`src/lib/tender-rfq/chase-service.ts` 只把一个已有的函数（`roundPolicyInEffect`）与一个常量（`OPEN_ITEM_WINDOW_DAYS`）导出，不改它们。
- 不改 `prisma/schema.prisma`。

## Decisions

### D1 调用 Muse 的查表函数，在外面包一层；不复制、不改它

网页的判断 = 几条网页才有的前置状态 → 调 `decideNextStep` → 对它的结果做网页一侧的细化与换位置。十条共用规则的顺序、条件、结论文字都来自它。

- 否决：照着它另写一张网页的表。两张表迟早不一致，G12 就是这么来的。
- 否决：把查表函数改成两边通用的核心、Muse 与网页各自渲染。要动冻结通道的文件，`next_step` 的输出有改变的风险，而收益只是代码好看一点。
- 否决：把文件挪到 `src/lib/tender/` 再从 muse-bridge 转出口。同样要动 muse-bridge；位置不好看可以以后再挪。

### D2 截标提醒单独算，不参与排序；只认截标时间，按天说

调两次查表：一次去掉截标时间，得到真正的下一步；一次去掉待批，只看它是不是命中「三天内截标」——要不要提醒由它决定，「三天」仍只有一处定义。怎么说由网页定：按天（「2 天后」「1 天多后」「不到 1 天后」「到了或刚过」），不说钟点。过了整整一天才给「截标日期已过」这个结论。

- 否决：沿用它的顺序（截标排第二）。命中后只剩一句「N 天后截标」，下一步被盖住。
- 否决：用它的原话。它向上取整，25 小时说成「2 天后」，比实际宽松。
- 否决：说到小时（本设计的第一版）。手工填的截标时间存成当天中午，「约 5 小时后截标」是假精确；一过中午就判「已错过截标」更是错的。
- 否决：没有截标时间时拿内部到期日顶替（Muse 的取法）。到期日不是截标，提交页上截标时间显示的也是「暂无」。

### D3 网页补充的状态放在查表之外，只在它没有答案、或答案在网页上不成立的地方补

前置（查表之前）：已中标、项目已结束、已提交、截标日期已过一天以上。细化（查表之后）：

- 查表说「没分析」→ 按有没有文件、是否在解析、是否失败分开；**如果询价或定价已经在走（老项目、或有人手工做了），跟着实际进度说**，分析的事放在顺带要办的事里。
- 分析等待审核且查表落到「还没询价」或「没有待办」→ 改为「等你确认要求并批准」；已有已确认的要求时顺带提示可以先去询价。有进行中的询价时不改，只顺带提一句分析还没批准。
- 分析已批准却没有一条已确认的要求 → 单列：入口用不了，批准后不能再确认，出路是重新分析或手工建一轮。
- 查表说「没回」而已经选定了一家 → 没回的不再挡路，按未响应再查一次表。
- 查表说「没有待办」→ 按询价轮次与投标价再分：已回复没录入、等回复、只有一家报价、一轮没拿到报价、已有投标价准备提交；认不出的状态不猜，带人去看这一轮。
- 已有投标价时，「还没询价」让位给「准备提交」。

- 否决：把这些加进 Muse 的表。见 D1。

### D4 等回复与没回复：按定时扫描的口径喂数，不承诺系统会做什么

等待天数：该轮带了跟进授权且仍生效 → 授权里定格的天数；否则项目负责人的偏好 → 组织设置 → 3 天。用的是扫描自己的函数。扫描不再看的供应商（轮次已结束、发出超过它 90 天的时间窗）按未响应交给查表；回复截止用扫描的 `deadlinePassed`，过了就按未响应再查一次表。

文字只说现在的状态（几家没回、超过几天、哪几家没有邮件线程）并指向这一轮。**不说「定时检查会起草催单」「系统不会再催」**：催不催取决于邮箱有没有连接、这一轮有没有授权、有没有被驳回过的催单卡——这些卡片不知道（第一版说了，审查逐条证明是错的）。

- 否决：沿用 Muse 的取法（提问人的天数、不看截止）。卡片会说「该催了」，而扫描不会催。
- 否决：把扫描的全部判断搬进来算「这一家会不会被催」。要读卡片状态、邮箱、授权，等于在卡片里重做一遍扫描；说错的代价比不说大。
- 代价：同一个状态，Muse 与网页在这一条上可能说的不一样。Muse 已冻结，记在已知限制里。

### D4a 当前这份分析、当前这一轮

分析：最近一次；最近一次失败或被取代、而之前有等待审核或已批准的一份 → 用之前那份（询价入口用的也是它）。轮次：没取消的里最新一轮有已发出供应商的；都没发出过 → 最新一轮。

- 否决：一律取最新一轮（Muse 的取法，本设计的第一版）。手工建一个空轮次、或一张发送卡过期后留下的草稿轮次，会把上一轮的报价盖成「还没问过供应商」。
- 否决：一律取最近一次分析。重新分析失败一次，卡片就说「上次分析失败」，而询价其实照常能用。

### D4b 指向询价入口时，读入口自己的状态

结论是「还没询价」或「一轮没拿到报价」时，再调一次页面上询价入口的读取函数（只读），拿它的「能不能用、为什么不能」。不能用时把它的原因写出来。

- 否决：只写「去问供应商要价」。入口可能因为没连邮箱、三天内不开新轮、没有可发的供应商而是灰的，卡片就成了指向一个点不了的按钮。
- 否决：每次都读入口状态。它要读供应商、邮箱、历史发送，比卡片其余部分加起来还重；只在要指向它的两种结论下读。

### D5 位置是数据，不是回调

接口返回 `{ kind: "tab", tab, anchor } | { kind: "files" } | { kind: "href", href }`。页面按它切页签、滚动、开抽屉或跳转。缺的四个页内位置（供应商询价、投标价、投标工作区、关键日期）各加一个 `id`，都放在「没有数据时也会渲染」的元素上——第一版把询价的位置指到轮次列表，还没有轮次时它不存在，点了哪儿也去不了。

- 否决：接口返回一个网址。文件抽屉不是网址；同页切换不该整页刷新。
- 否决：在卡片上直接放「批准」「发送」按钮。批准的按钮已经在该在的地方，旁边有正文可看；卡片上再放一个，等于绕过了看正文这一步。

### D6 待批：按项目直接查，不用收件箱的前 50 条

条件用 `loadPendingMineWhere`（与「待我确认」同一组），再加 `projectId`、待批、未过期。

- 否决：像 Muse 那样取收件箱再按项目过滤。收件箱只取 50 条，组织里卡多的时候这个项目的卡会被截掉。

### D7 卡片出现时，决策摘要跟着它说

页面拿到接口结果后，把「项目决策摘要」与右侧「项目上下文」的下一步都换成同一条结论。决策摘要不带按钮（按钮在它正上方的卡片上）；项目上下文在每个页签都看得到、而卡片只在工作台，所以它保留按钮，去往同一个页签或文件抽屉。接口不可用时两处照旧。

- 否决：两处都留着各自的按钮。一页上两个「下一步」，说的还不一样。
- 否决：删掉决策摘要的下一步逻辑。开关关闭时页面要与现在相同。

### D8 开关默认关

`TENDER_WEB_NEXT_STEP_ENABLED`（真值才开）+ `TENDER_WEB_NEXT_STEP_ORG_ALLOWLIST`（空 = 所有组织）。关闭时接口 404，页面不渲染卡片。

- 否决：不设开关直接上。它改的是每个招投标项目的首屏，先在自家组织看几天。

### D9 投标工作区的阻断项怎么用

工作区开启时现算一次判定（与它的读取接口用同一组函数）。成本类的两种阻断项不列（服务端看不到成本输入，列了就永远在）；截标时间类的两种也不列（卡片另有提示）；其余的在「准备提交」里列前两条并给出总数。**只在已经录了价格表时才谈阻断项**：工作区开了但没用过的组织，阻断项只有「价格表没有任何行项」，那是另一件事，放在顺带要办的事里（并提示可从招标分析带入，FIX-2）。

- 否决：把所有阻断项都列出来。「成本还没核算」会一直挂着，人很快就不看了。
- 否决：阻断项一出现就作为主结论。询价还没发的时候说「尺寸没核对」，顺序不对。

## 与八条硬纪律的关系

1. **零 schema**：遵守。只读既有的表与字段；不新增表、列、迁移。
2. **出站先审批**：遵守。卡片与接口不建审批、不批准、不发送；批准仍由人在既有按钮上完成。
3. **禁止第三套队列**：遵守。没有后台执行；接口在请求里现算。
4. **脱敏**：遵守。响应不含任何金额（毛利率、估值、我方报价、供应商报价、成本都不出）；来自数据的自由文字（审批标题、阻断项说明、入口的说明）带金额或百分比时整段替换，不做局部遮盖；Muse 通道没有新增内容。
5. **不爬登录页**：不涉及。
6. **邮箱分离**：不涉及。
7. **确定性优先**：遵守。判断全部是查表与固定规则；不新增模型调用；共用状态直接调用既有的查表函数。
8. **测试注册**：两个新测试注册进 `scripts/test-all.sh` 与 `scripts/test-ci-unit.sh`。

## 验证方式

- `npx tsx src/lib/tender-next-step/__tests__/web-next-step.test.ts`（新）：每一种状态的结论、原因、位置；与 Muse 查表逐状态对照；截标提醒与下一步并存、按天说；等回复与没回复的口径；询价入口三种状态；待批的各种卡；全部 25 条规则逐条核对权限说明；工作区三种情形；金额的整段替换；位置到网址；开关；决策摘要与右侧面板；接线与「点击只是导航」的源码断言（含页内位置在区块根元素上）。
- `npx tsx src/lib/tender-next-step/__tests__/web-next-step-db.isolated.test.ts`（新，本地隔离库，经真实路由处理函数）：一个标从没传文件走到已中标；待批的范围；负责人的天数与授权里定格的天数；催过两次的；用不上的催单；已取消的报价；工作区关 / 开未用 / 开已用；只有到期日；两份分析、最近一次失败；三轮询价（空轮次、取消、完成、超出时间窗）；已批准而没有已确认的要求；没有分析但已有报价；权限与开关；不写库；响应里没有金额。
- 变异核对：把实现逐处改坏（含独立审查做过而第一版测试没发现的 15 处），每一处都要有测试失败。
- `npx tsx src/lib/muse-bridge/__tests__/next-step.test.ts` 等既有测试不改断言通过；读到被改文件的既有测试全部重跑。
- 全量：`npm run test:ci`、`npm run typecheck`、`npm run lint:baseline`、`bash scripts/check-test-registry.sh`、`bash scripts/test-runtime-architecture.sh`。
- 真实应用截图（本地库、演示数据）存 `docs/acceptance/flow-h1/`，并记下点击按钮后页面的位置与发出的请求。
- 开 PR 前请一个不带结论的独立审查（重点：有没有说错状态的情形、位置对不对、多租户与审批可见范围、测试能不能发现问题）。
- `openspec validate tender-web-next-step --strict`。

## Risks / Trade-offs

- **卡片说错比不说糟。** 每种状态都有测试；看不准的状态（只有一家报价、认不出的状态）给的是选项或「去看一下」，不是指令；不承诺系统之后会做什么。
- **强制要求不满足、有供应商没回，排在比价与定价之前**（查表的顺序，网页沿用；只有「已选定之后没回的不挡路」做了调整）。
- **网页上没有「标记已提交」与「起草催单」的按钮**。卡片照实说明，指到最近的位置。
- **每次取数是十条左右的查询**，要指向询价入口时再加入口自己的一组。只在项目数据载入、审批变化、分析状态变化、回到工作台时取，不轮询。
- **开关关闭时，招投标项目的页面每次打开多一次返回 404 的请求**（页面不知道开关的状态）；非招投标项目不请求。
- **Muse 与网页在「没回该催」、取哪一轮、取哪个截标时间上可能不一致**（D2、D4、D4a）。Muse 已冻结。
- **审批中心按当前选中的组织列卡**：一个人属于多个组织时，从卡片进审批中心可能要先切组织。
- **老项目（没有 `workDomain = tender`、只靠旧字段认作招投标的）没有卡片**；接口与询价入口都只认 `workDomain`。
- **隔离库测试在 CI 里跳过**（仓库现状）：本地跑并在报告里写明。

## Migration Plan

无数据迁移。开关默认关；打开顺序建议先只对自家组织。回滚 = 关开关或回滚代码，没有遗留数据。
