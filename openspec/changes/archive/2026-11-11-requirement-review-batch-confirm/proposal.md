# Proposal：要求审核的批量确认——勾选后一次确认，批准分析前看得到还剩几条

TASKFLOW：RFQ-AUTO-4（Phase F 续，接 RFQ-AUTO-2）
来源：Lucas 2026-11-11「其他按照你推荐的做」（RFQ-AUTO-2 实施中发现的事项，交接文档 §0.5a 第 2 项）。

## Why

招标要求只能一条一条点「确认」，而询价单只带已确认的要求、批准分析之后界面不再允许确认——一个标几十条要求就要点几十次，没点完就批准的那些会被悄悄落在询价单外面。批量确认的接口早就有，界面没有用上。

## What Changes

- 在招标分析面板的要求列表上，为每条待确认的要求加勾选框，并加「全选待确认的」「取消全选」与「确认选中的 N 条」。只在分析等待审核时出现；默认一条都不选。
- 「确认选中的 N 条」调用既有的批量确认接口；选中超过 200 条时按 200 条一批依次提交。完成后显示实际确认了几条。
- 要求列表上方显示计数：已确认 / 待确认 / 已驳回各几条。
- 「批准分析」按钮旁，在还有待确认的要求时显示一句提示：还剩几条没确认、批准后不能再确认、它们不会进询价单。不增加点击。
- 批量确认接口每次成功写一条审计（谁、哪份分析、请求确认哪几条、实际确认了几条）。接口的响应结构不变。
- 面板提交时要求接口「只在分析仍是等待审核时确认」：分析已被批准或被取代时接口返回 409、一条都不确认。这是请求体里新增的一个可选字段，不带它的调用行为不变。
- 不加功能开关：这是既有接口上的界面操作，不涉及对外发送。

## 受影响的 Muse 意图

不触碰 muse-bridge。无受影响的意图。

## Out of scope

- 批量驳回：不做（没有对应接口，驳回是少数情况，留在逐条操作）。
- 「一键全部确认」而不经过勾选：不做。
- 批准分析之后继续确认要求：不做（不改审核流程的先后）。
- 按类别分组、筛选、搜索要求：不做。
- 在要求上标出「会不会进询价单」：不做。
- 单条确认 / 驳回补审计：不做（既有缺口，另提）。
- 改批量确认接口的上限或语义、改询价单取要求的规则：不做。
- 新的 LLM 调用、schema 变更、定时任务：不做。

## Capabilities

### New Capabilities

- `tender/requirement-review-batch-confirm`：招标要求审核时的批量确认——勾选、提交、计数、批准前的提示与审计。

### Modified Capabilities

无。

- `src/lib/tender-auto-analysis/`：新增一个纯函数文件（计数、全选、分批、提示文案）。

- `src/lib/tender-auto-analysis/review.ts`：批量确认多一个可选参数（只在等待审核时确认），不传时行为不变。
- 不改单条确认 / 驳回路由、批准路由、`src/lib/tender-rfq/**`、`prisma/schema.prisma`。
