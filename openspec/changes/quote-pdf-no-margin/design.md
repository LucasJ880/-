# Design：报价单 PDF 永远不印利润率（FIX-26a）

## Context

旧报价单编辑器（`src/components/quote/quote-editor.tsx`）的合计条有「导出 → 导出 PDF」（`src/components/quote/quote-summary-bar.tsx:87-95`），点了以后在浏览器里动态加载 `src/lib/quote/export-pdf.ts`（`quote-editor.tsx:24`），用编辑器手里的报价头、行项与合计（`calculateTotals`）生成 PDF 并下载（`quote-editor.tsx:322-325`）。编辑器挂在投标页签的报价区，没有开关，生产在用；能打开编辑器的是项目读者（`requireProjectReadAccess`，含只读成员与不是项目成员的组织管理员）。

PDF 今天印的全部内容（`export-pdf.ts`，2026-11-23 在 `325cbdc0` 上逐行核对）：

| 位置 | 内容 | 来源 | 是否内部数字 |
|---|---|---|---|
| `:50-52` | 「QUOTATION」 | 固定 | 否 |
| `:57` | 报价标题（空时「Untitled Quote」） | `header.title` | 否 |
| `:60` | 「Project: 项目名 \| Version n」 | 项目名、版本 | 否 |
| `:66-75` | Template、Currency、Trade Terms、Payment Terms、Delivery、Valid Until、MOQ、Origin | `header` 八项 | 否（Template 印的是中文模板名，helvetica 显示不出，不在本 change） |
| `:98-108` | 行项表：#、Category（英文类别）、Item、Spec、Unit、Qty、Unit Price、Total | 每行 `category`、`itemName`、`specification`、`unit`、`quantity`、`unitPrice`、`totalPrice` | 否 |
| `:133-136` | Subtotal、Total Amount | `totals.subtotal`、`totals.totalAmount` | 否（卖价） |
| **`:137-139`** | **「Profit Margin: x%」** | **`totals.profitMargin`** | **是** |
| `:150-157` | 「Generated by QingYan AI \| 日期」 | 固定 + 当天 | 否 |

传进来但不印的：`totals.internalCost`（内部成本）、`totals.lineCount`、每行 `costPrice`（成本价）、`remarks`（备注）、`isInternal`、`header.internalNotes`（内部备注）。所以要删的只有利润率这一行；内部成本、成本价、内部备注今天就不印，本 change 加测试看住，以后有人往 PDF 里加字段时测试会失败。

`isInternal`：仓库里没有任何代码把它写成 `true`（`grep -rn "isInternal: true" src` 无结果），旧编辑器没有这个开关，PDF 照旧不按它过滤。

## Goals / Non-Goals

**Goals**：任何人导出的旧报价单 PDF 都不带利润率、内部成本、成本价与内部备注；其余版式与改动前一致。

**Non-Goals**：
- `src/components/quote/**`（编辑器显示、导出菜单文字）、`src/lib/quote/export-excel.ts`、`src/lib/quote/calculate.ts`、`src/lib/quote/rules.ts`、`src/app/api/projects/[id]/quotes/**`、`src/lib/agent/skills/quote.ts`、`src/lib/agent-core/tools/**`：FIX-26。
- `src/app/api/projects/[id]/inquiries/**`、`src/lib/inquiry/**`、`src/components/inquiry/**`：FIX-26b。
- `src/lib/quote-engine/quotation-pdf.ts`、`quotation-html.ts`（报价引擎的客户报价单，另有禁出键清单）。
- `src/lib/muse-bridge/**`、`prisma/`、`vercel.json`、`package.json`。

## Decisions

### D1：对所有人删去利润率这一行，不出内部版 PDF

`export-pdf.ts` 删掉 `if (totals.profitMargin != null) { totalsLines.push(["Profit Margin", …]) }` 三行，合计只剩 Subtotal 与 Total Amount。函数签名不改（编辑器调用处不动）。

- 备选 A：只对没有财务查看权的人去掉。否决：PDF 是给客户的，负责人导出、发给客户时同样不该印；今天最常导出的正是负责人。判定财务查看权还要等 FIX-26 的接口改动，拖慢唯一从客户手里出去的口子。
- 备选 B：分客户版 / 内部版两种 PDF。否决：同一版式、同一文件名规则（`标题_v版本.pdf`），发错一次就是今天这个问题（GATE ④ 已定不出）；内部核算用 Excel。
- 备选 C：把 PDF 内容抽成纯函数再测（FIX-26 四件套原写法）。否决：只为删一行就重排整个文件，改动面大；直接生成真 PDF 再抽文字测得更实。

### D2：测试在 Node 里生成真的 PDF，抽页面文字断言

新测试 `src/lib/quote/__tests__/export-customer-pdf.test.ts`：在测试里把 jsPDF 的 `save` 换成「把 `output()` 存下来」（不写文件、不碰浏览器），调用真实的导出函数，从 PDF 内容流里取出所有文字操作（`(…) Tj`）拼成页面文字，再断言：
- 有：「QUOTATION」、报价标题、品名、「Subtotal:」「Total Amount:」、「CAD 100.00」；
- 没有：「Margin」、利润率数值、内部成本数值、成本价数值、内部备注原文（用少见的值：65.38、34.62、17.31、「SECRET-NOTE-7731」）；
- 利润率为 `null` 的报价单同样通过；
- 源码断言：`export-pdf.ts` 里没有 `profitMargin`、`internalCost`、`costPrice`、`internalNotes`。

只在抽出的页面文字里搜，不在整份 PDF 字节里搜，避免坐标数字碰巧相同。改动前的代码上跑，「没有 Margin / 65.38」两条失败、源码断言失败（tasks 1.1 记数字）。

- 备选 A：只断言传给 PDF 的数据（不生成 PDF）。否决：证明不了 PDF 上真的没有；协调会话要求「改前生成的 PDF 文字里能找到利润率数字」。
- 备选 B：用 Chromium 打开 PDF 读文字。否决：要浏览器，CI 子集里跑不了；jsPDF 默认不压缩内容流，文字操作可以直接读。

## 八条硬纪律

1. 零 schema：不涉及（不改 `prisma/`）。
2. 出站先审批：不涉及。PDF 在浏览器里生成、由人自己发；本 change 让它少带一项内部数字，不新增出站。
3. 禁止第三套队列：不涉及。
4. 脱敏：触碰。利润率是 Decision A 明列不出的三样之一（「毛利率」）；本 change 让旧报价单 PDF 对任何人都不带它，也看住内部成本、成本价、内部备注（规格「报价单 PDF 不印内部数字」的 SHALL NOT）。Muse 不涉及。
5. 不爬登录页：不涉及。
6. 邮箱分离：不涉及。
7. 确定性优先：不涉及（不调模型）。
8. 测试注册：触碰。新测试注册进 `scripts/test-all.sh` 与 `scripts/test-ci-unit.sh`；`bash scripts/check-test-registry.sh` 通过，基线文件不加行。

## 验证方式

- `npx tsx src/lib/quote/__tests__/export-customer-pdf.test.ts`：改动前失败（数字记进报告），改动后全过。
- 门禁：`npm test`（失败清单与 main 基线 10 项逐条相同）、`npm run test:ci`、`npm run typecheck`、`npm run lint:baseline`、`bash scripts/check-test-registry.sh`、`bash scripts/test-runtime-architecture.sh`、`npx openspec validate quote-pdf-no-margin --strict`、`git diff origin/main -- prisma/ vercel.json package.json` 为空。

## Risks / Trade-offs

- 负责人以后从 PDF 上看不到利润率：编辑器合计条与 Excel 里照样有（FIX-26 之后只给有财务查看权的人）。
- 已经发出去的 PDF 收不回来，系统也查不到发给过谁；要不要通知客户由人定（报告写明）。
- 编辑器屏幕上、Excel 里、接口里的利润率与内部成本照旧对项目读者可见，要等 FIX-26。
