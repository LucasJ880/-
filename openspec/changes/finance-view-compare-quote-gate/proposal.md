# Proposal：比价落地价与报价引擎内部数字统一只给有财务查看权的人（CHAIN-2e）

TASKFLOW：CHAIN-2e（Phase F（续）— 情报串联；CHAIN-2b 报告 §6 GATE 问题 ④，Lucas 2026-11-20「532 统一」，单独开 change）。核对基线：main `451bb0d3`（含 CHAIN-2b #532，2026-11-23 合并）；提示句由 CHAIN-2b 的同一常量拼成。GATE 三问 Evan 2026-11-22 已答（design「GATE」一节）；四条意外发现与 GATE ① 的前提开工前已逐条核实（design「开工前核实（2026-11-23）」）。

## Why

同一个项目工作台里，报价表助手（CHAIN-2b）与寻源建议卡（CHAIN-2）的我方成本只给有财务查看权的人，比价矩阵的落地价、询价追踪页的落地价、「报价与成本」卡（报价引擎）的估算成本与毛利率却分别对项目读者、对持项目角色成本读权限的人显示——而项目只读角色 `viewer` 也带这项权限，等于每个项目成员都能看。

## What Changes

- 新增一个「对本项目有没有财务查看权」的判定入口：与成本核算接口同一口径（平台超级管理员、持组织范围 `project.finance.manage` 或 `project.finance.read`、项目负责人）；授权查询出错时只剩平台超级管理员与项目负责人，并记一条只含原因的警告日志。
- 改报价引擎权限：看内部数字（估算成本、毛利、成本行、内部备注、分析、导入、客户报价编辑视图）改为只看财务查看权，不再认项目角色的成本读权限；编辑、批准同时要求财务查看权与项目角色的成本写 / 审权限（特权直通，与今天相同）。
- 改「报价与成本」卡、投标页报价区列表、「我方报价」卡：没有财务查看权时不显示估算成本与毛利率两列 / 两格，另显示一句谁能看、找谁。
- 改投标页报价区与「报价与成本」卡：不能新建报价时显示一句为什么、下一步（请人把你设为主负责人），不再出现「去创建报价」与新建说明。
- 改各处提示：项目负责人是导入用的系统账号时改为找组织管理员；授权查询出错时写「暂时无法确认」，不冒充没有权限；单个报价页保存被拒时不丢编辑。
- 改单个报价页：没有财务查看权时只显示那一句提示与客户视图；读取失败时写出接口给的原因；两种情况都不再停在「加载报价引擎…」。
- 改比价矩阵（`…/compare/matrix`）与 AI 报价分析（`…/compare/analysis`）：没有财务查看权时每行落地单价 / 总价为空、换算说明为空、带 `costHidden: true`，一句话结论换成不含金额与百分比的版本；排序、最低价 / 推荐标记、各项检查、换算不出的原因照常。
- 改 AI 报价分析：没有财务查看权时交给模型的输入不含落地价与带金额的结论，提示词写明金额不提供；仍是同一次模型调用，数字校验用同一份（不含落地价的）输入；分析面板显示一句谁能看落地价。
- 改询价追踪页：落地价按行所在项目判定，没有财务查看权的那格写「落地价只给有财务查看权的人看」；换算不出的原因与「最便宜」照常。

## Out of scope

- 供应商报价原价（询价明细 `…/inquiries/[inquiryId]` 与旧比价 `…/compare` GET 返回的单价 / 总价）：项目读者做询价本来就要看，照旧显示。
- 报价表助手的我方成本与比价成本建议（CHAIN-2b 已做）；寻源建议卡的我方落地价（CHAIN-2 已按财务查看权）。
- 成本核算 `bid-workspace/cost-sheet`（已按财务查看权）；项目财务接口（`allowCostPermission` 仍认项目角色的成本读权限，开关生产关着，另开任务）。
- legacy 报价接口、问青砚报价工具、Muse 比价的权限与审计（审查发现，另开任务；legacy 报价接口在打开 `TENDER_QUOTE_ENGINE_ENABLED` 之前必须修）。
- 给 `bids` 岗位开组织范围财务权（CHAIN-2b GATE ① 已答「不用改」）。
- 合并 CHAIN-2b 与本 change 各自的兜底判定（本 change 合并后另开整理，编号待定）。
- 谁能当、谁能换项目负责人（CHAIN-2c #539）；派发时不指定负责人的项目怎么补负责人（写进报告「合并后要人做的事」）。
- 落地价的算法、排序与推荐规则（`src/lib/tender-rfq/landed-cost.ts`、`compare.ts` 的 `buildCompareMatrix`）。

### Modified Capabilities
