# Proposal：逐行投标成本核算表

TASKFLOW：TI-2（Phase F，Tender Intelligence Phase B 第二项；来源 `docs/tender-intelligence-gap-analysis.md` §3.3、§6 的 N7 与 §17.2，Owner Gate A 已拍板）。依赖 TI-1（`tender-price-schedule-lines`）的行项契约。

## Why

现有定价只有一个手填的总成本；落地成本每个项目只有一个数量、一个关税率，不分进口与本地，没有进口环节税的现金流。18 行、进口与本地混合的货物标算不了逐行成本，核算过程也没有一张能给 Owner 看的表（Lucas 2026-11-11：核算表要「表现出来」）。

## What Changes

- 新增逐行直接成本计算：货值折加元、关税、分摊运费、本地配送、其它不可回收成本、不可抵扣税，各分项单独列出。
- 新增进口与本地采购的显式区分：本地行不计国际运费、关税与进口 GST，填了即拒绝。
- 新增关税依据分级：带 HS 编码、原产地、来源与日期的才算已核实；否则只能作为标明的敏感性假设。
- 新增进口 GST 的两种去向：可抵扣时只进现金流，不可抵扣时进成本，二者不重复。
- 新增运费方案互斥：一个情景只选整柜、拼柜、空运、本地之一，混合须显式声明并附说明。
- 新增整票费用按体积、重量、货值或数量分摊到行，分摊后与整票金额对到分。
- 新增两种定价口径（按售价毛利率、成本加成），同时输出毛利率与加成率。
- 新增预备金两种口径（按售价留、计入成本），同一笔不重复计。
- 新增两套成本模型的对账：逐项差额与价格差，不给「胜出者」。
- 新增缺参数不出数：缺报价、数量、汇率（含来源与日期）或关税率时，该行成本为空并列出原因。
- 新增核算表视图：分组行、小计、合计块、假设与出处块、阻断与提示；并提供与视图数字一致的 Markdown 渲染。
- 把 Skill 包自带的成本样例移植为金标测试。

本次只交付纯函数与测试：不接界面、不落库、不联网、不调模型。线上行为零变化。

## 受影响的 Muse 意图

无。不触碰 muse-bridge；`price_scenario` 的口径（决定 A）不变。

## Out of scope

- 不落库、不加接口、不加页面、不加开关。
- 不查询任何税则、汇率、运价来源；关税率、汇率、运费都是调用方给的输入。
- 不做 HS 归类；不判断某个税率是否正确，只区分「带核实依据」与「未核实」。
- 不改报价引擎、落地成本模块、定价助手的现有计算与界面。
- 不把核算结果写回报价引擎或项目财务（后续 change）。
- 不推断竞争对手的成本、价格或毛利。
- 不生成 PDF 或 xlsx；本次的渲染只有 Markdown。
