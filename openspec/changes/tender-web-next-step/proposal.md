# Proposal：项目页告诉人「现在卡在哪、下一步点哪里」

TASKFLOW：FLOW-H1（Phase F 续）
来源：交接文档 §0.5b 第 3 项；方案 `docs/QINGYAN_TENDER_FLOW_PLAN.md` §7 的 H1（断点 G1、G12）；Lucas 2026-11-11「Flow-H1 可以开始了，按照你推荐的做」。

## Why

青砚有一张确定性的「下一步」查表，但只接在已冻结的 Muse 通道上；网页上要求确认之后就不再指路，人只能自己记着该去哪个页签点什么。网页上另有两处各说各的「下一步」（工作台三步卡、项目决策摘要），都不看询价、报价、审批的实际状态。

## What Changes

- 新增接口 `GET /api/projects/{id}/next-step`：返回这个标现在的一条结论、原因、要去的位置、截标提醒、顺带要办的事。只读，项目读权限。
- 让网页的判断复用 Muse 的同一张查表（十条规则原样调用，不改它），在它前后补上网页才需要的状态：没传文件、文件解析中、分析完等确认与批准、等回复、只有一家报价、一轮没拿到报价、已有投标价准备提交、已提交、截标已过、项目已结束。
- 把截标提醒从「规则」改成「卡片上的一行」：临近截标时不再盖住真正的下一步。
- 让催单的口径与定时催单扫描一致：等待天数取项目负责人的设置（或该轮批准时定格的天数），回复截止过了就不再提示催。
- 让每一步指到页面上具体的位置：页签加锚点（招标分析、询价轮次、某一轮、投标价、投标工作区）、文件抽屉、审批中心。卡片只带人过去，不替人批准、不发任何东西。
- 在工作台页签顶部加「下一步」卡片；卡片出现时，「项目决策摘要」不再给出另一个下一步。
- 投标工作区已开启时，把它的阻断项与「价格表还没录」带进卡片。
- 新增开关 `TENDER_WEB_NEXT_STEP_ENABLED`（默认关，可按组织白名单）；关闭时接口 404、页面与现在相同。

## 受影响的 Muse 意图

无。不改 `src/lib/muse-bridge/` 下任何文件；`next_step` 意图的输入、输出、文案都不变（网页一侧调用它的查表函数，不修改它）。

## Out of scope

- 用这张表推导六段进度条、取代工作台三步卡（H1 的后半）：不做，另开 change。三步卡与六段进度条照旧。
- 在网页上新增「起草催单」「标记已提交」的按钮：不做。卡片只指向已有的位置；没有按钮的动作照实说明。
- 改 Muse `next_step` 的规则或口径（包括它与催单扫描不一致的那一处）：不做，Muse 通道已冻结。
- 让模型决定下一步、或给下一步写说明：不做（硬纪律第 7 条）。
- 自动批准、自动发送、自动推进阶段：不做。
- 在别的页签、项目列表、首页显示下一步：不做，本次只在工作台页签。
- schema 变更、定时任务：没有。

## Capabilities

### New Capabilities

- `tender/web-next-step`：网页上的「下一步」——接口、判断规则、指向的位置、项目页卡片。

### Modified Capabilities

无。Muse 的 `next_step`、询价入口、投标工作区、审批的行为都不变。
