# Spec Delta

## Purpose

`src/app/api/projects/[id]/` 下的每个接口都必须先过项目级权限检查；由一个不依赖数据库的守卫测试看住，以后在这个目录下新加接口漏了检查就失败。

## ADDED Requirements

### Requirement: 项目目录下的每个接口先过项目级权限检查
`src/app/api/projects/[id]/` 目录下每个路由文件导出的每个 HTTP 处理函数，SHALL 在做下面任何一件事之前先完成项目级权限检查，并在检查不通过时原样返回拒绝响应：
- 读写数据库；
- 访问文件存储；
- 解析文件；
- 调用模型；
- 建任务或执行任务步骤；
- 发通知；
- 入队；
- 写审计。

在检查之前，处理函数里等待完成的异步调用 SHALL 只有取路由参数与读请求体两种（有的接口要先看请求体再决定用哪一级检查）。项目级权限检查 SHALL 只认仓库里已有、并逐个核对过「先判项目可见性」的守卫，名单与出处写在守卫测试里。名单里的守卫 SHALL 按它被导入的来源模块认定；同名但来自别处的函数不算。

#### Scenario: 守卫测试
- **WHEN** 运行 `npx tsx src/lib/projects/__tests__/project-routes-guard.test.ts`
- **THEN** 目录下每个路由文件的每个处理函数都通过检查，退出码为 0

#### Scenario: 漏了检查的处理函数
- **WHEN** 目录下某个处理函数完全不做项目级权限检查，或在检查之前就读写数据库、调用模型、发通知
- **THEN** 守卫测试退出码非 0，并指出是哪个文件的哪个处理函数、缺的是什么

#### Scenario: 检查了却不看结果
- **WHEN** 目录下某个处理函数调用了守卫，但没有在守卫拒绝时原样返回
- **THEN** 守卫测试退出码非 0，并指出这个处理函数

#### Scenario: 冒名的守卫
- **WHEN** 某个路由文件从名单以外的模块导入一个与名单守卫同名的函数，并在处理函数里调用它
- **THEN** 守卫测试退出码非 0，并指出这个处理函数没有调用名单里的守卫

#### Scenario: 认不出的导出写法
- **WHEN** 某个路由文件用 `export { … }` 或 `export * from …` 导出处理函数
- **THEN** 守卫测试退出码非 0，并指出这个文件

### Requirement: 已下线接口的例外
固定返回 410、不读写任何数据的已下线接口 SHALL 列在守卫测试的例外名单里，并写明下线理由与出处。守卫测试 SHALL 校验例外名单里的每个接口仍然只返回 410、不导入数据库、不做任何异步调用；不再满足时测试 SHALL 失败。例外名单里的路由文件不存在时，测试 SHALL 失败，提示删掉这一条例外。

#### Scenario: 已下线的批量催单接口
- **WHEN** 守卫测试检查 `POST /api/projects/:id/inquiries/batch-followup`
- **THEN** 它按例外通过，因为它只返回 410、不读写任何数据

#### Scenario: 例外接口被改回干活
- **WHEN** 例外名单里的某个接口开始读写数据库，或不再固定返回 410
- **THEN** 守卫测试退出码非 0，并指出这个接口不能再按例外放过
