# Proposal：采购监控里的新标可以「跟这个标」

TASKFLOW：P2-3a（P2-3 的第一步；依赖 PROC-1 已上线的新标拉取，P2-1 的主体）
来源：H7 只读调查 `docs/QINGYAN_H7_INVESTIGATION.md` §4 切法 1；交接文档 §0.5f 第 4 项。Lucas 2026-11-15「如果有新的四件套或者是其他的方案，都按照你推荐的走……你全权负责这个项目」。

## Why

PROC-1 已经每周从 CanadaBuys 官方开放数据拉新标，按组织的关键词筛成候选，放在「采购监控」页；但候选上只能「关注 / 忽略」。看中一条新标后，要自己去新建项目、手抄招标编号、截标日、采购方、公告链接，再手动去关联——这就是 H7 要打通的「发现 → 跟进」的断点。

## What Changes

- 采购监控的候选里，**招标公告**（不是合同、不是信息公开请求）多一个「跟这个标」按钮。点了：
  - 新建一个招投标项目（负责人 = 点的人，和手工新建项目相同的默认成员与环境），预填项目名、招标编号、截标日、发布日期、采购方、来源平台与公告链接；
  - 把这条公告关联到新项目（关联类型「本项目」）；
  - 把候选改为「关注」。
- **同一组织的同一条公告只建一个项目**：再点（或两人同时点）都回到同一个项目；已经关联过「本项目」的，按钮变成「已跟进 · 打开项目」。
- 已过截标日的公告不能跟（写明已截标）；只读成员不能跟。
- 新项目里没有文件；上传招标文件后，照现有流程自动分析（不加新入口）。
- 新接口 `POST /api/procurement/instruments/{id}/follow`。

## 受影响的 Muse 意图

无。`follow_tender` 意图仍未开放（Muse 已永久冻结）；本次是 Web 上的同一件事。

## Out of scope

- 早报里的新标（P2-3b）、预评分（P2-2）、新标视图与每天排期（P2-1 收尾）、自动拉公告附件（P2-3c）：各自另立 change。
- 自动跟进（不点也建项）：不做，必须人点。
- 改 PROC-1 的拉取、去重、优先级、通知；改手工新建项目的流程。
- schema 变更、新开关、模型调用、对外动作：没有。

## Capabilities

### New Capabilities

- `procurement/tender-follow`：从采购监控的招标公告一键建招投标项目——谁能点、建出什么、怎么保证只建一次、什么情况不能跟。

### Modified Capabilities

无。
