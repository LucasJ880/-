# Proposal：组织页上的「询价与落地价设置」

TASKFLOW：W-2（RFQ 设置页；依赖 W-1，已完成）
来源：交接文档 §0.5d 做完之后的推荐顺序第 1 项。Lucas 2026-11-15「476、481可合并后，你自己去合并，继续按照你推荐的做」。

## Why

询价的发件设置和落地价换算参数（汇率及其日期与来源、运费 / 保险 / 清关估算、项目关税率）现在只能调 `PUT /api/organizations/[orgId]/tender-rfq-settings` 来改，没有页面；所以 FLOW-H2 的「来自比价矩阵」在大多数组织里只会显示「换算不出」。

## What Changes

- 组织详情页给组织管理员（org_admin，以及平台管理员）多一节「询价与落地价设置」：发件显示名 / 显示地址 / 授权邮箱；汇率表（币种 → CAD）连同日期与来源；运费、出口内陆运费的估算方式（按件 / 按票 / 按货值百分比）与数值；保险费率；清关杂费；按项目的关税率与交付截止。
- 保存 = 调现有的 PUT：**只发人改过的项**（没动的项不发，原来的值与环境变量回退都不受影响）；改成空 = 清空。汇率表填了数字就必须有日期与来源（页面先拦，接口也拦）。
- 读取用现有的 GET；页面不加新接口、不改接口、不改数据结构。
- 页面写明这些参数会用在哪里（比价矩阵的落地价、报价表助手的成本建议），以及「这是估算参数，落地价会标明出处」。

## 受影响的 Muse 意图

无。Muse 的比价与情景照旧读组织设置；本次只是多了一个能改这些设置的页面。

## Out of scope

- 回复提前量、轮次锁天数、催单天数：现有 PUT 不收这几项（读取有默认值），要改得先扩接口——另定。
- 改换算规则、默认值、谁能改（仍是 org_admin / 平台管理员）。
- 新开关：不加（只对组织管理员可见，写的正是接口本来就允许写的东西；理由见 design D5）。
- schema 变更、模型调用、对外动作：没有。

## Capabilities

### New Capabilities

- `tender/rfq-settings-page`：组织页上的询价与落地价设置——谁能看、显示什么、保存时发什么、怎么校验。

### Modified Capabilities

无。
